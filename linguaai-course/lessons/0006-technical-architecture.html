技术实现：LinguaAI 的架构浓缩

预计 12 分钟 · 只讲架构思路，不讲代码细节 · 目标：理解这个应用「为什么这么搭」，而不是「怎么写」

为什么要加这节课

前四课都在讲方法（怎么用 Agent 和 Skill）。这节课换个视角：用 LinguaAI 当案例，看看一个真实应用的架构长什么样，以及哪些架构决策让 Agent 协作更顺畅。

一句话记住

把逻辑写成纯函数、把外部依赖藏在适配器后面、把状态塞进 localStorage——这三件事让 Agent 能放心地改代码而不牵一发动全身。

整体结构：两块

learn_english_with_ai/
├── app/      React + Vite + TypeScript 前端（浏览器里跑）
└── worker/   Cloudflare Worker（TED 数据后端，绕过 CORS）

为什么分两块？因为浏览器直接抓 TED 的 RSS 会被 CORS 拦。Worker 做了三件事：抓 RSS、清洗 transcript、带日缓存返回。前端只管调 /api/channels/...。

前端三层：页面 · 组件 · 领域逻辑

层位置职责
页面pages/每个功能一页（文章列表、导入、单词预览、播客、发现…）
通用组件components/侧边栏、顶栏、配置面板等跨页复用
领域逻辑lib/纯函数 + 少量 hooks，不依赖 React

关键设计：领域逻辑尽量写成纯函数（articles.ts、processing/pipeline.ts、pdf/parse.ts、listening/quiz.ts…）。纯函数的好处是好测——给定输入必有输出，不用 mock 整个 React 树。这正是 tdd skill 能高效工作的前提。

核心数据流

导入文本 → saveArticle() → Article（processing 为空）
    ↓
AI 预处理（getTextAdapter().extractWords/Phrases/Sentences）
    ↓
attachProcessing() → Article.processing { words, phrases, sentences, audio }
    ↓
后续页面消费 processing：
  - 单词预览页 → words / phrases
  - 播客页     → sentences + audio（TTS）

Article 是整个应用的核心数据模型，所有页面都围绕它转。processing 字段是 AI 的产物，缺失时页面会引导用户去加工。

AI 适配器层：mock 先行的典范

lib/ai/index.ts 提供 getTextAdapter() / getVoiceAdapter() 两个工厂函数，调用方只依赖接口，不感知 mock/真实：

  • mock 模式：返回固定测试数据，无需网络、不花钱
  • real 模式：有 API Key → 真实适配器（OpenAI 兼容文字 + 火山 TTS 语音）；缺 Key → 回落 mock
为什么 mock 先行

第 1 课讲过：让 AI 功能在不花钱的情况下先跑通全链路、先写测试。接真实模型时只是替换一个开关，测试一行不改。这就是适配器模式的威力——把「变化的供应商」和「稳定的接口」隔开。

音频引擎：一个 hook 管所有播放

lib/audio/useSentencePlayer.ts 是个自定义 hook，封装了：加载音频、按句子定位播放、控制语速、循环模式。页面只需调用它暴露的状态和方法，不用直接碰 audio 元素。

这个抽象让「单句播放」「连读」「逐句精听」都复用同一套逻辑，测试也集中在一个地方。

PDF 解析：纯函数 + 严格校验

lib/pdf/parse.ts 用 pdf.js 解析文本，然后做三件事：去页眉页脚、三种版式检测、按标题切分文章。双语模式下严格对齐中英文句子数。

关键决策：只存英文正文，译文放 sentences[].translation——避免数据冗余，也让后续处理统一。

持久化：localStorage 就够了

整个应用没有后端数据库。文章、配置、学习进度全部存 localStorage。对一个桌面版个人学习应用来说，这是最简单也最可靠的选择——零运维、离线可用。

测试布局

测试文件与源文件同名（foo.ts → foo.test.ts），工具函数配单测，页面配 @testing-library/react 测试。全工程 370+ 测试，大部分跑在纯函数上——快、稳、不 flaky。

动手练习
  1. 打开 app/src/lib/，数一数有多少 .test.ts。问：为什么纯函数多的地方测试也多？
  2. 读 app/src/lib/ai/index.ts，理解工厂函数的路由逻辑——它怎么决定返回 mock 还是 real？
  3. 看 app/src/routes.ts 和 App.tsx，理解路由是怎么组织的（提示：常量唯一来源）。

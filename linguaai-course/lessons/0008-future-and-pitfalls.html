展望与挖坑：这套方法能改进的地方

预计 12 分钟 · 目标：诚实复盘本工程和这套 Agent 协作范式的不足，为后续课程留白

为什么要专门讲「不足」

前 6 课都在讲「怎么做」。最后一课讲「哪里还不够好」。一个方法论如果只展示成功案例，是危险的——你会以为它万能。诚实的复盘比完美的宣传更有价值。

一句话记住

最大的成本不是积分，是「每个会话重新对齐」的认知开销。这套范式的下一个突破口，是让 Agent 跨会话记住项目上下文，而不是每次从零开始。

坑一：会话割裂，Agent 每次都要重新了解项目

本工程用了 20+ 个会话完成。每个新会话开头，Agent 都要重新读仓库、重新理解「这个应用是干什么的」、重新加载项目记忆。这是最大的隐性成本——不是钱，是时间和注意力。

项目记忆（project_memory.md）部分缓解了这个问题，但它是事后沉淀的，且只记录「硬约束」和「教训」，不记录「当前进行到哪」。

可能的改进方向：
  • 会话交接文档：每个会话结束时写一份 .scratch/session-handoff.md（当前在做什么、下一步是什么、有哪些未决问题），下个会话开头 Agent 先读它
  • 项目状态文件：维护一份始终最新的 STATUS.md（已完成的工单、进行中的工单、下一步优先级），Agent 不用翻 issue 列表
  • 自动加载项目记忆：让 Agent 在每个会话开头自动注入项目记忆，而不是靠它「想起来去读」

坑二：token 消耗与会话长度的矛盾

本工程约 5000 积分。看起来不多，但有一个隐藏矛盾：

  • 所有任务放一个会话：上下文连贯，不用重新对齐，但会话越来越长，每轮都要重传整个历史，token 浪费严重
  • 每个任务开新会话：token 省了，但每个会话要重新对齐项目，认知开销大，且容易丢失上下文导致返工

本工程的实际做法是「按功能模块切会话」（导入一个会话、音频一个会话、PDF 一个会话……），这是一个折中，但不是最优解。

可能的改进方向：
  • 会话即工单：一个会话 = 一张工单的实现循环，做完就关。上下文靠工单本身（验收标准）和项目记忆传递
  • 摘要压缩：长会话到一定长度后，让 Agent 把历史摘要成几百字的「会话记忆」，后续只带摘要不带全量历史
  • 模块化上下文：Agent 按需加载相关文件（读工单时只加载相关模块），而不是每次把整个仓库塞进上下文

坑三：Skill 触发全靠手动

核心 skill 都带 disable-model-invocation: true——必须用户手动输入 /grill-me、/to-spec 等。这保证了「人主导」，但也意味着用户必须记住该在什么时候用哪个 skill。

对新手来说，「什么时候该 grill-me、什么时候该 to-spec」本身就是需要学习的。本课程其实就在教这个判断。

可能的改进方向：
  • 流水线编排器：一个 meta-skill，根据当前状态自动建议下一步该触发哪个 skill（检测到有 PRD 无工单 → 建议 to-tickets）
  • 状态机驱动：把流水线建模成状态机（想法 → 已讨论 → 有 PRD → 有工单 → 已实现），Agent 自动判断当前状态和下一步
  • 模板化触发：常用组合（grill-me + to-spec + to-tickets）打包成一个「需求产出」宏，一次触发跑完三步

坑四：项目记忆的边界模糊

项目记忆很有用，但什么该记、什么不该记没有明确规则。记少了不够用，记多了变成噪音（Agent 可能被过时的记忆误导）。

本工程的项目记忆里既有「硬约束」（必须用 async/await），也有「经验教训」（工厂引用要用 useMemo），还有「工程约定」（240px 侧边栏）。这些混在一起，优先级不清晰。

可能的改进方向：
  • 分级记忆：硬约束（不可违反）> 当前状态（会变）> 历史教训（参考），Agent 按优先级加载
  • 过期机制：每条记忆带时间戳和「适用范围」，超过一定时间或范围变化时标记为待复核
  • 记忆即 ADR：把重要决策写成架构决策记录（ADR），有编号、有上下文、有后果，比散记更可追溯

坑五：本工程本身的功能局限

作为应用，LinguaAI 还有不少没做的：

  • 纯 localStorage，无云端同步——换设备数据就没了
  • 无多用户——个人应用，没有账号体系
  • 复习算法简单——没有 SM-2 之类的间隔重复调度
  • 移动端未适配——定位桌面版

这些不是 bug，是有意的范围控制（回忆 PRD 的 Out of Scope）。但如果要继续做，这些是自然的下一步。

最后的总结

这套课的核心信息可以浓缩成三句话：

  1. Agent 是初级工程师，Skill 是 SOP，工单是合同——你的角色是管理者，不是打字员
  2. 先对齐要什么，再决定怎么造——grill-me → to-spec → to-tickets 不是流程，是防止返工的保险
  3. 把决策固化成记忆，把坑变成资产——项目记忆和 learning-records 让每次会话站在昨天的肩膀上

课程到此结束。但方法论的实践才刚开始——用你自己的项目跑一遍这条流水线，比读十遍教程都管用。

课后行动
  1. 挑一个你手头的小项目（或一个想法），完整跑一遍：setup → grill-me → to-spec → to-tickets → implement。不求完美，求跑通。
  2. 跑完后，写一份你自己的 project_memory.md，记录这次踩的坑和定下的约束。
  3. 回头看第 7 课列的五个坑，挑一个你最有共鸣的，想想在你的项目里怎么规避。

课程结束

7 课全部完成。你现在掌握了：用一条 Skill 流水线（setup → grill-me → to-spec → to-tickets → implement + tdd + code-review）把模糊想法变成已关闭工单的完整方法，以及它在 LinguaAI 上的真实实践。

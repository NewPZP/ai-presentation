Tool 插件开发速查表

骨架 + defineTool + 打包安装 · 打印友好

对应 DSH 0.1.2-rc.1。以官方「开发一个 Tool」与工具编写参考为准。

一句话

插件 = 导出 name + apply(ctx) 的模块。工具 = 在 apply 里 ctx.tools.register(defineTool({...}))。

最小插件骨架

import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'
export const inject = ['tools']        // 等依赖就绪再 apply

export function apply(ctx: Context) {
  // 注册能力
}

工具的三种形态

形态写法什么时候用
函数 export function apply(ctx) 绝大多数工具插件，够用
对象 export default { name, inject, apply } 需要更整齐的声明
Service 类 class X extends Service 要给别人提供服务时

defineTool 字段表

ctx.tools.register(defineTool({
  name: 'greet',
  description: 'Greet someone by name.',     // 模型据此决定调不调
  parameters: {
    name: { type: 'string', required: true, description: '要问候的名字' },
    limit: { type: 'number' },                  // 默认可选
  },
  output: {
    schema: { type: 'string' },                  // 规范值的类型
    render: (_args, value) => [{ type: 'text', text: value }],
  },
  async execute(args, exec) {
    return `Hello, ${args.name}!`
  },
}))
字段说明
name工具名，模型调用时用它
description面向模型的提示词——写不清，模型就不会用
parameters参数 schema；defineTool 据此校验并推导 args 类型
output.schema规范值类型，根可以是对象 / 数组 / 标量 / null
output.render把规范值转成模型可见内容
execute(args, exec)参数已校验；exec.signal 用于取消；exec.agent 可注入上下文

execute 的约定

规则要点
参数已校验 类型 / 必填 / 字面量 / 联合 / 嵌套都会校验；但非空、正数、跨字段等约束要自己查
定义只读 注册后不要改 schema 或换回调；要热替换就 dispose 该 effect 再注册新的
返回规范值 只返回 output.schema 声明的值，不要返回内容块；渲染交给 render
抛异常 = isError 基础设施故障抛异常；合法的「不理想结果」写进规范值（如非零退出码）
遵守 signal exec.signal 触发即取消进行中的工作
后台长任务 用 ctx.jobs.start({ kind, label, owner: exec.agent, run })；发布后用任务自有取消信号而非 exec.signal

配置（Config）

import Schema from '@deepseek-ai/schemastery'

export interface Config {
  greeting: string
  maxRetries: number
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
})

export function apply(ctx: Context, config: Config) { /* ... */ }
  • 无硬编码可调参数。 检验：能否在 cordis.yml 改掉它而不动代码？
  • 配置错误要响亮。 schema 在加载时校验，不合法就让插件加载失败，别静默兜底。
  • 改 config 会触发插件热替换（effect 自动清理，无旧注册残留）。

加载：开发用 patch overlay

# scratch-plugin/cordis.yml
- insert:
    - id: greet
      name: '/absolute/path/to/scratch-plugin/src/my-plugin.ts'
      config:
        greeting: '你好'
pnpm dsh web --patch ./scratch-plugin/cordis.yml

name 必须是绝对路径：patch 只贡献配置，不改变 loader 的模块解析基准目录。

打包：bundle vs profile

组合包 bundleprofile
回答这个包贡献什么？这套配置由哪些包组成？
manifestdsh.bundle.patchdsh.profile.bundles
位置npm 包$DSH_HOME/profiles/<name>
谁写你（分发的东西）用户（启动的东西）
 
// bundle 的 package.json
{
  "name": "dsh-hello-plugin",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
# bundle 的 cordis.patch.yml 按包名引用自己
- insert:
    - id: hello
      name: dsh-hello-plugin
dsh plugin --profile web add ./hello-plugin
dsh --profile web --dump-config    # 应看到 "# == dsh-hello-plugin" 层
dsh plugin --profile web remove dsh-hello-plugin

四层加载顺序（后者胜）

1. dsh.profile.bundles 列出的各 bundle patch（按列表顺序，base 在前）
2. profile 自己的 cordis.patch.yml
3. $DSH_HOME/cordis.patch.yml（机器本地共享偏好）
4. 每个 --patch <path> overlay（按 argv 顺序）

注意：patch 会整体替换目标行的 config，不是深度合并。覆盖某一行的 `id` 时，必须重述该行需要的每一个键。

从 git 安装的构建授权（安全相关）

  1. git 安装拉的是源码不是产物，没有环节跑 build → TypeScript 包没有 lib/，加载失败。
  2. 作者须提供自包含的 prepare 脚本（pnpm 在 git 安装后运行）。
  3. 用户须显式授权构建（pnpm ≥10 默认拦截），把 pnpm 打印的确切包键写进该 profile 的 pnpm-workspace.yaml：
allowBuilds:
  dsh-hello-plugin: true

把这项授权理解为允许该包的代码在安装时于你机器上执行，且不在任何沙箱之内。只对源码可信的包授权，并锁死 commit（github:you/hello-plugin#<sha>）。想省掉这一步就分发构建产物：发 npm，或 pnpm pack 出 tarball 再装。

验证链（三层证据）

证据怎么看
1 · 加载了终端出现 apply 里的 console.log
2 · 进表了工具 schema 流入系统提示词组装，模型「看得见」
3 · 真调用了Trajectory 里出现该工具的 tool/call + tool/result

排错速查

症状多半是
插件没加载cordis.yml 里 name 用了相对路径
ctx.tools 是 undefined忘了 export const inject = ['tools']
模型不调用你的工具description 写得含糊，或参数 schema 描述不清
加载即失败且报配置错schema 校验没过——这是预期行为，按报错改配置
git 安装报构建被拦未在 pnpm-workspace.yaml 授权 allowBuilds
覆盖某行后配置丢了patch 整体替换 config，需重述所有键

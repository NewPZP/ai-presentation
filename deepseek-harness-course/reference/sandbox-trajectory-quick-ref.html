沙箱与 Trajectory 速查表

安全边界 + 审批规则 + 轨迹读法 · 打印友好

数据对应 DSH 0.1.2-rc.1（2026-09）。Developer Preview 阶段，边界可能随版本变化。

一句话

沙箱只围住写，审批只拦「要更多权限」，Trajectory 记录一切。三者叠加才有可用的安全姿势。

沙箱三档

模式文件效果管不到用在
read-only 写入全部拒绝（默认兜底） 网络访问
进程可见性
凭证读取 		纯阅读、不信任的任务
workspace-write 只写工作区根目录 + 后端临时目录 日常使用
danger-full-access 隔离被绕过，无隔离承诺 只在完全清楚后果时

后端：Linux 用 bwrap / Landlock，macOS 用 Seatbelt，Windows 用 ACL 受限令牌。如果没有任何后端可用，DSH 会抛 SANDBOX_UNAVAILABLE，而不是裸跑。

审批规则

情况会弹审批吗
普通命令，在现有权限内不会——一开始就不需要批准
命令请求比当前会话更大的权限会，这才是审批触发点
调用不请求权限，而是修改会话设置本身不会 ← 2026-08 的 CVE 就从这里进来

安全清单（每次开工前过一遍）

  1. 用可丢弃环境：一次性目录或容器，不放真实项目、真实密钥。
  2. 凭证不进工作区：沙箱限制写，不限制读——~/.ssh、~/.aws 都在它的读取范围内。
  3. 默认 workspace-write + ask，不为图省事开 danger-full-access。
  4. 锁定版本，并确认版本号 ≥ 0.1.2-rc.1。
  5. 桌面版要单独查：它内置的 harness 版本由封装作者决定，不等于官方最新。
  6. 插件、MCP、技能、钩子先审查再执行——它们是代码。
  7. 记住官方声明：未经安全审计，沙箱与审批「不保证隔离」。

Trajectory 事件读法

turn/start                  # 回合开始
 ├─ step/start              # 一步 = 一次模型调用 + 其工具执行
 │   ├─ user/message        # 用户输入 / 注入的上下文
 │   ├─ assistant/message   # 模型输出（+ usage）
 │   ├─ tool/call           # 调了谁、参数是什么
 │   └─ tool/result         # 结果，或 error
 └─ turn/end                # reason: completed / blocked / error / max-tokens / aborted
你想知道去看
哪一步失败了带 error 的 tool/result
这一回合为什么结束turn/end 的 reason
这轮花了多少钱assistant/message 的 usage（0.1.2 也直接显示在回答末尾）
它到底看到了什么会话日志里的上下文注入记录

轨迹工具

工具用途入口
内置 Trajectory 视图 实时按来源检视会话记录（首选） Web UI 的 Chat / Trajectory tab
dsh-trajectory 导出为可分享的自包含 HTML（附 SHA-256） npx --yes github:ciceroyang/dsh-trajectory#v0.4.2 ./session.jsonl.zstd --out report.html
dsh-replay 时间旅行调试：replay / visualize / diff 进阶，精修 Agent 行为时用

存储形态：session.jsonl.zstd——zstd 压缩的 append-only JSONL，一行一个事件。resume / fork / search / replay 都基于同一条流。

版本安全（CVE-2026-82533）

版本状态
0.1.1-rc.2 及更早受影响（本机接口无认证，可被诱导关闭沙箱）
0.1.2-alpha.1已修复，但只在 GitHub，未上 npm
0.1.2-alpha.2首个带修复的 npm 版本
0.1.2-rc.1当前 npm 版，已含修复（一次性 token + 签名 cookie）

修复只解决了接口认证，没有改变沙箱：「读取和网络访问不受限制」在 0.1.2-rc.1 依然成立。

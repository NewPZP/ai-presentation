Cordis 插件机制术语表

写插件前必懂的核心概念 · 打印友好

一句话理解 Cordis

Cordis 是 DSH 的微内核。它不管 Agent 具体干什么，只负责插件的加载、卸载、依赖管理和热重载。DSH 的所有能力（模型、工具、循环、沙箱）都以 Cordis 插件的形式挂载。

核心概念

术语是什么类比
Context（ctx） 共享上下文对象，所有插件通过它注册能力、订阅事件、获取服务。 插件们共用的一块「公共白板」
Plugin 一个导出 apply(ctx) 函数的模块。DSH 加载时调用 apply，插件通过 ctx 注册能力。 一个自带安装逻辑的功能包
Service 在 ctx 上公开的一项能力，其他插件通过 inject 依赖它。比如 ctx.tools、ctx.sessions。 插件对外提供的 API
inject 插件声明它依赖哪些服务。依赖就绪后 apply 才执行；依赖消失时插件自动卸载。 「等这些零件到齐了再开工」
Effect 通过 ctx.effect(() => () => cleanup()) 注册的副作用。插件卸载时自动执行清理。 「装的时候建连接，卸的时候关连接」
Event 类型化事件系统。ctx.on('event', handler) 订阅，ctx.emit('event') 广播。 插件间的消息广播

插件的三种形态

形态写法什么时候用
函数形式 export function apply(ctx) { ... } 日常写工具插件，够用了
对象形式 export default { name, apply(ctx) { ... } } 需要配置校验、更复杂的声明
Service 类 class MyService extends Service { ... } 给其他插件提供公共服务时

关键扩展点 API

// 注册一个工具，模型可以调用它
ctx.tools.register({
  name: 'text_stats',
  description: '统计文本的字符数和单词数',
  parameters: { /* JSON Schema */ },
  execute: async (args) => { /* ... */ }
})

// 注册模型适配器
ctx.llm.registerAdapter(['deepseek'], adapter)

// 订阅会话事件
ctx.on('session/event', (session, event) => { /* ... */ })

// 获取服务（inject 声明后也可直接 ctx.sessions）
const sessions = ctx.get('sessions')

// 注册副作用，卸载时自动清理
ctx.effect(() => {
  const conn = openConnection()
  return () => conn.close()
})

会话事件流（Event Sourced）

DSH 的会话是一个仅追加（append-only）的事件日志。每个事件是 { type, seq, time, data }。理解这些事件类型，你就能写监听型插件（比如会话导出、费用统计）。

事件类型data说明
turn/start / turn/end{turn} / {turn, reason}回合边界。reason: completed/error/max-tokens/aborted/blocked
step/start / step/end{turn, step}一步 = 一次模型调用 + 它发起的工具执行
user/messageUserMessage用户输入、注入上下文、目标延续
assistant/message{message, usage?}模型输出 + token 消耗
tool/call / tool/result{name, arguments} / {message, error?}工具调用与结果
todo/write{todos}任务清单快照

配置三层叠加模型

profile（~/.dsh/profiles/<name>）
 ├─ bundle 层     ← dsh.profile.bundles 声明的组合包，按顺序叠加
 ├─ 用户层       ← profile 的 cordis.patch.yml
 └─ 覆盖层       ← $DSH_HOME/cordis.patch.yml + --patch overlays

每个 bundle 通过 package.json 里的 dsh.bundle.patch 声明配置补丁，DSH 启动时把补丁打进配置树，再由 Loader 逐个挂载插件。

插件生命周期

PENDING → LOADING → ACTIVE / FAILED → UNLOADING → DISPOSED

声明了 inject 的插件会等依赖服务全部就绪再执行 apply；依赖消失会自动卸载，恢复后重新加载。所有通过 ctx 注册的能力，在插件卸载时自动撤销——这就是 Cordis 的「零泄漏生命周期」。

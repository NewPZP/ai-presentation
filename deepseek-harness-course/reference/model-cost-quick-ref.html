模型与成本速查表

换模型 + 控成本 + 最佳实践 + 排错 · 打印友好

对应 DSH 0.1.2-rc.1（2026-09）。Developer Preview 阶段，口径与 API 可能变化。

一句话

模型适配器是插件，所以换供应商不用改 Harness；而每一次模型调用都要重发整个 surface，所以省钱的主战场是上下文。

换模型：三个层次

层次做法适合
换配置Settings → Models已支持的供应商，绝大多数情况
换 providercordis.yml 里的 provider / model按任务分派不同模型
写适配器继承 LlmAdapter，实现 stream()供应商还没有适配器

写一个 LLM 适配器（最小骨架）

class MyAdapter extends LlmAdapter {
  async *stream(options: GenerateOptions): AsyncIterable<StreamChunk> {
    // 1. options.messages → 供应商格式
    // 2. 调流式 API（记得透传 options.signal）
    // 3. 响应 → StreamChunk 分片
  }
}

export const name = 'my-llm-adapter'
export const inject = ['llm']

export function apply(ctx: Context, config: Config) {
  ctx.llm.registerAdapter(config.providers, new MyAdapter(config.apiKey))
}

StreamChunk 协议要点

规则说明
block-start / block-end必须成对；index 从 0 递增
text-delta逐片输出文本
tool-call-deltaargumentsDelta 是原始 JSON 文本的增量
usage必须在 finish 之前产出
finish必须是最后一个分片；tool-calls 表示请求执行工具
 
# cordis.yml 里接上 provider / model
- id: my-llm
  name: './src/my-llm-adapter.ts'
  config:
    apiKey: !!js process.env.MY_API_KEY     # 从环境变量读，别写死
    providers: [my-provider]

- id: agent-loop
  name: '@deepseek-ai/dsh-agent-loop'
  config:
    agents:
      - id: main
        provider: my-provider
        model: my-model-v1

照抄这两个已交付实现：packages/llm/llm-deepseek/（OpenAI 兼容格式）与 packages/llm/llm-pi-ai/（不同格式）。国产模型多走 OpenAI 兼容协议，改 endpoint + model id 即可。

错误处理：传输/协议故障抛带稳定 code 的 LlmError（不要依赖普通 Error 被自动转换）；每个 HTTP 请求合并 attributionHeaders()，并传递 options.signal；不支持的字段要抛错，不得静默丢弃。

成本：两个口径

数字含义
totalTokens当前请求 + 响应压力
surfaceTokens当前表层的路由定价总量 = 各节点价格之和

每一次模型调用都要重发整个 surface。上下文越长，不是贵一次，而是之后每一步都更贵——成本是累积的。

baseline.kind含义
usage最近一次成功的供应商调用请求结构相同 → 用真实 usage（准）
estimated无可用锚点 → 服务按启发式估算（仅供方向）

省钱四个动作

  1. 控制 surface，不是控制回复。 做完就开新会话；长任务用上下文压缩而非硬扛。
  2. 按任务选模型。 粗活用便宜快的，难活才上强模型，用 provider/model 分派。
  3. 利用峰谷定价。 闲时半价，可延迟的批量任务挪到闲时；dsh-peak-indicator 显示当前档期与切换倒计时。
  4. 装成本看板。 dsh-cost-meter 实时看会话花费与当日预算。

要定位「钱烧在哪一步」，用第 4 课的 Trajectory：每一轮 token 用量都在时间线上。

官方最佳实践（首次运行）

  1. 在空的可丢弃目录开始，不用家目录或客户 monorepo。
  2. 保持 workspace-write + ask，不从 danger-full-access 起步。
  3. pin 版本——不带版本号的 npx 跟随 latest。
  4. 审查插件 / MCP 服务器 / Skills / Hooks 再让它们执行。
  5. 凭证不进工作区——沙箱限制写，不限制读。

能力三层拆分（架构）

角色负责Bash 例子
Service Definition服务接口 + 请求/结果类型dsh-shell
Service Provider真正执行dsh-bash-local
Consumer暴露成模型可调用的工具dsh-tool-bash
  • 换提供方不动 Definition 和工具——只换 cordis.yml 一行。
  • 不要预防性拆分：只有角色需要独立演进时才分包；简单工具一个包够。
  • 显式优于隐式：默认值用显式 resolve(request)，不要藏在 run() 里的 ?? default。

排错速查

症状原因 / 解决
启动失败 / node-domexception Node 版本：需 ^22.19.0 或 >=24.0.0
端口 3080 EACCES Windows 上多为 Hyper-V / WSL2 / Docker 占用；别 chmod，停占用或换端口
页面加载但 API 403 不在信任 Host 列表——用 127.0.0.1，别用 localhost 或 IP
中文路径 workspace-invalid-path 0.1.2-rc.1 已修复该截断问题；旧版改用 ASCII 路径，且别选盘根
ERR_MODULE_NOT_FOUND 用 pnpm 装了发布版 CLI——改用 npx / npm；pnpm 只用于源码 checkout
沙箱内 HTTPS 报 SEC_E_NO_CREDENTIALS 沙箱破坏了 Windows Schannel；换不用 Schannel 的客户端，或经审批在沙箱外执行。网络本就在 SandboxMode 之外
Windows 沙箱 ACL 报错 把 HKCU 的 TMP/TEMP 指到你自己拥有的目录；工作区所有者要是你而不是 Administrators；别用 D:\ 这类盘根
杀毒软件告警 先确认是 @deepseek-ai/dsh，再比对官方 SHA

DeepSeek Harness 是什么？

从「手写 Agent」到「一切皆插件」 · 约 10 分钟

先回忆你已经会的

在 AI Agent 2.0 课程里，你手写过这样的 Agent 循环： 

# 你手写的 Agent 核心循环（伪代码）
while True:
    response = llm.chat(messages, tools)        # 调模型
    if response.tool_calls:
        result = execute_tool(response.tool_calls)  # 执行工具
        messages.append(result)                      # 结果回灌
    else:
        break                                   # 模型说停就停

这个循环就是 Agent 的心脏。你亲手把它写出来、跑通、加上记忆、封装成 Web 服务。这说明你已经理解了 Agent 的本质：LLM + 工具 + 循环。

问题是：当你想让这个 Agent「真的干活」时，光有这个循环够吗？

手写 Agent 会撞到的墙

假设你要让 Agent 帮你重构一个真实项目。你需要它：

  • 读文件、改文件、跑命令、搜索代码
  • 记住跨会话的项目上下文
  • 限制它不能删你家目录、不能读你的 SSH key
  • 出错时能回放、能定位是哪一步烧的钱
  • 换个模型供应商不用重写一半代码

这些事每一件都不复杂，但堆在一起就是几千行工程代码。Claude Code、Codex、OpenCode 这些产品，本质上都是在「手写循环」外面包了一层厚厚的壳——工具集、沙箱、记忆、可追溯、权限管理。

LLM 是灵魂，但灵魂不能直接在你的电脑上动手。它需要一具身体——这具身体就叫 Harness。

一句话记住 Harness

Agent = Model + Harness

「Harness」本意是马具——把马的力量接到犁和车上、又不让马脱缰的那套装置。模型是马，Harness 是马具：它负责把模型接到文件系统、终端、网页上，记录它做了什么、限制它能做什么，出错时决定是重试还是把问题扔回给人。

所以 Claude Code 是 Harness，Codex 是 Harness，OpenCode 也是 Harness。它们都是「模型 + 一层让模型能动手的壳」。

DeepSeek Harness 不一样在哪？

大多数 Harness（Claude Code、Codex）是精装房：内核一体化封装，体验打磨得很细，但封闭，社区没有插手的空间。你想加个自定义工具？只能等官方。

DeepSeek Harness（简称 DSH）走的是反方向——毛坯房，五个字的设计主张：

一切皆插件

在 DSH 里，没有「特权核心」。模型适配器是插件，工具注册表是插件，会话日志是插件，连 Agent 主循环本身都是插件。每一层都可以替换、扩展、热重载，而不用改 DSH 的源码。

能力在 DSH 里是什么你可以做什么
模型 模型适配器插件 换 DeepSeek / GLM / Qwen / OpenAI 兼容，改配置就行
工具 工具注册插件 自己写工具，或装社区插件
记忆 / 会话 会话日志插件 append-only 日志，可回放、分叉、搜索
安全 沙箱插件 read-only / workspace-write / danger-full-access 三档
循环 Agent loop 插件 甚至可以替换主循环本身

底层驱动这一切的是 Cordis——一个极小的 TypeScript 微内核。Cordis 管插件的安装、卸载、依赖、热重载，DSH 把所有能力都建成 Cordis 插件。

为什么这对你重要？

你想做自己的 AI Agent。如果用 Claude Code，你被锁在 Anthropic 的工具集和体验里；如果用 LangChain，你要在抽象层里反复猜「这个回调到底什么时候触发」。

DSH 的思路是：你只写你需要的那一块，剩下的用官方或社区插件拼。想换模型？换适配器。想加个图片 OCR 能力？装 modlens。想做跨会话记忆？装 OpenViking。拼装，而不是重造。

DSH 是 2026 年 8 月 13 日开源的，MIT 协议，两天冲了 9.5 万 Star。它是目前唯一一个把「连主循环都插件化」做到生产可用的开源 Agent 运行时。

本节课的小测验

检验一下理解

在 DeepSeek Harness 的设计中，以下哪一项不是可替换的插件？

  • 模型适配器
  • Agent 主循环
  • Cordis 微内核本身
  • 会话日志

「Agent = Model + Harness」这个公式里，Harness 负责的是？

  • 预测下一个 token
  • 让模型能调用工具、管理上下文、限制权限
  • 训练模型参数
  • 提供 GPU 算力

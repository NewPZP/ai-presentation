安装 DSH 与四种运行模式

跑起来、选对模式、管好权限 · 约 12 分钟

先检查你的 Node 版本

DSH 对 Node 版本有硬性要求：^22.19.0 或 >=24.0.0。低于这个版本会在启动时报错。 

# 检查版本
node -v

你当前的版本是 v22.18.0，差一点点。需要升级。如果你用 nvm： 

# 安装 22.19+ 或 24+
nvm install 22.19.0
nvm use 22.19.0

# 验证
node -v   # 应该显示 v22.19.0 或更高

为什么版本卡这么死？ DSH 大量使用了 Node 22.19 才稳定的原生特性（比如更新的 fetch、stream 处理）。用低版本跑会出现莫名其妙的 node-domexception 或模块加载失败。

一键启动 Web UI

最简单的启动方式——不需要全局安装，用 npx 临时拉取： 

# 体验最新稳定版（npm latest 通道，当前 0.1.1-rc.2）
npx @deepseek-ai/dsh web

# 体验预览版（npm next 通道，当前 0.1.2-rc.1，推荐）
npx @deepseek-ai/dsh@0.1.2-rc.1 web

第一次运行会下载依赖（约 40MB），稍等片刻。启动后终端会打印： 

# 输出类似这样
  ➜  Local:   http://127.0.0.1:3080/

浏览器打开 http://127.0.0.1:3080，你会看到 DSH 的 Web 界面。

第一次打开要做两件事

  1. 配 API Key：进 Settings → Models，填入你的 DeepSeek API Key（或其他 OpenAI 兼容供应商的 Key）。Key 存在本地，不会回显明文。
  2. 选工作区：选一个空的、可丢弃的目录作为 Agent 的工作目录。不要一上来就选你的家目录或真实项目。

安全提醒：API Key 等于钱包的钥匙。只在设置里填，永远不要贴进聊天框、不要出现在截图里。

四种运行模式

DSH 启动后可以选择运行模式（Mode）。每种模式预设了不同的工具集和权限，适配不同场景。不要一上来就用全功能模式，先理解每种适合干什么。

模式包含什么什么时候用
Standard 文件编辑、shell、文件搜索、网页搜索、技能、规划、目标、子代理、工作流 在真实仓库上做完整的编码任务。默认推荐
Code / PTC Standard 的全部工具 + Code Mode SDK（模型用 TypeScript 编排多步工具调用） 需要模型把多步操作组合成一段程序执行时
Minimal 只有两个工具：持久化 bash + str_replace_editor 模型基准测试、极简环境下的能力评估
Creator Standard 能力 + 运行时检查 + 内存中插件实验 + 预设编写引导 构建自定义 Agent 预设、测试 Cordis 插件

怎么选？

  • 日常编码、改项目 → Standard
  • 让模型自己写代码来串联多个工具 → PTC
  • 评测模型在裸环境下的能力 → Minimal
  • 你要开发插件或自定义预设 → Creator

沙箱权限：三档安全策略

除了运行模式，你还要设置沙箱模式（SandboxMode），控制 Agent 对文件系统的写权限。这是 DSH 最重要的安全防线。

沙箱模式文件效果建议
read-only 默认安全档。写入全部拒绝 第一次跑、不信任的任务、纯阅读场景
workspace-write 只能写工作区根目录和临时目录 日常使用推荐，Agent 能干活但碰不到工作区外的文件
danger-full-access 绕过隔离，等于不设沙箱 除非你完全清楚在做什么，否则永远别用

DSH 的沙箱在不同操作系统用不同后端：Linux 用 bwrap / Landlock，macOS 用 Seatbelt，Windows 用 ACL。如果后端不可用，DSH 会直接抛 SANDBOX_UNAVAILABLE 而不是裸跑——这是设计上的安全保证。

官方最佳实践：第一次运行的 5 条

来自 官方 Guides：

  1. 在空的、可丢弃的目录里开始，不要选家目录或客户的 monorepo。
  2. 保持 workspace-write + ask（每次操作询问），不要一上来就 danger-full-access。
  3. 锁定版本。不带版本号的 npx @deepseek-ai/dsh web 跟随 latest（0.1.1-rc.2），要体验新功能就 pin @0.1.2-rc.1。
  4. 插件、MCP 服务器、技能、钩子执行前先审查。
  5. 凭证不要放在工作区里——文件沙箱限制的是写入，不是读取。

常见启动问题速查

报错原因解决
node-domexception / 启动失败 Node 版本低于 22.19 升级 Node 到 22.19+ 或 24+
EACCES on port 3080 端口被占用（Docker/WSL/Hyper-V） 停掉占用进程，或换端口
ERR_MODULE_NOT_FOUND 用 pnpm 装了发布版包 用 npx 或 npm 装发布版；pnpm 只在源码构建时用
页面加载但 API 返回 403 访问的不是 127.0.0.1（不在信任 Host 列表） 用 http://127.0.0.1:3080，不要用 localhost 或 IP

动动手

本课实操任务：

  1. 升级 Node 到 22.19+
  2. 运行 npx @deepseek-ai/dsh@0.1.2-rc.1 web
  3. 打开 http://127.0.0.1:3080，填入 API Key
  4. 选一个空目录作为工作区，用 Standard 模式 + workspace-write 权限
  5. 让 Agent 做一件小事：在工作区里创建一个 hello.md，写入「Hello from DSH」

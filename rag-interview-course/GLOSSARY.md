# RAG 面试 Glossary

本工作区对 RAG 相关术语的权威定义。所有课程、参考文档、学习记录都遵循这里的用词。**术语只在用户真正理解后才收编**——这里是压缩后的已知知识，不是预习用的字典。还没掌握的词，看 `NOTES.md` 的课程进度。

## 基础（来自「AI Agent 2.0」第 11 课，已掌握）

**RAG（Retrieval-Augmented Generation，检索增强生成）**:
不把所有知识塞进上下文，而是先检索出与当前问题最相关的若干片段，只把这些片段喂给 LLM 再生成答案。
_Avoid_: 知识库问答（那是应用形态，不是方法）、向量搜索（只是其中一环）

**Chunking（切分）**:
把长文档拆成适合检索的片段。片段大小是召回率与上下文精度的第一个权衡点。
_Avoid_: 分段、切片（口语）

**Embedding（向量化）**:
把一段文本映射成定长浮点向量，使语义相近的文本向量距离也相近。
_Avoid_: 编码、特征（太宽泛）

**余弦相似度**:
两个向量的夹角余弦，用于衡量语义相近程度；RAG 里最常见的向量距离口径。
_Avoid_: 相似度（不指明口径时太含糊）

**Top-k**:
检索阶段取回的候选片段数量。k 越大召回越可能命中，但噪声和上下文成本也一起上升。
_Avoid_: 条数、数量（口语）

## 主链路结构（第 1 课收编）

**离线索引（Indexing）**:
文档进入系统时一次性完成的链路：解析 → 切分 → 向量化 → 写入索引。文档不变就不重跑。
_Avoid_: 预处理（含糊）、ETL（那是数据工程的词）

**在线服务（Serving / Retrieval-time）**:
每次用户提问都要跑的链路：查询改写 → 检索 → 融合 → 重排 → 上下文组装 → 生成。
_Avoid_: 推理（在 RAG 语境里特指模型前向，容易混）

**主链路**:
把 RAG 拆成离线索引与在线服务两条链路的结构化叙述。面试回答 RAG 流程时的默认骨架。
_Avoid_: 流程、pipeline（不体现两条链路的分野）

**上下文组装（Context Assembly）**:
把检索到的片段按某种顺序、带着元数据与引用标记拼进提示词的过程。片段顺序会显著影响模型用不用得上它。
_Avoid_: 拼接、prompt 拼接（太随意）

## 切分与索引（第 2 课收编）

**召回上限**:
切分与离线索引质量所决定的、在线检索再好也无法超越的天花板。核心推论：切丢了的内容，重排和生成都救不回来。
_Avoid_: 上限、瓶颈（不说清是谁的上限）

**chunk 判据**:
判断一个 chunk 是否合格的标准——脱离上下文后人还能看懂，模型也能看懂。
_Avoid_: 块质量（不可操作）

**固定长度切分**:
按固定 token 或字符数硬切并加 overlap。最省事、行为可预测，是本工作区认可的**默认起点**。
_Avoid_: 暴力切分（贬义且不准确）

**递归字符切分**:
按分隔符优先级（段落 → 行 → 空格）递归下刀，尽量落在自然边界。LangChain 的 `RecursiveCharacterTextSplitter` 即此策略。
_Avoid_: 智能切分（它并不理解语义）

**结构感知切分**:
按文档自身的结构（Markdown 标题、HTML 标签、PDF 章节）切分，并把标题路径写进块内。文档有结构时性价比最高。
_Avoid_: 按段落切（那只是其中一种退化情形）

**语义切分**:
把句子成组做 embedding，在相邻组语义距离的转折处下刀。实验性、成本高，仅在结构混乱时考虑。
_Avoid_: 智能分块（含糊）

**上下文增强切分（Contextual Retrieval）**:
用 LLM 为每个 chunk 生成 50–100 token 的定位说明，前置到块上之后再去做 embedding 和建 BM25 索引。属叠加增强，不替代基础切分。
_Avoid_: 上下文切分（歧义）、语境化（口语）

**overlap**:
相邻 chunk 之间共享的一段文本，用于防止答案正好横跨切分边界。代价是索引膨胀与重复召回挤占 top-k。
_Avoid_: 重叠度、冗余（后者是它的代价，不是它本身）

**chunk expansion**:
检索时用小块保证精度与低延迟，命中后把邻近块或父块一并带入上下文。与 parent-child、small-to-big 同义。
_Avoid_: 扩展检索（歧义）

**检索粒度 / 生成粒度**:
前者指 chunk 作为检索单位的粗细，后者指拼进上下文供模型使用的粗细。二者**不必相同**，这是 RAG 里一处关键解耦。
_Avoid_: 块大小（只描述前者）

**块元数据**:
随 chunk 一同存储的结构化字段：来源、标题路径、页码、时间、权限标签。用于检索过滤、组装定位与引用溯源。
_Avoid_: 附加信息（太含糊）

## 检索与融合（第 3 课收编）

**稠密检索（Dense Retrieval）**:
把查询和文档分别编码成向量，按向量相似度排序。擅长语义相近，对低频精确串不敏感。
_Avoid_: 向量搜索（口语）、语义检索（不体现与稀疏的对照）

**稀疏检索（Sparse Retrieval）**:
把文本表示为加权词项，按词项重合度打分。经典实现是 BM25，**不做任何模型推理**。擅长精确词项，对词形与词义是盲的。
_Avoid_: 关键词搜索（过于宽泛）、传统检索（含糊）

**BM25**:
在 TF-IDF 基础上引入词频饱和与文档长度归一化的词项加权评分函数，是检索领域长期未被超越的强基线。
_Avoid_: TF-IDF（后者是它的基础而非等价物）

**IDF 修饰**:
稀疏向量检索里让稀有词权重高于常见词的开关。不开启时，常见词可能与零件编号得到相同权重。
_Avoid_: 权重归一化（不是一回事）

**混合检索（Hybrid Retrieval）**:
同时跑稠密与稀疏两路检索并融合结果，用对称的盲区互相补足。
_Avoid_: 多路检索（那泛指包括多查询改写的更宽情形）

**融合（Fusion）**:
把多路检索的排序结果合并成单一排序。**只做重排，作用在候选并集上，不能创造候选。**
_Avoid_: 合并、聚合（不体现排序语义）

**RRF（Reciprocal Rank Fusion，倒数排名融合）**:
只用名次不用分数的融合方法，`Σ 1/(k + r(d))`，原文取 k = 60，用于缓和异常系统高排名的影响。本质是共识机制：奖励多路都认可，惩罚一枝独秀。
_Avoid_: 排名融合（中英混用不统一）

**按分数融合（Score-based Fusion）**:
先按查询把每路分数归一化到同一尺度再加权相加（如 DBSF、Weaviate 的 relativeScoreFusion）。保留「赢多少」的信息，也因此会放大分数分布本身的不可靠。
_Avoid_: 加权融合（不指明是否归一化）

**候选深度（Candidate Depth）**:
每路检索送入融合的候选条数上限。当正确答案不在并集里时，**唯一有效的手段是加深候选，而不是换融合算法**。
_Avoid_: 召回数量（会被误读成最终结果条数）

**查询改写（Query Rewriting）**:
在检索前用 LLM 改变查询表述，以缩小用户用词与语料用词之间的鸿沟。对精确型号类查询可能帮倒忙。
_Avoid_: 查询优化（太含糊）

**多路查询（Multi-query）**:
把原问题改写成多个不同角度的查询，各自检索后融合。代价是检索次数成倍增加。
_Avoid_: 查询扩展（那是给查询加同义词，机制不同）

**HyDE**:
先让 LLM 生成一段假想答案文档，再用它去检索。依据是答案的写法比问题更像文档，而编造的细节会被编码器的稠密瓶颈过滤。
_Avoid_: 假答案检索（口语）

## 重排与两段式（第 4 课收编）

**双塔（Bi-encoder）**:
查询与文档分别编码成向量、只在最后比一次距离的架构。编码时两者互不可见，但文档向量可离线预计算。
_Avoid_: 双编码器、向量检索（后者是实现形态，不体现架构）

**交叉编码器（Cross-encoder）**:
把查询与文档拼成一条序列联合编码、由分类头输出单一相关性分数的架构。每层注意力都做逐词交叉。
_Avoid_: 精排模型（口语）、重排模型（那是它在管线中的角色，不是架构）

**后期交互（Late Interaction / ColBERT）**:
文档保留每 token 的向量，检索时用 MaxSim 做 token 级匹配再汇总。文档侧可在索引期算好，在线只有查询过模型。
_Avoid_: 延迟交互（译名不统一，本工作区固定用「后期交互」）

**两段式检索（Two-stage Retrieval）**:
第一级用可预算的廉价表示做粗召回，第二级用昂贵的精细模型在少量候选上精排。它是成本结构的必然结果，不是设计偏好。
_Avoid_: 多阶段检索（那泛指任意层数，含量化重打分等）

**重排（Rerank）**:
在不改变候选集合的前提下，用更强的模型重新排列已有候选的顺序。**它不能创造候选，也不能救回没被召回的文档。**
_Avoid_: 二次检索（会被误解为又去召回了一批）

**排序差距（Ranking Gap）**:
把候选集「当作已被完美排序」所得的分数与管线当前得分之差。它等于任何更好的排序阶段所能捞回的上限，是判断该不该上重排的判据。
_Avoid_: 提升空间（含糊）、召回缺口（那是候选缺失，完全不同的东西）

**最优可能分数（Best-possible Score）**:
仅在这批已召回候选内部做理想排序所能达到的分数。它不是理论极限，而是**这批候选的天花板**。
_Avoid_: 上界、理论上限（易被误读为任务的理论极限）

**nDCG@k**:
归一化的折损累计增益，只评前 k 名且越靠前权重越高；归一化分母取「相关度降序前 k 个」的理想排序。对 k 敏感且呈台阶状。
_Avoid_: 排序准确率（不是一回事）

**MMR（最大边际相关性）**:
在相关性之外惩罚候选与已选结果的相似度，用于去重与增加多样性。它用相关性换多样性。
_Avoid_: 多样性排序（不体现取舍）

第 1 课 · RAG 面试冲刺

RAG 面试作战地图

一条主链路、五处失分点、一个 90 秒口播结构 · 约 15 分钟

你现在的 RAG，过不了面试

你在 AI Agent 2.0 第 11 课里已经跑通过一条 RAG： 切分文档 → 调 embedding → 用余弦相似度找最相近的几段 → 拼进提示词。代码能跑，答案也对。

但面试不考「你会不会跑」，考的是你为什么这么做、换个做法会怎样、你怎么知道现在这个更好。 你那条 demo 是一条直线，面试官会从直线的每个接缝处切开问你——而你现在一处都答不上来。

「介绍一下 RAG 的流程。」

这题 90% 的候选人会答成：「把文档切块，向量化存到向量库；用户提问时把问题向量化，检索相似的块，拼到提示词里让模型回答。」

这段回答的问题是：它把 RAG 说成了一个方法，而 RAG 其实是一条流水线。 面试官听到「方法」就会开始逐个零件地问你选型理由；听到「流水线」，他会顺着你的结构问下去，而结构是你定的。 这节课要给你的，就是那个结构。

一、先把主链路摆出来

RAG 的第一性结构不是「切分→向量化→检索→生成」，而是两条链路的解耦： 文档进入系统时做的事，和用户提问时做的事，是分开的。

离线索引 · 文档变了才跑一次
解析PDF / HTML / 表格
切分大小与重叠
向量化embedding 模型
入库索引 + 元数据
在线服务 · 每次提问都要跑
查询改写多路 / 消歧
检索向量 + BM25
融合RRF 排序
重排cross-encoder
组装生成引用与拒答

这个划分本身就是得分点。它直接回答了三个面试官一定会问的问题：

  • 文档更新了要重跑什么？只重跑离线那条链路上受影响的部分，在线服务不动。
  • 延迟预算花在哪？在线链路是延迟敏感路径，离线链路可以慢、可以批处理、可以用大模型做增强。
  • 优化往哪下手？离线决定召回的上限（切分切坏了，后面再精排也救不回来），在线决定这份上限能兑现多少。

二、90 秒口播：五个节拍

被要求「介绍一下 RAG」时，别背课文。按下面五个节拍说，每一拍都停一下看面试官反应——他会顺着最感兴趣的那一拍追问， 而那一拍就是你接下来十分钟的战场。

90 秒结构（照着说，不要背）
  1. 定义 + 动机（10 秒）：RAG 不是让模型变聪明，是让模型看到它训练时没见过的知识，而且不用重训—— 文档一变，重新索引就行。
  2. 拆成两条链路（20 秒）：离线索引做解析、切分、向量化、入库；在线服务做查询改写、检索、融合、重排、组装生成。
  3. 指出关键耦合（20 秒）：离线决定召回上限，在线决定兑现多少。所以我会先量召回，再谈生成。
  4. 主动交代取舍（20 秒）：说一个你真实做过的选择，例如「切分我选了按标题结构切、块内保留标题路径，代价是块大小不均」。 这一拍是分水岭——主动讲取舍的人，会被当成做过的人。
  5. 落到评测（20 秒）：检索用 Recall@k 和 MRR，生成用忠实度与拒答率；不量化就没法证明改动有效。

三、五处失分点

下面五处，是你那条直线最容易被切开的地方。每一处都配了面试官的真实问法和你该有的姿势。 后续课程会逐个把它们补成完整答案。

失分点 1：把 RAG 讲成一条直线

「你的文档每天更新，是不是每次都要把所有文档重新向量化一遍？」

如果你脑子里只有一条线，你会答「是的」——然后开始解释怎么让它跑得快一点，越描越黑。 正确姿势是先说两条链路是解耦的：只有被改动的那批文档需要重跑解析、切分、向量化，索引是增量的； 在线服务一行代码都不用动。再补一句：如果换了 embedding 模型，那才必须全量重跑，因为新旧向量不在同一个空间里，不能混着比。

失分点 2：把「检索」等同于「向量检索」

「用户查的是产品型号 XR-2400B，你的向量检索为什么搜不出来？」

这是朴素 RAG 最经典的翻车现场。向量检索擅长的是语义相近，不擅长精确匹配： 冷门型号、错误码、人名、法律条款号这类低频 token，在 embedding 空间里几乎没有区分度，反而会被语义上「像」的邻近词吸走。 正确姿势是混合检索：BM25 一路保精确匹配，向量一路保语义泛化，两路结果用 RRF 之类的排名融合算法合并。 这一处能答出「稀疏检索和稠密检索是互补而非替代」，应用岗这一轮就稳了一半。 更有说服力的是直接甩数据：Anthropic 的实测中， 单用向量检索时 top-20 的检索失败率是 5.7%，加上 BM25 后降到 2.9%——这是别人量出来的，不是你的感觉。

失分点 3：根本没有重排这一环

「向量检索 top-20 里明明有正确答案，为什么模型还是答错了？」

召回了，不等于用上了。向量检索用的是双塔结构——问题和文档分别编码， 两者在编码时没有见过对方，只能比「整体像不像」。而重排用的是 cross-encoder，把问题和候选文档拼在一起送进模型， 能做逐词的交叉注意，判断「这段到底能不能回答这个问题」。 代价是它慢得多，不能对全库跑，所以标准做法是两段式：向量检索粗召回几十条，cross-encoder 精排到 3–5 条再喂给 LLM。 Anthropic 那组实验里，在混合检索之上再加一层 rerank，失败率从 2.9% 继续压到 1.9%——收益是叠加的，不是二选一。

失分点 4：无法回答「你怎么知道改好了」

「你说你优化了检索，效果提升了——怎么证明？」

这是最致命的一处，因为它决定面试官信不信你前面说的所有话。答「感觉回答更准了」等于承认没有工程能力。 正确姿势是分两层量化：检索层看 Recall@k（该被找到的有没有进候选）和 MRR / nDCG（排得够不够靠前）； 生成层看忠实度（答案是否只依据检索到的上下文）和拒答率（没检索到时会不会硬编）。 还要能说出一个细节：Recall@k 是重排的天花板——粗召回没进来的文档，重排再强也变不出来。

失分点 5：把向量库当成黑盒

「一亿条向量，你怎么做到几十毫秒内返回？」

「向量数据库很快」不是答案。要能说出近似最近邻这个前提： 暴力比对是线性的，撑不住规模，所以索引结构用图或聚类把搜索范围压下来——HNSW 走的是分层可导航小图，IVF 先把向量聚成簇、只搜最近的几个簇， PQ 再把向量压成短码以省内存。 算法岗 还要能说出代价：这些结构都是用召回率换速度， 参数调得越激进越快、也越容易漏掉真正的最近邻；应用岗 至少要能说出「快是近似的代价换来的，参数需要按召回率调」。

四、自测：合上上文再答

下面三题不要往回翻。答错了不要紧，答错之后立刻看到解释，比答对更有用。

检索练习 · 第 1 题

下面哪一步属于离线索引链路？

  • 文档切分并入库
  • 查询改写成多条
  • 候选结果再重排
  • 上下文拼进提示

检索练习 · 第 2 题

用户查一个冷门产品型号，纯向量检索最容易在哪吃亏？

  • 专有名词记不住
  • 语义相近分不清
  • 长文档切不干净
  • 向量维度不够高

检索练习 · 第 3 题

哪一项不能作为「RAG 变好了」的证据？

  • 回答读起来更通顺
  • 召回率提升了十点
  • 重排后排序更靠前
  • 引用命中率提高了

五、真练一次：录一段 90 秒

读到这里你已经有了结构，但看懂结构不等于能说出来。面试是口头检索，必须练口头检索。 现在打开手机录音，别打草稿，按五个节拍说 90 秒，然后把录音放给自己听一遍——你会立刻听出哪一拍卡住了。

先说，再展开对照范文

「RAG 解决的是模型看不到私有知识的问题——它不改模型，而是让模型在回答前先看到相关材料。 结构上我会拆成两条链路：离线索引负责把文档解析、切分、向量化并入库；在线服务负责查询改写、检索、融合、重排、组装上下文再生成。 这两条链路的耦合点在于，离线决定召回的上限，在线决定这份上限能兑现多少，所以优化时我会先量召回、再动生成。 具体到我的做法，检索上我用的是向量加 BM25 的混合检索再 RRF 融合，因为纯向量对型号、错误码这种精确串不敏感；切分上按标题结构走，块内保留标题路径做上下文，代价是块大小不均、需要额外处理超长块。 评测分两层：检索层看 Recall@k 和 MRR，生成层看忠实度和拒答率。评价一个改动是否有用，我会先看 Recall@k 有没有动——因为它是重排的天花板。」

自检三问：① 我有没有说出「两条链路」而不是一条直线？② 我有没有主动讲一个取舍？ ③ 我有没有落到具体指标？三个都有，这段就成了。

六、本课要带走的三句话

  1. RAG 是两条链路，不是一条直线。离线索引决定召回上限，在线服务决定兑现多少。
  2. 主动讲取舍，比记住更多名词值钱。面试官分不清「做过」和「读过」时，取舍是唯一的区分信号。
  3. 没有指标就没有优化。Recall@k 是重排的天花板，这句话能救回一整轮面试。

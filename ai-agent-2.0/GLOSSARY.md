# AI Agent Glossary

本工作区对 AI Agent 相关术语的权威定义。所有课程、练习、学习记录都遵循这里的用词。术语只在用户真正理解后才加入——这里是压缩后的已知知识，不是预习字典。

## 核心概念

**LLM**:
大语言模型。一个无状态、文本进文本出的函数：给一段文本，返回一段文本。
_避免_: 模型、AI（太宽泛）

**Agent（智能体）**:
以 LLM 为大脑、能自主决定下一步动作（调用工具 / 回答 / 终止）、并在循环中运行直到完成任务的程序。
_避免_: 机器人、bot（歧义）

**Workflow（工作流）**:
代码预先定义好执行路径，LLM 只在某些步骤被调用。路径是确定的，LLM 不决定走哪条路。
_避免_: 流程、pipeline（当与 Agent 对比时）

**Agent vs Workflow 的判据**:
谁在控制路径？代码控制 → Workflow；LLM 控制 → Agent。

## Agent 的三大组件（Lilian Weng 经典划分）

**Planning（规划）**:
Agent 把一个大目标拆成可执行的子步骤的能力。常见做法：思维链（CoT）、ReAct 的 Thought→Action→Observation 循环。
_避免_: 计划（太日常）

**Memory（记忆）**:
Agent 在多步之间保留信息的能力。分短期（当前循环的上下文）和长期（跨会话的持久存储）。
_避免_: 缓存（歧义）

**Tool Use（工具调用 / Function Calling）**:
Agent 通过调用外部函数（搜索、代码执行、数据库查询等）来获取信息或产生副作用，突破 LLM 只能输出文本的限制。
_避免_: 插件（除非特指平台插件机制）

## 运行时要素

**Tool（工具）**:
一个有明确输入输出 schema 的函数，Agent 通过它作用于外部世界。
_避免_: 函数（太宽泛）、API（太宽泛）

**短期记忆（Short-term Memory）**:
当前会话内 LLM 能引用的信息，本质是 messages 列表里累积的历史消息。进程退出即丢失。
_避免_: 缓存、上下文（歧义）

**长期记忆（Long-term Memory）**:
跨会话持久化的信息。分两类：①会话历史（整段对话存文件/数据库，下次读回）；②事实/知识记忆（按语义检索，如 RAG）。本工作区目前只做了第①类。
_避免_: 存储（太宽泛）

**Agent Loop（Agent 循环）**:
"调用 LLM → 若 LLM 要求调用工具则执行工具 → 把工具结果喂回 LLM → 重复，直到 LLM 给出最终回答" 的迭代过程。这是 Agent 区别于一次性 LLM 调用的本质。

**Harness（运行时框架）**:
围绕 LLM 本体的工程外壳：循环控制、工具调度、上下文管理、错误恢复、状态持久化、评测。Agent 2.0 时代的核心战场。
_避免_: 框架（太宽泛）

**指数退避（Exponential Backoff）**:
重试暂时性错误的标准策略：每次失败后等待时间指数增长（如 1s → 2s → 4s），给服务端喘息时间，同时不让自己等太久。
_避免_: 重试（太宽泛）

**自我修复（Self-Recovery）**:
Agent 在工具失败或参数错误时，通过把错误信息回传给 LLM，让 LLM 自己决定下一步（换参数、换工具、告诉用户）的能力。Agent 2.0 比 1.0 鲁棒的关键之一。

## 代际划分（本工作区口径）

**Agent 1.0**:
2023–2024 年的早期 Agent：AutoGPT 式、单 Agent、纯 prompt 驱动、无评测、状态脆弱、经常跑飞。
_避免_: 传统 Agent

**Agent 2.0**:
2025–2026 年的新一代 Agent：工具原生、有 Harness、有评测、有持久状态、可控可观测、支持多 Agent 委托。本工作区教的就是这一代。
_避免_: 新一代 Agent（口语化）

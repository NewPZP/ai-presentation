什么是 AI Agent？

一个能跑的最小心智模型 · 约 8 分钟

先记住一句话

Agent = LLM + 工具 + 循环。 就这一句话，剩下都是细节。

如果你只能从这堂课带走一样东西，就带这句。它解释了为什么 ChatGPT 的对话框不是 Agent，也解释了为什么 AutoGPT 会让很多人失望——他们以为 Agent 是「更聪明的 LLM」，其实 Agent 是「把 LLM 套进一个会循环、能用工具的程序里」。

为什么不能直接调 LLM API？

你已经会用 ChatGPT 了。你也听说过可以写代码调用 LLM API——给它一句话，它回一句话，就像调用一个函数： 

# 这不是 Agent，这只是一次 LLM 调用
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "北京天气怎么样？"}]
)
print(response.choices[0].message.content)

问题来了：LLM 的训练数据是冻结的，它不知道此刻北京的天气。它会编一个，或者承认不知道。无论哪种，你都没拿到真实答案。

LLM 是一个无状态、文本进文本出的函数。它没有眼睛、没有手、没有记忆、不知道现在几点。它唯一能做的事，就是根据文本预测下一段文本。

如果你想让「AI」真的帮你查天气、读文件、发邮件、订机票——你必须给它工具，并让它自己决定什么时候用、用哪个、用几次。这就是 Agent 在做的事。

Agent 的三个要素

把这句话拆开看：

要素作用没有它会怎样
LLM 大脑：理解任务、决定下一步、生成回答 什么都做不了，连「下一步该干嘛」都想不出来
工具（Tool） 手脚：查天气、读文件、搜索、写代码……任何 Python 函数都能变成工具 Agent 只能嘴上说，不能真的动手
循环（Loop） 把「想 → 做 → 看结果」反复执行，直到任务完成 只能回答一个问题、调一次工具，就结束——那叫工作流，不叫 Agent

Anthropic 在 Building Effective Agents 里给了一个干净的判据：

谁在控制路径？ 如果是代码写死了步骤，那是 Workflow；如果是 LLM 自己决定下一步走哪，那是 Agent。

一个能跑的最小 Agent

下面这段代码不到 30 行，但它是一个真 Agent：它会自己决定要不要调工具、调几次，然后给出最终答案。先扫一眼，不用全懂，下面会逐段讲。 

# 最小 Agent：能查天气，能多步推理
from openai import OpenAI
import json

client = OpenAI()  # 需要 OPENAI_API_KEY 环境变量

# 1. 定义工具：一个普通 Python 函数
def get_weather(city: str) -> str:
    # 真实项目里这里会调天气 API，这里先用假数据
    weather = {"北京": "晴，25°C", "上海": "多云，28°C"}
    return weather.get(city, "未知")

# 2. 把工具的"说明书"告诉 LLM
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询某个城市的实时天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"]
        }
    }
}]

# 3. Agent 循环
messages = [{"role": "user", "content": "北京和上海今天哪个更热？"}]

while True:
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        tools=tools,
    )
    msg = resp.choices[0].message
    messages.append(msg)

    # 如果 LLM 没要求调工具，说明它要直接回答 → 结束
    if not msg.tool_calls:
        print(msg.content)
        break

    # 如果 LLM 要求调工具，就执行它指定的工具，把结果喂回去
    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)
        result = get_weather(**args)
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": result
        })

逐段拆解

第 1 步：工具就是普通函数。 get_weather 和你平时写的函数没区别。Agent 之所以能「动手」，全靠这些函数。后面你会把搜索、读文件、发邮件都写成这样的函数。

第 2 步：给 LLM 一份"说明书"。 LLM 不会自己去猜你有什么函数。你要用 JSON Schema 告诉它：有个工具叫 get_weather，它接受 city 参数。这份说明书叫 tool definition。LLM 看懂说明书后，才会在需要时「点名」要调它。

第 3 步：循环是 Agent 的心脏。 看那个 while True——这就是 Agent 区别于一次性 LLM 调用的本质：

  1. 把对话发给 LLM
  2. 看 LLM 是想直接回答（结束循环），还是想调工具
  3. 如果调工具：执行函数，把结果作为新的消息塞回对话
  4. 回到第 1 步，LLM 现在有了工具结果，可以继续推理

在这个例子里，LLM 会自己决定：「我需要先查北京，再查上海，然后比较两个温度。」 这两次工具调用、最后那次比较——路径是 LLM 决定的，不是你写死的。这就是 Agent。

为什么这是「Agent 2.0」而不是 AutoGPT 那种？ 因为它用的是模型原生的工具调用能力（tool calling），而不是用 prompt 硬哄模型输出一段「Thought: ... Action: ...」文本再正则解析。原生 tool calling 是 2024 年后所有主流模型的标准能力，更稳定、更可控、更便宜。这是代际分水岭之一。

动手跑起来

  1. 安装 SDK：pip install openai
  2. 设置环境变量：export OPENAI_API_KEY=sk-...
  3. 把上面的代码存为 agent.py，运行 python agent.py
  4. 试着把问题改成「北京、上海、广州今天哪个最热？」，观察 LLM 会调几次工具。

如果你还没有 API Key，可以用 OpenAI 平台申请一个，几块钱就够跑完这堂课。后面我们会换到 Anthropic 的 Claude，思路完全一样。

小测验

检查你的理解

下面哪个程序最符合「Agent」的定义？

  • 一个脚本：先调 LLM 翻译，再把结果存进数据库，路径写死在代码里
  • 一个循环：每次问 LLM 下一步调哪个工具，执行后把结果喂回，直到 LLM 说完成
  • 一个函数：输入城市名，返回固定格式的天气字符串
  • 一个 Prompt：让 LLM 一次性写完一篇关于 Agent 的文章

应用一下

用户问「帮我看看我邮箱里最近的发票并算出总额」。这个任务为什么必须用 Agent，而不是一次性 LLM 调用？

  • 因为 LLM 不会算加法，必须用循环多算几次
  • 因为一次性调用太慢，循环能加速
  • 因为需要先读邮箱（工具1），可能要翻页（工具2），再识别发票（工具3），再求和（工具4）——步骤数和顺序取决于邮件内容，无法预先写死
  • 因为 Agent 比 LLM 更便宜，省钱

项目实战

从 0 到 1 做一个你的 Agent 产品 · 约 25 分钟

这是毕业课

前 13 课你学了所有零件：工具、循环、记忆、流式、评测、生产化、多 SDK、RAG、多 Agent、架构选择。这一课把这些零件组装成一个真正的产品。

和前 13 课不同，这一课没有标准答案--因为产品要围绕你的创业方向。我会给一个完整的方法论和参考案例，但具体做什么由你定。

读完这一课后，你应该能独立完成：需求分析 → 架构选择 → 实现核心 → 评测 → 部署 → 迭代。这是从「会写 Agent 代码」到「能做 Agent 产品」的跨越。

第一步：选对问题

Agent 产品的成败 80% 取决于「选没选对问题」。再好的技术也救不了一个没人需要的产品。选问题的三条原则：

原则 1：问题里要有「路径不固定」

回顾第 13 课：路径能写死就用 Workflow，不需要 Agent。所以你的产品问题里必须有「路径需要 LLM 灵活决定」的部分，Agent 才有价值。

适合 Agent 的问题不适合的问题
「帮我看这个代码为啥不跑」--要看代码、跑测试、看报错、改 「每天汇总销售发飞书」--路径固定，Workflow 够
「研究下这家公司值不值得投资」--要查财报、算指标、对比、写报告 「翻译这段话」--一次 LLM 调用
「规划下周东京旅行」--要查航班、酒店、景点、排日程、权衡预算 「把 PDF 转 Word」--纯工具任务

原则 2：容错率要够高

Agent 会出错（选错工具、编造内容、跑偏）。如果你的场景容错率为零（如医疗诊断、金融交易），别用 Agent。好的 Agent 产品场景：

  • 有用户兜底：产出由人审核后再用（如代码生成、文案起草）
  • 可迭代：错了用户反馈，系统能改进
  • 试错成本低：错了重试就行，不造成不可逆损失

原则 3：价值要够大

Agent 比 Workflow 贵、慢。如果它省下的时间/创造的价值不超过成本，就没商业意义。问自己：用户愿意为这个功能付多少钱？Agent 的调用成本是多少？

好场景：一个 Agent 调用花 0.5 元，但帮用户省了 1 小时（值 100 元）。坏场景：花 0.5 元，只省了 10 秒。

第二步：架构选择

选好问题后，用第 13 课的决策框架定架构。常见产品的典型架构：

产品类型推荐架构
智能客服 Routing（分类）+ 内层按需：FAQ 用 Workflow+RAG，复杂咨询用 Agent
编程助手 纯 Agent（多工具：读文件、改代码、跑测试、看报错）
数据分析助手 Agent + 代码解释器（工具：执行 SQL、画图、统计）
研究助手 Agent + RAG + 搜索工具（查资料、汇总、写报告）
写作助手 Workflow（Prompt Chaining：大纲 → 初稿 → 校对 → 润色）
旅行规划 多 Agent（主 Agent + 航班专家 + 酒店专家 + 行程专家）

新手常犯的错：一上来就上最复杂的架构（多 Agent + RAG + 流式）。正确做法：从最小可用架构开始，评测驱动地加复杂度。

第三步：参考案例--「智询研究」

下面是一个完整的产品案例，展示从 0 到 1 的全过程。假设你做一个「公司研究助手」--用户输入一家公司名，Agent 自动查财报、算指标、对比同行、写研究报告。

3.1 需求拆解

用户：帮我研究下比亚迪值不值得投资

Agent 应该：
1. 查比亚迪近 3 年财报（工具：search_financial_data）
2. 算关键指标：营收增长、毛利率、PE（工具：calculate）
3. 查行业对比数据（工具：search_industry_data）
4. 综合分析，写一份报告（LLM 生成）

产出：结构化研究报告，含数据、图表、结论

3.2 架构决策

用决策框架走一遍：

  • 路径能写死吗？不能--不同公司能查到的数据不同，用户关注的指标不同，需要 LLM 灵活决定查什么、算什么
  • 要调几个工具？3-5 个--search_financial_data, calculate, search_industry_data, generate_chart
  • 能容忍不可预测性？能--研究报告由人审阅后再决策，不是直接交易
  • 延迟可接受？能--研究报告本就需要几分钟，用户有预期

结论：用 Agent，不需要多 Agent（工具不多、领域单一）。

3.3 最小实现

# research_agent.py
from openai import OpenAI
import json

client = OpenAI()

SYSTEM_PROMPT = """你是公司研究助手。
流程：
1. 用 search_financial_data 查公司近 3 年财报
2. 用 calculate 算关键指标（营收增长率、毛利率、PE）
3. 用 search_industry_data 查行业对比
4. 如有数值数据，用 generate_chart 生成图表
5. 综合分析，写结构化报告

报告格式：
## 公司概况
## 财务表现（含数据）
## 行业对比
## 投资建议（含风险提示）
"""

# ===== 工具 =====
def search_financial_data(company: str, years: int = 3) -> str:
    """查公司财报（示例用模拟数据）"""
    # 真实场景：调Wind/同花顺/雅虎财经 API
    data = {
        "比亚迪": "2023: 营收 4220亿 增长 42%, 毛利率 20%, 净利 300亿; 2022: 营收 2970亿, 毛利率 17%; 2021: 营收 2160亿, 毛利率 13%",
        "茅台": "2023: 营收 1500亿 增长 18%, 毛利率 91%, 净利 750亿",
    }
    return data.get(company, f"未找到 {company} 的财报数据")

def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/.() ")
    if not all(c in allowed for c in expression): raise ValueError("非法字符")
    return str(eval(expression))

def search_industry_data(industry: str) -> str:
    data = {
        "汽车": "行业平均毛利率 15%, 营收增长 10%。新能源细分赛道增长 35%",
        "白酒": "行业平均毛利率 65%, 营收增长 12%",
    }
    return data.get(industry, f"未找到 {industry} 行业数据")

def generate_chart(data: str, chart_type: str = "bar") -> str:
    # 真实场景：用 matplotlib/plotly 生成图片，返回 URL
    return f"已生成 {chart_type} 图表：{data[:50]}..."

# ===== 工具定义 =====
tools = [
    {"type": "function", "function": {
        "name": "search_financial_data",
        "description": "查询上市公司财报数据（营收、利润、毛利率等）",
        "parameters": {"type": "object", "properties": {
            "company": {"type": "string", "description": "公司名"},
            "years": {"type": "integer", "description": "查几年，默认3"}
        }, "required": ["company"]}
    }},
    {"type": "function", "function": {
        "name": "calculate",
        "description": "计算数学表达式，如 '(4220-2970)/2970*100' 算增长率",
        "parameters": {"type": "object", "properties": {
            "expression": {"type": "string"}
        }, "required": ["expression"]}
    }},
    {"type": "function", "function": {
        "name": "search_industry_data",
        "description": "查询某行业的平均指标，用于对比",
        "parameters": {"type": "object", "properties": {
            "industry": {"type": "string", "description": "行业名，如 '汽车'、'白酒'"}
        }, "required": ["industry"]}
    }},
    {"type": "function", "function": {
        "name": "generate_chart",
        "description": "生成图表（柱状图、折线图等）",
        "parameters": {"type": "object", "properties": {
            "data": {"type": "string", "description": "数据描述"},
            "chart_type": {"type": "string", "enum": ["bar", "line", "pie"]}
        }, "required": ["data"]}
    }},
]

tool_map = {
    "search_financial_data": search_financial_data,
    "calculate": calculate,
    "search_industry_data": search_industry_data,
    "generate_chart": generate_chart,
}

# ===== Agent 循环（和第 5 课的结构一致）=====
def research(query: str) -> str:
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": query}
    ]
    for _ in range(15):  # 研究任务可能步骤多，给 15 轮
        resp = client.chat.completions.create(
            model="gpt-4o",  # 研究任务用强模型
            messages=messages,
            tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            return msg.content
        for tc in msg.tool_calls:
            print(f"-> {tc.function.name}({tc.function.arguments})")
            args = json.loads(tc.function.arguments)
            try:
                result = tool_map[tc.function.name](**args)
            except Exception as e:
                result = f"工具失败：{e}"
            print(f"   {str(result)[:80]}")
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": str(result)})
    return "研究超时，步骤太多"

# 测试
print(research("研究下比亚迪值不值得投资"))

3.6 迭代

上线后的迭代节奏：

  1. 第 1 周：收集真实用户问题，看 Agent 在哪些 case 上挂了
  2. 第 2 周：把挂掉的 case 补进评测集，调 prompt 或加工具修复
  3. 第 3 周：对比不同模型（gpt-4o vs Claude）在评测集上的表现，选最优
  4. 第 4 周：优化成本--简单 case 路由到小模型，复杂 case 才用大模型
  5. 持续：每周跑评测，确保新改动没引入回归

第四步：你的产品该做什么

现在轮到你了。围绕你的创业方向，按这个流程走：

  1. 写一句话需求：你的 Agent 帮谁解决什么问题？例：「帮二级市场投资者快速研究一家公司是否值得投资」
  2. 用决策框架判断架构：路径能写死吗？要几个工具？容错率够吗？
  3. 列工具清单：Agent 需要哪些工具？每个工具的 name / description / parameters 写清楚
  4. 写 system prompt：身份 / 能力边界 / 行为规则 / 输出格式
  5. 实现最小版：用第 5 课的 Agent 类，跑通核心流程
  6. 设计 5-10 个评测用例：覆盖典型场景和边界 case
  7. 加上 Web 服务 + 流式：第 6-8 课的方案
  8. 生产化部署：第 9 课的方案
  9. 找 5 个真实用户试用：收集反馈，迭代

常见陷阱清单

陷阱症状解法
过度工程化 第一版就上多 Agent + RAG + 向量库 从单 Agent 最小版开始，评测驱动地加复杂度
工具描述不清 LLM 经常选错工具或传错参数 description 写清楚「什么时候用」「不用来干什么」，第 2 课的原则
system prompt 太长 LLM 忘规则、遵循率下降 控制在 500 字内，只写必要规则，用示例代替规则
不评测就上线 用户反馈差但不知道哪里有问题 上线前至少跑 10 个评测用例，工具准确率 80%+
忽略成本 单个调用成本超用户付费 监控每次调用的 token 数，简单 case 路由到小模型
没有兜底 Agent 出错时用户无反馈 工具失败要回传错误，Agent 卡住要超时退出，加「转人工」选项
过早优化 还没用户就纠结选哪个向量库 先用 Chroma 本地跑，有规模压力再换 Qdrant/Pinecone

下一步学习方向

这个课程到这里结束，但你的学习才刚开始。推荐方向：

  • 读源码：看 OpenAI Agents SDK 和 LangGraph 的源码，理解工业级 Agent 框架的设计

第 5 课 · AI Agent 2.0 实战

封装 Agent 类与错误处理

从「能跑」到「能稳定跑」· 约 15 分钟

前四课的代码长什么样？

走到这儿，你的 agent.py 应该有 100 多行了——工具定义、tools 列表、tool_map、系统提示、load/save messages、trim、两层循环……全堆在一个文件、平铺在模块顶层。能跑，但有几个问题开始浮现：

  1. 状态散落：messages、MEMORY_FILE、SYSTEM_PROMPT 都是全局变量，想改成「多用户」就得满文件改。
  2. 循环和逻辑耦合：Agent 循环、对话循环、工具调度混在一起，想换 LLM（比如从 OpenAI 换 Claude）要大改。
  3. 没有错误处理：API 一超时、一报错，整个程序就崩。用户聊到一半历史就丢了。

这一课把它们整理成两个东西：一个 Agent 类（封装状态和行为）+ 一层错误处理（应对生产环境的不可控）。这是从「玩具」走向「能上线」的第一道分水岭。

第一件事：封装成类

目标长这样——一个 WeatherAgent 类，把所有状态和方法收拢在一起：

from openai import OpenAI
import json, os, time
from typing import Callable

class WeatherAgent:
    """一个带工具、记忆、错误处理的最小 Agent 类。"""

    def __init__(
        self,
        system_prompt: str,
        memory_file: str = "memory.json",
        max_turns: int = 20,
        model: str = "gpt-4o-mini",
    ):
        self.client = OpenAI()
        self.model = model
        self.system_prompt = system_prompt
        self.memory_file = memory_file
        self.max_turns = max_turns

        self.tools: list[dict] = []          # tool 定义（给 LLM 看的）
        self.tool_map: dict[str, Callable] = {}  # name → 函数

        self.messages = self._load_messages()

    # --- 工具注册 ---
    def register_tool(self, name: str, description: str, params: dict, fn: Callable):
        """把一个 Python 函数注册成 Agent 可用的工具"""
        self.tools.append({
            "type": "function",
            "function": {
                "name": name,
                "description": description,
                "parameters": params,
            }
        })
        self.tool_map[name] = fn

    # --- 记忆 ---
    def _load_messages(self) -> list:
        if os.path.exists(self.memory_file):
            with open(self.memory_file, "r", encoding="utf-8") as f:
                return json.load(f)
        return [{"role": "system", "content": self.system_prompt}]

    def _save_messages(self):
        with open(self.memory_file, "w", encoding="utf-8") as f:
            json.dump(self.messages, f, ensure_ascii=False, indent=2)

    def _trim(self, messages: list) -> list:
        """保留 system + 最近 N 条；按完整轮次对齐（避免 tool 消息孤立）"""
        system = [m for m in messages if m["role"] == "system"]
        non_system = [m for m in messages if m["role"] != "system"]
        return system + non_system[-self.max_turns:]

    # --- 单轮 Agent 循环 ---
    def chat(self, user_input: str) -> str:
        """处理一轮用户输入，返回助手回复"""
        self.messages.append({"role": "user", "content": user_input})

        while True:
            messages_to_send = self._trim(self.messages)
            msg = self._call_llm_with_retry(messages_to_send)
            self.messages.append(msg)

            if not msg.tool_calls:
                self._save_messages()
                return msg.content

            # 执行工具调用
            for call in msg.tool_calls:
                result = self._execute_tool_with_retry(call)
                tool_msg = {
                    "role": "tool",
                    "tool_call_id": call.id,
                    "content": result,
                }
                self.messages.append(tool_msg)

    # --- 带重试的 LLM 调用（下面讲） ---
    def _call_llm_with_retry(self, messages, max_retries=3):
        for attempt in range(max_retries):
            try:
                resp = self.client.chat.completions.create(
                    model=self.model,
                    messages=messages,
                    tools=self.tools,
                )
                return resp.choices[0].message
            except Exception as e:
                if attempt == max_retries - 1:
                    raise  # 最后一次还失败就抛出
                wait = 2 ** attempt  # 1s, 2s, 4s 指数退避
                print(f"[LLM 调用失败，{wait}s 后重试] {e}")
                time.sleep(wait)

    # --- 带容错的工具执行（下面讲） ---
    def _execute_tool_with_retry(self, call, max_retries=2):
        for attempt in range(max_retries):
            try:
                args = json.loads(call.function.arguments)
                fn = self.tool_map[call.function.name]
                result = fn(**args)
                print(f"→ {call.function.name}({args}) = {result}")
                return str(result)
            except Exception as e:
                if attempt == max_retries - 1:
                    # 工具彻底失败，返回错误信息给 LLM，让它自己决定怎么办
                    return f"工具执行失败：{e}。请换种方式或告诉用户。"
                print(f"[工具 {call.function.name} 失败，重试] {e}")

看着长，但结构清晰：状态（self.messages、self.tools 等）都在 __init__ 里，行为（chat、register_tool、_load/_save/_trim）是方法。下面是使用方： 

# --- 定义工具函数（和前几课一样） ---
def get_weather(city: str) -> str:
    weather = {"北京": "晴，25°C", "上海": "多云，28°C", "广州": "雷阵雨，31°C"}
    return weather.get(city, "未知")

def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/.() ")
    if not all(c in allowed for c in expression):
        raise ValueError("只支持数字和 + - * /")
    return str(eval(expression))

# --- 组装并运行 Agent ---
SYSTEM_PROMPT = """你是一个简洁的天气助手。

规则：
- 涉及天气的问题，必须先调 get_weather 获取实时数据。
- 涉及数值计算时，使用 calculate 工具。
- 回答用中文，不超过两句话。"""

agent = WeatherAgent(
    system_prompt=SYSTEM_PROMPT,
    memory_file="memory.json",
    max_turns=20,
)

agent.register_tool(
    name="get_weather",
    description="查询某个城市的实时天气，返回形如 '晴，25°C' 的字符串",
    params={"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
    fn=get_weather,
)
agent.register_tool(
    name="calculate",
    description="计算数学表达式，如 '28 - 25' 或 '(25+28+31)/3'",
    params={"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]},
    fn=calculate,
)

# --- 对话循环 ---
print(f"天气助手已就绪（已加载 {len(agent.messages)} 条历史）")
while True:
    user_input = input("\n你: ")
    if user_input.strip() in ("exit", "quit", "退出"):
        break
    try:
        reply = agent.chat(user_input)
        print(f"\n助手: {reply}")
    except Exception as e:
        print(f"\n[出错了，但历史已保存] {e}")

为什么要封装成类？

对比一下：

维度前四课（平铺脚本）本课（Agent 类）
多用户 改 MEMORY_FILE 要满文件找 agent_a = WeatherAgent(memory_file="a.json")，agent_b = WeatherAgent(memory_file="b.json")，互不干扰
换模型 改 model="gpt-4o-mini" 这个硬编码 WeatherAgent(model="gpt-4o")，构造时传
测试 难——循环和全局状态耦合 可以单独测 _trim、register_tool、chat
换 LLM 厂商 大改——OpenAI 和 Claude 的 API 不同 把 _call_llm_with_retry 抽成接口，子类实现（下一阶段的事）

封装的核心收益不是「代码好看」，而是状态有了边界。前四课你只要跑一个 Agent 还行；一旦想做多用户、做测试、换模型，平铺结构就会让你改一处崩三处。类是把「这个 Agent 的所有状态和行为」收拢到一个对象里，边界清晰，外部只通过方法交互。

第二件事：错误处理

生产环境和玩具的差距，很大程度在怎么对待错误。前四课代码有一个隐含假设：API 永远成功、工具永远不抛错。现实是：

  • OpenAI API 会限流（429）、会超时、会内部错误（500）
  • 你的工具函数会抛异常（文件不存在、JSON 解析失败、网络请求挂掉）
  • LLM 偶尔会返回不合规的 tool_call（参数 schema 对不上、调了不存在的函数）

任何一处崩了，用户聊一半的历史可能就丢了。下面是两层容错。

层 1：LLM 调用的指数退避重试

API 错误大多是暂时性的——过几秒重试就好了。标准做法是指数退避：第一次失败等 1 秒，第二次等 2 秒，第三次等 4 秒，再失败才真报错。 

def _call_llm_with_retry(self, messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            resp = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                tools=self.tools,
            )
            return resp.choices[0].message
        except Exception as e:
            if attempt == max_retries - 1:
                raise  # 最后一次还失败 → 让上层处理
            wait = 2 ** attempt  # 1, 2, 4 秒
            print(f"[LLM 失败，{wait}s 后重试] {e}")
            time.sleep(wait)

注意最后一行 raise——三次都失败就抛出去，由调用方决定怎么办（在 chat 里没接，就冒到对话循环的 try 里，打印错误、历史已保存、用户还能继续聊）。

层 2：工具执行的容错

工具失败更常见，而且不应该让 Agent 崩。正确做法是：把错误信息作为 tool 消息的内容喂回给 LLM，让它自己决定怎么办——换种参数重试、换个工具、或者直接告诉用户「这个我做不了」。 

def _execute_tool_with_retry(self, call, max_retries=2):
    for attempt in range(max_retries):
        try:
            args = json.loads(call.function.arguments)
            fn = self.tool_map[call.function.name]
            result = fn(**args)
            return str(result)
        except Exception as e:
            if attempt == max_retries - 1:
                # 关键：不 raise，返回错误信息给 LLM
                return f"工具执行失败：{e}。请换种方式或告诉用户。"
            print(f"[工具 {call.function.name} 失败，重试] {e}")

这条原则很重要：工具失败时，不要让程序崩，也不要默默吞掉——把错误信息作为 tool 消息返回给 LLM。LLM 看到「工具执行失败：城市名不能为空」后，常常会自己修正参数重试。这就是 Agent 的自我修复能力，也是 Agent 2.0 比 1.0 更鲁棒的关键之一。

动手实验

  1. 把代码跑通，确认功能上和第 4 课一致——能查天气、能算数、能跨会话记忆。
  2. 故意制造错误：临时把 get_weather 改成 raise Exception("模拟 API 挂了")，再问「北京天气」。观察 Agent 的反应——你应该看到它说「工具执行失败，我无法查询实时天气」，而不是整个程序崩掉。
  3. 测重试：在 _call_llm_with_retry 第一次调用前加 raise Exception("模拟超时")，让它前两次必失败、第三次成功。看日志里会不会打印「[LLM 失败，1s 后重试]」然后继续跑。
  4. 多用户：再实例化一个 agent_b = WeatherAgent(memory_file="b.json")，给 a 说「我在北京」，给 b 说「我在上海」。退出重开，确认 a 和 b 各自记得各自的城市——这就是封装成类带来的直接好处。

一个常见的进阶问题：LLM 调了不存在的工具怎么办？

偶尔 LLM 会返回一个 call.function.name = "get_temperature"（它记错了名字），而你的 tool_map 里只有 get_weather。此时 self.tool_map[call.function.name] 会抛 KeyError。

这个错误被层 2 的 except 接住后，返回给 LLM 的信息是「工具执行失败：'get_temperature'。请换种方式」。但更好的做法是给 LLM 一个更明确的提示：

def _execute_tool_with_retry(self, call, max_retries=2):
    for attempt in range(max_retries):
        try:
            args = json.loads(call.function.arguments)
            if call.function.name not in self.tool_map:
                available = list(self.tool_map.keys())
                return f"没有叫 '{call.function.name}' 的工具。可用的有：{available}"
            fn = self.tool_map[call.function.name]
            return str(fn(**args))
        except Exception as e:
            if attempt == max_retries - 1:
                return f"工具执行失败：{e}"
            print(f"[工具失败，重试] {e}")

这样 LLM 看到「没有叫 X 的工具，可用的是 [A, B]」后，通常下一轮就会改调对的工具。这是用错误信息引导 LLM 自我修正的典型模式。

小测验

检查你的理解

工具函数 get_weather 抛了 KeyError（城市名不存在）。最合理的处理是？

  • 让程序崩掉，让用户重启
  • 默默吞掉错误，给 LLM 返回空字符串
  • 把错误信息作为 tool 消息返回给 LLM，让它知道发生了什么、自己决定下一步
  • 自动把城市名改成"北京"再重试

应用一下

OpenAI API 偶尔会返回 429（请求太频繁）。你的 Agent 应该怎么应对？

  • 立即重试，越快越好
  • 用指数退避：等 1s → 重试；再失败等 2s → 重试；再失败等 4s → 重试；还失败才报错给上层
  • 直接放弃这一轮，告诉用户「服务不可用」
  • 换一个 LLM 厂商

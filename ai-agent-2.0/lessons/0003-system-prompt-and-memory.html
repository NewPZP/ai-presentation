第 3 课 · AI Agent 2.0 实战

系统提示与最简记忆

让 Agent 有人格、能持续对话 · 约 12 分钟

这一课要解决两件事

第 2 课 结尾留了个悬念：你问「今天该穿什么衣服？我在北京」，LLM 可能不调 get_weather 直接凭印象答。这不算错，但不是你想要的——你希望它先查再答。

这堂课用两件事解决它，顺便把 Agent 从「跑一次就结束」升级成「能持续对话」：

  1. 系统提示（System Prompt）：给 Agent 一份「行为守则」，告诉它你是谁、该怎么做事、什么必须做、什么别做。
  2. 对话循环：把 messages 列表保留下来，循环接收用户输入。这就是 Agent 的「短期记忆」。

第一件事：系统提示

到目前为止，我们的 messages 列表第一项都是用户的提问。其实 OpenAI（和所有主流 LLM API）都支持一种特殊角色：system。它放在列表最前面，是「写给 LLM 的设定」，不是对话的一部分。 

messages = [
    {
        "role": "system",
        "content": """你是一个简洁的天气助手。

规则：
- 涉及天气的问题，必须先调 get_weather 获取实时数据，不要凭印象编造。
- 涉及数值计算时，使用 calculate 工具，不要心算。
- 回答用中文，不超过两句话。"""
    },
    {
        "role": "user",
        "content": "今天该穿什么衣服？我在北京。"
    }
]

加上这条 system 消息后，再问「今天该穿什么衣服？我在北京」，你会看到调度轨迹变了——LLM 这次主动调了 get_weather('北京')，再根据真实天气给穿衣建议。

为什么 system prompt 有效？ 因为 LLM 在生成回复时，会把整个 messages 列表作为上下文。system 消息排在最前，权重最高，相当于「导演在开拍前给演员的嘱咐」。用户的每句话都会被它过滤一遍。

系统提示该写什么？

一个好系统提示通常包含四块，按需取用：

模块作用本课的例子
身份 你是谁、为谁服务 「你是一个简洁的天气助手」
能力边界 你能做什么、不能做什么 （隐含在身份里：只管天气和计算）
行为规则 必须做、禁止做、优先级 「涉及天气必须先调 get_weather」「不要心算」
输出风格 语气、长度、格式 「中文，不超过两句话」

新手最常犯的错：把所有规则都塞进 system prompt，写得像产品需求文档。规则越多，LLM 记得越少、越容易互相冲突。只写和当前任务强相关的规则，能少则少。规则不是写给人看的合规文件，是给 LLM 的注意力锚点。

第二件事：对话循环 = 最简记忆

现在的 Agent 每次跑完就结束——下次问新问题，它忘了上一轮说过什么。怎么让它「持续对话」？

答案极其朴素：把 messages 列表保留下来，循环接收用户输入。

# 对话循环：外层接收用户输入
while True:
    user_input = input("\n你: ")
    if user_input.lower() in ("exit", "quit", "退出"):
        break

    messages.append({"role": "user", "content": user_input})

    # Agent 循环：内层处理工具调用
    while True:
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            print(f"\n助手: {msg.content}")
            break

        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = tool_map[call.function.name](**args)
            print(f"→ {call.function.name}({args}) = {result}")
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result
            })

注意结构——现在是两层循环：

  • 外层（对话循环）：等用户说话，把话塞进 messages
  • 内层（Agent 循环）：处理这一轮可能出现的多次工具调用，直到 LLM 给出最终回答

而 messages 列表是跨轮保留的——这就是「记忆」。第 2 课的 Agent 跑完一次，messages 就丢了；这一课的 Agent 把它存下来，下一轮对话时整段历史一起发给 LLM，LLM 就能引用上下文。

完整代码

from openai import OpenAI
import json

client = OpenAI()

# --- 工具（沿用第 2 课） ---
def get_weather(city: str) -> str:
    weather = {"北京": "晴，25°C", "上海": "多云，28°C", "广州": "雷阵雨，31°C"}
    return weather.get(city, "未知")

def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/.() ")
    if not all(c in allowed for c in expression):
        return "错误：只支持数字和 + - * /"
    try:
        return str(eval(expression))
    except Exception as e:
        return f"错误：{e}"

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询某个城市的实时天气，返回形如 '晴，25°C' 的字符串",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "计算一个数学表达式，如 '28 - 25' 或 '(25+28+31)/3'。当需要精确数值计算时使用。",
            "parameters": {
                "type": "object",
                "properties": {"expression": {"type": "string"}},
                "required": ["expression"]
            }
        }
    }
]

tool_map = {"get_weather": get_weather, "calculate": calculate}

# --- 新增：系统提示 ---
SYSTEM_PROMPT = """你是一个简洁的天气助手。

规则：
- 涉及天气的问题，必须先调 get_weather 获取实时数据，不要凭印象编造。
- 涉及数值计算时，使用 calculate 工具，不要心算。
- 回答用中文，不超过两句话。"""

# --- 对话循环 + Agent 循环 ---
messages = [{"role": "system", "content": SYSTEM_PROMPT}]

print("天气助手已就绪（输入 '退出' 结束）")

while True:
    user_input = input("\n你: ")
    if user_input.strip() in ("exit", "quit", "退出"):
        break

    messages.append({"role": "user", "content": user_input})

    while True:
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            print(f"\n助手: {msg.content}")
            break

        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = tool_map[call.function.name](**args)
            print(f"→ {call.function.name}({args}) = {result}")
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result
            })

跑一下，体会「记忆」

运行 python agent.py，按这个顺序输入：

你: 北京今天怎么样？
→ get_weather({'city': '北京'}) = 晴，25°C
助手: 北京今天晴，气温 25°C，适合外出。

你: 那上海呢？                    # ← 注意：没说"天气"，但 LLM 知道你在问天气
→ get_weather({'city': '上海'}) = 多云，28°C
助手: 上海今天多云，气温 28°C，比北京略热。

你: 两个城市平均多少度？
→ calculate({'expression': '(25+28)/2'}) = 26.5
助手: 两地平均气温约 26.5°C。

看第二轮——你只说了「那上海呢？」，LLM 就知道你在问天气。这不是魔法，是因为整段 messages 历史都被发给了它，它看到了上一轮你问北京天气的上下文。

洞察：「记忆」是什么？ LLM 本身是彻底无状态的——它没有硬盘、没有变量、不记得上一秒发生了什么。所谓「Agent 记住了对话」，真相是：你的代码把历史消息重新发给了它一遍。每轮对话，LLM 都是把整个 messages 列表从头读一遍，假装自己「记得」。

这条洞察决定了一件事：记忆会膨胀。对话越长，messages 越长，每次调用的 token 越多、越贵、越慢。这就是后续课程要解决的核心工程问题之一（摘要、压缩、长期记忆、RAG）。但现在先享受「能用」的状态，把「能用得好」留给后面。

动手实验

  1. 把系统提示里的规则删到只剩一句「你是一个天气助手」，再问「今天该穿什么衣服？我在北京」。观察 LLM 还会不会主动调 get_weather。这能让你直观感受 system prompt 对行为的引导强度。
  2. 故意连续问 5 轮天气，然后问「我刚才问过哪些城市？」。LLM 应该能答对——因为整段历史都在 messages 里。这就是「短期记忆」的边界：能记住这次会话里的内容。
  3. 退出程序，重新运行 python agent.py，再问「我刚才问过哪些城市？」。这次它会答不上来——因为 messages 是内存里的列表，进程一退出就没了。这就是「短期记忆」的另一半边界：跨会话不保留。

实验 3 的现象会自然引出下一课的主题：长期记忆。在那之前，先确认你理解了为什么实验 3 会失败——这不是 LLM 的 bug，是设计使然。

小测验

检查你的理解

关于 system prompt，下面哪句最准确？

  • 它是 LLM 训练时固化的人格，改不了
  • 它必须放在 messages 列表最后，作为收尾
  • 它是一条 role="system" 的消息，放在 messages 最前面，是写给 LLM 的行为守则，权重高于普通对话
  • 它只用来声明模型名称，不能写规则

应用一下

你重启了 Agent 程序，发现它忘了你上一会话说过的所有事。这为什么？

  • LLM 的记忆模块坏了，需要重启 API
  • 所谓「记忆」只是 messages 列表，进程退出后内存释放，列表就没了——LLM 本身从来就不记得任何事
  • 系统提示写错了，需要加一句「请记住所有历史」
  • OpenAI 限制了跨会话存储，需要付费升级

下一步

你的 Agent 现在有人格、能持续对话，但还是「金鱼记忆」——重启就忘。下一课我们给它加长期记忆：把对话历史写到文件（或数据库），下次启动时读回来。这是从「能跑」到「能用」的最后一公里。

第 4 课 · AI Agent 2.0 实战

长期记忆

让 Agent 重启后还记得你 · 约 14 分钟

上一课留下的悬念

第 3 课 结尾做了个实验：退出程序、重新运行，再问「我刚才问过哪些城市？」——Agent 答不上来。原因是 messages 列表存在内存里，进程一退出就没了。

这一课解决这个问题。方式比你想的朴素：把 messages 写到文件，下次启动时读回来。

第 3 课那条洞察的另一半：既然「记忆」是代码喂给 LLM 的，那只要代码把它存下来，下次再喂回去，就有了长期记忆。LLM 本身不需要变，变的是你的工程。

三种记忆，别混在一起

在动手之前，先把术语理清楚——这是后面所有讨论的基础：

类型存哪生命周期本课对应
短期记忆 messages 列表（内存） 一次会话内，进程退出就没 第 3 课已实现
长期记忆（会话历史） 文件 / 数据库 跨会话，按用户或会话 ID 持久化 本课要实现
长期记忆（知识 / 事实） 向量数据库、知识图谱 跨会话，按语义检索 后续课程（RAG 那块）

本课只做第 2 种——把整段对话历史存下来。第 3 种（向量检索）是更高级的玩法，等基础打牢再讲，不然容易一上来就被各种「RAG」「embedding」术语绕晕。

最小实现：JSON 文件

先用最朴素的方式——一个 JSON 文件。每个用户一个文件，文件里就是他的 messages 列表。 

import json
import os

MEMORY_FILE = "memory.json"  # 真实项目里按用户 ID 分文件

def load_messages():
    """启动时从文件读历史；没文件就新建，带系统提示"""
    if os.path.exists(MEMORY_FILE):
        with open(MEMORY_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    # 没有历史 → 初始化系统提示
    return [{"role": "system", "content": SYSTEM_PROMPT}]

def save_messages(messages):
    """每次对话后把整段历史写回文件"""
    with open(MEMORY_FILE, "w", encoding="utf-8") as f:
        json.dump(messages, f, ensure_ascii=False, indent=2)

然后把第 3 课的对话循环稍改两行：

messages = load_messages()  # ← 启动时读历史（之前是新建空列表）

while True:
    user_input = input("\n你: ")
    if user_input.strip() in ("exit", "quit", "退出"):
        save_messages(messages)  # ← 退出时存历史（之前什么都不做）
        break

    messages.append({"role": "user", "content": user_input})

    while True:
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            print(f"\n助手: {msg.content}")
            save_messages(messages)  # ← 每轮也存一次，防止意外崩溃丢历史
            break

        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = tool_map[call.function.name](**args)
            print(f"→ {call.function.name}({args}) = {result}")
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result
            })

# 第一次运行
你: 我在北京
助手: 好的，已记下你在北京。

# 退出，重新运行 python agent.py

你: 我在哪个城市？

它记住了。恭喜，你的 Agent 有了长期记忆。

但马上会撞墙：记忆会膨胀

跑通后，故意聊个 20 轮天气（每轮都触发工具调用）。然后再聊几轮，你大概率会遇到两类错误之一： 

# 错误 A：超过模型上下文窗口
openai.BadRequestError: Error code: 400 - {
  "error": {
    "message": "This model's maximum context length is 128000 tokens..."
  }
}

# 错误 B：没报错但变贵变慢
# 每轮都把全部历史发过去，token 消耗线性增长

这就是第 3 课预告过的问题：记忆会膨胀。每轮对话都把完整历史喂给 LLM，对话越长，每次调用的 token 越多——直到撑爆模型的上下文窗口。

这是 Agent 工程的核心难题之一，没有银弹。下面介绍三种主流应对方式，从最简单到最复杂。本课只要你能实现「最简版」就够了，但要知道后面有更好的方案。

方案 1：滑动窗口（最简单）

只保留最近 N 轮对话，老的消息直接丢弃。N 通常取 5–10。 

def trim_messages(messages, max_turns=8):
    """保留 system + 最近 max_turns 条消息"""
    system = [m for m in messages if m["role"] == "system"]
    non_system = [m for m in messages if m["role"] != "system"]
    # 取最后 N 条，但要小心 tool 消息不能脱离 tool_call 单独存在
    trimmed = non_system[-max_turns:]
    return system + trimmed

优点：5 行代码搞定，token 消耗可控。
缺点：早期对话内容彻底丢失。如果你 10 轮前告诉它「我在北京」，第 11 轮它就忘了。

方案 2：摘要压缩（折中）

当 messages 超过阈值时，让 LLM 把老消息总结成一段摘要，用摘要替换老消息。 

def summarize_old_messages(messages, keep_recent=4):
    """把老消息压缩成摘要，保留最近 keep_recent 轮"""
    system = [m for m in messages if m["role"] == "system"]
    non_system = [m for m in messages if m["role"] != "system"]

    old = non_system[:-keep_recent]
    recent = non_system[-keep_recent:]

    if not old:
        return messages  # 没什么可压缩的

    # 让 LLM 把 old 总结成一段摘要
    summary_resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{
            "role": "user",
            "content": f"请用 3 句话总结以下对话的关键信息：\n\n{json.dumps(old, ensure_ascii=False)}"
        }]
    )
    summary = summary_resp.choices[0].message.content

    return system + [{
        "role": "system",
        "content": f"之前的对话摘要：{summary}"
    }] + recent

优点：保留关键信息（用户在哪、目标是什么），token 消耗可控。
缺点：多一次 LLM 调用，有延迟；摘要可能丢细节；实现复杂度上升。

方案 3：向量化检索（最复杂，留给后续课）

把每条消息存进向量数据库（如 Chroma、Qdrant），下次对话时用相关问题检索出最相关的几条历史，只把这些喂给 LLM。这就是 RAG 的思路。

本课不实现这个，因为：① 需要引入 embedding 模型和向量库，依赖一多概念就乱；② 在你还没把基础 Agent 跑顺之前，RAG 通常是把问题搞复杂的根源。等你做完前几课、确认真的需要它时，我们再开一整课讲。

本课的完整代码

下面是带滑动窗口的完整版本（方案 1 + 持久化）：

from openai import OpenAI
import json, os

client = OpenAI()

# --- 工具（沿用） ---
def get_weather(city: str) -> str:
    weather = {"北京": "晴，25°C", "上海": "多云，28°C", "广州": "雷阵雨，31°C"}
    return weather.get(city, "未知")

def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/.() ")
    if not all(c in allowed for c in expression):
        return "错误：只支持数字和 + - * /"
    try:
        return str(eval(expression))
    except Exception as e:
        return f"错误：{e}"

tools = [
    {"type": "function", "function": {
        "name": "get_weather",
        "description": "查询某个城市的实时天气",
        "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}
    }},
    {"type": "function", "function": {
        "name": "calculate",
        "description": "计算数学表达式，如 '28 - 25'。需要精确数值计算时使用。",
        "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}
    }}
]
tool_map = {"get_weather": get_weather, "calculate": calculate}

SYSTEM_PROMPT = """你是一个简洁的天气助手。

规则：
- 涉及天气的问题，必须先调 get_weather 获取实时数据。
- 涉及数值计算时，使用 calculate 工具。
- 回答用中文，不超过两句话。"""

# --- 记忆：持久化 + 滑动窗口 ---
MEMORY_FILE = "memory.json"
MAX_TURNS = 20  # 保留最近 20 条非 system 消息

def load_messages():
    if os.path.exists(MEMORY_FILE):
        with open(MEMORY_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    return [{"role": "system", "content": SYSTEM_PROMPT}]

def save_messages(messages):
    with open(MEMORY_FILE, "w", encoding="utf-8") as f:
        json.dump(messages, f, ensure_ascii=False, indent=2)

def trim_messages(messages, max_turns=MAX_TURNS):
    """保留 system 消息 + 最近 max_turns 条非 system 消息。
    注意：tool 消息必须紧跟在对应的 tool_call 之后，否则 API 会报错。
    这里简化处理——直接按条数截断，复杂场景需要更小心的对齐。"""
    system = [m for m in messages if m["role"] == "system"]
    non_system = [m for m in messages if m["role"] != "system"]
    return system + non_system[-max_turns:]

# --- 主循环 ---
messages = load_messages()
print(f"天气助手已就绪（已加载 {len(messages)} 条历史消息）")

while True:
    user_input = input("\n你: ")
    if user_input.strip() in ("exit", "quit", "退出"):
        save_messages(messages)
        break

    messages.append({"role": "user", "content": user_input})

    # 发送前裁剪，避免 token 爆炸
    messages_to_send = trim_messages(messages)

    while True:
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages_to_send,
            tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)
        messages_to_send.append(msg)

        if not msg.tool_calls:
            print(f"\n助手: {msg.content}")
            save_messages(messages)
            break

        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = tool_map[call.function.name](**args)
            print(f"→ {call.function.name}({args}) = {result}")
            tool_msg = {
                "role": "tool",
                "tool_call_id": call.id,
                "content": result
            }
            messages.append(tool_msg)
            messages_to_send.append(tool_msg)

动手实验

  1. 跑通后做跨会话测试：第一次运行说「我在北京」，退出，重开问「我在哪个城市」。确认它能答对。
  2. 打开 memory.json 看看里面长什么样。你会直观看到「记忆」就是一堆 JSON——没有什么神秘的，就是上次对话的 messages 列表。
  3. 把 MAX_TURNS 改成 4，故意聊 10 轮，然后问第 1 轮聊过的事。它会答不上来——这就是滑动窗口的代价。再改回 20，看能不能答对。
  4. （进阶）试着把存储从 JSON 文件换成 SQLite。代码改动很小（json.load → sqlite3 查询），但能体会「持久化层」和「Agent 逻辑」分离的好处。这一步是为后面部署做铺垫——线上服务不能依赖本地文件。

一个容易被忽略的坑：tool 消息的完整性

代码里 trim_messages 有个简化处理：直接按条数截断。但 OpenAI 的 API 有个硬规则——每条 tool 消息必须紧跟在对应的 tool_call 之后，否则会报 "tool message without preceding tool_call" 错误。

如果裁剪刚好把 assistant 消息（含 tool_call）留下了，但对应的 tool 消息被截掉了，就会触发这个错误。本课代码在大多数情况能跑通（因为 MAX_TURNS=20 通常包含完整的轮次），但生产环境需要更小心的对齐逻辑——裁剪要在「完整的一轮」边界上裁，不能在轮中间切。

这是工程代码和教学代码的差距所在。本课给你的是「能跑且能理解」的版本，生产级实现需要处理边界情况——这是后续「Agent 工程化」课程的主题。先把现象记下来：哪天你遇到这个报错，就知道原因了。

小测验

检查你的理解

Agent 能「记住」跨会话的对话，本质上是因为？

  • LLM 有内置的长期记忆模块，自动存储历史
  • 你的代码把上次对话的 messages 存到文件/数据库，这次启动时读回来再发给 LLM
  • OpenAI 的 API 会自动帮你保存所有历史
  • 系统提示里写了「请记住所有对话」

应用一下

你的 Agent 用了滑动窗口保留最近 10 条消息。用户第 1 轮说「我在北京」，聊到第 15 轮时问「我在哪个城市？」——Agent 答不出来。下面哪种处理最合理？

  • 把 MAX_TURNS 改成 1000，永不丢失
  • 每轮都让 LLM 把所有历史总结一遍
  • 把「用户在哪」这类关键事实单独抽出来存到「用户档案」里，每轮作为 system 消息注入——这就是「事实记忆」和「对话历史」分离的设计
  • 直接换更大的模型，上下文窗口够大就行

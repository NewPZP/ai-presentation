第 10 课 · AI Agent 2.0 实战

切换到 Claude

从 OpenAI SDK 到 Anthropic SDK · 约 14 分钟

为什么要学两个 SDK？

前 9 课你都用 OpenAI 的 SDK。但做产品时只绑一家是危险的--API 涨价、限流、服务故障、某家模型在某个任务上更好，都可能让你想换。会两家 SDK，你才能根据任务和成本选最合适的。

这一课用 Anthropic 的 Claude 重写 Agent。Claude 在长上下文、代码理解、工具调用上有自己的特色，和 OpenAI 的 API 设计也略有不同。学完这课你会有一个直觉：LLM API 的核心概念是相通的，差异在细节。

这也是为什么前 9 课我们坚持用原生 SDK 而不是 LangChain--当你理解了原生 API 的差异，再用框架就是「封装的便利」而不是「黑箱的依赖」。反过来，一上来就用框架，换厂商时就是灾难。

两个 SDK 的核心差异

先看一张对照表，心里有数：

概念OpenAIAnthropic Claude
客户端 from openai import OpenAI from anthropic import Anthropic
调用方法 client.chat.completions.create() client.messages.create()
系统提示 放在 messages 里，role 为 "system" 独立参数 system=，不在 messages 里
消息格式 {"role": "user", "content": "文本"} {"role": "user", "content": [{"type": "text", "text": "文本"}]}（更结构化）
工具定义 tools=[{"type": "function", "function": {...}}] tools=[{"name": ..., "input_schema": ...}]（少一层嵌套）
工具调用 返回 message.tool_calls 列表 返回 content 里的 tool_use 块
工具结果 role 为 "tool" 的消息 role 为 "user"，content 里放 tool_result 块
停止原因 finish_reason: "tool_calls" 或 "stop" stop_reason: "tool_use" 或 "end_turn"
最大输出 由模型决定 必须显式传 max_tokens 参数

看起来差异很多，但本质都是把同样的概念用不同的 JSON 结构表达。下面逐项实现。

第一件事：系统提示的位置变了

OpenAI 把 system 放在 messages 列表第一项：

# OpenAI
messages = [
    {"role": "system", "content": "你是天气助手"},
    {"role": "user", "content": "北京天气"}
]
resp = client.chat.completions.create(model=..., messages=messages)

Claude 把 system 作为独立参数，不混在 messages 里：

# Claude
messages = [
    {"role": "user", "content": "北京天气"}
]
resp = client.messages.create(
    model=...,
    system="你是天气助手",  # ← 独立参数
    messages=messages,
    max_tokens=1024,  # ← Claude 必填
)

为什么这个差异重要？ 因为它影响你的记忆存储结构。前 9 课的 messages 列表第一项是 system，但切到 Claude 后 messages 里不该有 system。解决方案：把 system_prompt 作为 Agent 的属性单独存，不放进 messages。调用时临时拼上去。这是个好的设计习惯，无论用哪家 SDK 都适用。

第二件事：消息内容的结构化

OpenAI 的 content 是字符串：

{"role": "user", "content": "北京天气"}

Claude 的 content 是块列表，更结构化：

{"role": "user", "content": [{"type": "text", "text": "北京天气"}]}

看起来繁琐，但好处是能混合多种类型--同一条消息里可以同时有文本、图片、工具结果。Claude 的设计更面向多模态。

简单文本可以传字符串，Claude SDK 会自动转成 [{"type": "text", "text": ...}]。但工具结果是块，必须用列表形式。

第三件事：工具定义和调用

OpenAI 的工具定义多一层 function 嵌套：

# OpenAI
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询城市天气",
        "parameters": {"type": "object", "properties": {...}}
    }
}]

Claude 更扁平，用 input_schema 替代 parameters：

# Claude
tools = [{
    "name": "get_weather",
    "description": "查询城市天气",
    "input_schema": {"type": "object", "properties": {...}}
}]

工具调用的返回也不同。OpenAI 在 message.tool_calls 里：

# OpenAI 返回
msg.tool_calls = [
    {"id": "call_xxx", "function": {"name": "get_weather", "arguments": '{"city":"北京"}'}}
]

Claude 把工具调用作为 content 里的一个 tool_use 块：

# Claude 返回
msg.content = [
    {"type": "text", "text": "我来查一下北京天气"},  # 可能有文本
    {"type": "tool_use", "id": "toolu_xxx", "name": "get_weather", "input": {"city": "北京"}}
]
msg.stop_reason = "tool_use"  # 而非 "end_turn"

注意 Claude 的 input 直接是 dict，不需要 json.loads 解析。这是个体验提升。

第四件事：工具结果的格式

OpenAI 用 role 为 "tool" 的独立消息：

# OpenAI
messages.append({
    "role": "tool",
    "tool_call_id": "call_xxx",
    "content": "晴，25°C"
})

Claude 把工具结果放在 role 为 "user" 的消息里，content 是 tool_result 块：

# Claude
messages.append({
    "role": "user",
    "content": [{
        "type": "tool_result",
        "tool_use_id": "toolu_xxx",
        "content": "晴，25°C"
    }]
})

这个差异最容易踩坑--Claude 的工具结果消息 role 是 "user" 而不是某个独立的 "tool"。语义上是「用户（代表工具）把结果发给模型」。

完整的 Claude 版 Agent 循环

把上面四件事拼起来，就是 Claude 版的 Agent：

from anthropic import Anthropic
import json

client = Anthropic()  # 需要 ANTHROPIC_API_KEY 环境变量

SYSTEM_PROMPT = """你是一个简洁的天气助手。
规则：
- 涉及天气的问题，必须先调 get_weather 获取实时数据。
- 涉及数值计算时，使用 calculate 工具。
- 回答用中文，不超过两句话。"""

# 工具函数（和 OpenAI 版完全一样）
def get_weather(city: str) -> str:
    weather = {"北京": "晴，25°C", "上海": "多云，28°C", "广州": "雷阵雨，31°C"}
    return weather.get(city, "未知")

def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/.() ")
    if not all(c in allowed for c in expression):
        raise ValueError("只支持数字和 + - * /")
    return str(eval(expression))

# Claude 工具定义（扁平结构）
tools = [
    {
        "name": "get_weather",
        "description": "查询某个城市的实时天气",
        "input_schema": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"]
        }
    },
    {
        "name": "calculate",
        "description": "计算数学表达式，如 '28 - 25'",
        "input_schema": {
            "type": "object",
            "properties": {"expression": {"type": "string"}},
            "required": ["expression"]
        }
    }
]

tool_map = {"get_weather": get_weather, "calculate": calculate}

# Agent 循环
messages = []

def chat(user_input: str) -> str:
    messages.append({"role": "user", "content": user_input})

    while True:
        resp = client.messages.create(
            model="claude-3-5-sonnet-20241022",  # 或其他 Claude 模型
            system=SYSTEM_PROMPT,  # ← 独立参数，不进 messages
            messages=messages,
            tools=tools,
            max_tokens=1024,  # ← Claude 必填
        )

        # 把 assistant 回复存进 messages
        messages.append({"role": "assistant", "content": resp.content})

        # 判断是否要调工具
        if resp.stop_reason != "tool_use":
            # 不调工具 -> 提取文本返回
            text_parts = [b.text for b in resp.content if b.type == "text"]
            return "".join(text_parts)

        # 要调工具 -> 找出所有 tool_use 块，执行，把结果喂回去
        tool_results = []
        for block in resp.content:
            if block.type == "tool_use":
                print(f"-> {block.name}({block.input})")
                try:
                    result = tool_map[block.name](**block.input)
                except Exception as e:
                    result = f"工具执行失败：{e}"

                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": str(result)
                })

        # 工具结果作为 user 消息喂回去
        messages.append({"role": "user", "content": tool_results})

# 测试
print(chat("北京和上海今天哪个更热？"))

输出和 OpenAI 版几乎一样：

-> get_weather({'city': '北京'})
-> get_weather({'city': '上海'})
上海更热，28°C 比北京的 25°C 高 3 度。

关键差异的工程影响

1. system_prompt 要从 messages 里抽出来

前 9 课的 messages 列表第一项是 system 消息。切到 Claude 后不能这样--system 是独立参数。好的设计是：把 system_prompt 作为 Agent 的属性单独存，调用时拼到 Claude 的 system 参数或 OpenAI 的 messages[0]。 

class WeatherAgent:
    def __init__(self, system_prompt, llm_backend, ...):
        self.system_prompt = system_prompt  # 单独存
        self.llm_backend = llm_backend  # "openai" 或 "claude"
        self.messages = []  # 不含 system

    def chat(self, user_input):
        if self.llm_backend == "openai":
            # 调用时把 system 塞到 messages 最前
            msgs = [{"role": "system", "content": self.system_prompt}] + self.messages
            # ... OpenAI 调用逻辑
        else:
            # Claude: system 作为独立参数
            resp = client.messages.create(
                system=self.system_prompt,
                messages=self.messages,
                # ...
            )

这样换厂商时，self.messages 的结构不用变，只改调用逻辑。

2. Claude 的 input 直接是 dict，不用 json.loads

OpenAI 的 arguments 是 JSON 字符串，要 json.loads(call.function.arguments) 才能用。Claude 的 input 直接是 dict，block.input 就能用。这是个体验提升，少一层解析就少一个出错点。

3. Claude 必须传 max_tokens

OpenAI 的 max_tokens 是可选的（默认拿模型最大值）。Claude 必填，不传会报错。这个差异容易让第一次切 Claude 的人懵--代码看着对，跑起来就 400。

何时该用 Claude？

不是无脑换，要根据任务选。几家经验性观察（会随模型更新变化）：

场景倾向理由
长文档分析（10万+ token） Claude 长上下文窗口大，且在长文上表现稳定
代码生成、代码理解 都行，Claude 略优 Claude 在代码任务上评测分数通常更高
工具调用密集的场景 都行 两家都支持原生 tool calling，Claude 的 input 直接是 dict 略方便
多语言（中文） 都行 两家中文都不错，Claude 语气更克制
成本敏感 看具体模型 Haiku 便宜，gpt-4o-mini 也便宜。要对比两家的小模型
需要 function calling 生态 OpenAI 略优 第三方工具、教程更多

别陷入「哪家更强」的争论。正确姿势是：用第 7 课的评测框架，针对你的具体任务跑同一套用例，对比两家的准确率、延迟、成本。数据说话比信仰靠谱。

动手实验

  1. 申请 Anthropic API Key（console.anthropic.com），把上面的 Claude 版 Agent 跑通。确认能查天气、能多步推理。
  2. 对比评测：用第 7 课的评测脚本，对同一套测试用例分别跑 OpenAI 和 Claude 版，对比工具选择准确率和回答平均分。你会第一次用数据回答「这家比那家好在哪」。
  3. 抽象 LLM 后端：把 WeatherAgent 改造成支持 backend="openai" 或 backend="claude"，构造时选择。这是个有价值的重构--让换厂商变成传个参数的事，而不是改一堆代码。
  4. 混合使用：进阶玩法--Agent 主循环用 Claude（长上下文、工具调用稳），但 LLM 裁判用 gpt-4o-mini（便宜）。这种「不同任务用不同模型」的混合策略在生产里很常见。

小测验

检查你的理解

从 OpenAI 切到 Claude 时，系统提示（system prompt）的处理有什么不同？

  • 没区别，都放在 messages 列表第一项
  • Claude 不支持系统提示，只能写在 user 消息里
  • Claude 的 system 是独立参数，不放进 messages；OpenAI 是 messages 里 role="system" 的项。好的设计是单独存 system_prompt，调用时按 SDK 拼接
  • Claude 的系统提示必须用英文

应用一下

你切到 Claude 后，Agent 跑起来报错 "max_tokens is required"。原因和解决？

  • Claude 模型坏了，等官方修复
  • Claude 的 API 必填 max_tokens 参数（OpenAI 是可选的）。在 messages.create() 里加上 max_tokens=1024（或适合你任务的值）即可
  • API Key 没权限，需要升级套餐
  • 网络问题，重试就行

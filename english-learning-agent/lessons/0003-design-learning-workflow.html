第 3 课 · English Learning Agent

设计学习工作流：从聊天机器人到 AI 老师

状态机 + 阶段化系统提示 + 进度 UI · 约 25 分钟 · 产出：AI 按教学流程引导，能切换学习阶段

本课目标

前两课做出来的东西，AI 虽然能读文章，但它只是个「能查文章的聊天机器人」——你问什么它答什么，没有教学节奏。今天我们要给它装上教学流程，让它知道「现在该预习词汇」「现在该练习」「现在该检验」，像真人老师一样引导你一步步学。

你将学会三件事：

  • 用 TypeScript 类型定义一个状态机（学习阶段 + 顺序 + 转移）
  • 把每个阶段的「教学要求」写成数据驱动的系统提示
  • 前端加进度条 + 阶段切换按钮，后端按阶段选提示

这是整个项目的架构转折点。前两课是「聊天机器人」，从今天起它变成「AI 老师」。核心思路：学习流程是 Workflow（路径固定），每个阶段内的对话是 Agent（自由发挥）——这正是你前一课 Lesson 13 学的 Workflow + Agent 混合模式。

关键决策：Workflow 还是 Agent？

你的需求是「预习 → 朗读 → 重点词汇 → 句子讲解 → 练习 → 检验」这套流程。问题是：这个流程的路径谁决定？

有两种极端做法：

方案谁决定路径问题
纯 Agent LLM 自己决定下一步学什么 LLM 可能跳过练习直接检验，或反复在预习阶段打转，教学节奏不可控
纯 Workflow 代码写死每一步 太死板，用户想多问几句词汇就卡住

正确做法是混合——你前一课 Lesson 13 学的判断：

路径可预测就用 Workflow，路径需要 LLM 灵活决定才用 Agent。

学习的大流程（先预习再练习再检验）是可预测的——这是教学法的共识，用 Workflow 固定住。但每个阶段内部的对话（用户问某个词什么意思、AI 怎么解释）是灵活的，交给 Agent 自由发挥。

落地成架构就是：状态机管阶段切换，LLM 管阶段内对话。

  ┌─────────┐   ┌─────────┐   ┌──────────┐   ┌──────────┐
  │ 词汇预习 │──>│  朗 读   │──>│ 重点词汇  │──>│ 句子讲解  │
  └─────────┘   └─────────┘   └──────────┘   └──────────┘
                                                    │
  ┌─────────┐   ┌─────────┐                        │
  │  检 验   │<─│  练 习   │<───────────────────────┘
  └─────────┘   └─────────┘

  大箭头 = Workflow（代码控制阶段切换）
  每个框内 = Agent（LLM 自由对话）

第一步：定义学习阶段状态机

新建文件 lib/learning-phases.ts。这是整个应用的「课程引擎」——所有教学逻辑都从这里来。

// lib/learning-phases.ts

// 1. 用联合类型定义所有学习阶段
// 这就是状态机的「状态集合」
export type Phase =
  | "preview"    // 词汇预习
  | "reading"    // 朗读
  | "keyVocab"   // 重点词汇
  | "sentence"   // 句子讲解
  | "practice"   // 练习
  | "test";      // 检验

// 2. 阶段的展示信息
export interface PhaseInfo {
  id: Phase;
  label: string;       // 中文显示名
  description: string; // 一句话说明这个阶段干什么
}

// 3. 阶段顺序——这就是状态机的「转移规则」
// 数组顺序 = 学习顺序，下一个阶段就是数组里后一个
export const PHASE_ORDER: Phase[] = [
  "preview",
  "reading",
  "keyVocab",
  "sentence",
  "practice",
  "test",
];

// 4. 每个阶段的展示信息（用 Record 类型保证完整）
export const PHASE_INFO: Record<Phase, PhaseInfo> = {
  preview: {
    id: "preview",
    label: "词汇预习",
    description: "先扫一遍生词，建立印象",
  },
  reading: {
    id: "reading",
    label: "朗读",
    description: "通读全文，把握大意",
  },
  keyVocab: {
    id: "keyVocab",
    label: "重点词汇",
    description: "深入讲解关键词的用法",
  },
  sentence: {
    id: "sentence",
    label: "句子讲解",
    description: "拆解长难句和语法点",
  },
  practice: {
    id: "practice",
    label: "练习",
    description: "用新词新句造句填空",
  },
  test: {
    id: "test",
    label: "检验",
    description: "综合测试，量化掌握程度",
  },
};

// 5. 获取下一个阶段
export function getNextPhase(current: Phase): Phase | null {
  const index = PHASE_ORDER.indexOf(current);
  if (index === -1 || index === PHASE_ORDER.length - 1) {
    return null; // 最后一个阶段，没有下一个
  }
  return PHASE_ORDER[index + 1];
}

// 6. 获取阶段序号（用于显示「第 2/6 阶段」）
export function getPhaseIndex(phase: Phase): number {
  return PHASE_ORDER.indexOf(phase) + 1;
}

export const TOTAL_PHASES = PHASE_ORDER.length;

逐段解读：

  1. type Phase = "preview" | "reading" | ... — TypeScript 的联合类型（union type），用 | 列出所有合法值。currentPhase 变量只能是这六个字符串之一，写错（比如 "revison"）TS 立刻报错。这比 Python 里用字符串硬编码安全得多——错误在编译期就被抓住。
  2. Record<Phase, PhaseInfo> — 「键为 Phase、值为 PhaseInfo 的对象」。关键是：如果你 PHASE_INFO 里漏了某个阶段，或者多了不存在的阶段，TS 编译就报错。这叫完整性检查——类型系统帮你保证状态机的每个状态都有对应配置。
  3. getNextPhase — 状态机的转移函数。当前阶段在数组里的位置 +1 就是下一个。null 表示到了终点（检验阶段之后没有了）。
  4. 为什么用数组而不是 if-else？ 因为阶段顺序是数据不是逻辑。想加个「复习」阶段？往数组里插一项就行，getNextPhase 自动适应。这就是数据驱动——把会变的东西（顺序、内容）和不变的东西（转移逻辑）分开。

对应前一课的概念：这里的 Phase 联合类型 = Python 里的 Enum；PHASE_ORDER 数组 + getNextPhase = 状态机。差别是 TypeScript 的联合类型在编译期就能抓住拼写错误，比 Python Enum 还严格。

第二步：给每个阶段写专属系统提示

继续在 lib/learning-phases.ts 末尾追加。每个阶段的提示告诉 AI：在这个阶段，你该干什么、不该干什么、怎么引导用户。

// 接 lib/learning-phases.ts 末尾

// 7. 每个阶段专属的系统提示模板
// {article} 会在后端替换成实际文章内容
export const PHASE_PROMPTS: Record<Phase, string> = {
  preview: `你正在带用户做【词汇预习】。
文章内容：
{article}

你的任务：
1. 从文章中挑出 8-15 个对中高级学习者可能较难的词
2. 每个词给出：英文单词、词性、中文释义、文章中的原句
3. 不要解释太深，这一步只是建立印象，重点是"先混个眼熟"
4. 列完后问用户："这些词里有哪个想先深入了解的吗？准备好了可以说'下一步'进入朗读。"
格式要简洁，用列表。`,

  reading: `你正在带用户做【朗读】环节。
文章内容：
{article}

你的任务：
1. 把文章分段（每段 2-4 句）展示给用户
2. 先让用户试着朗读第一段（用户可以打字说"我读完了"或提问）
3. 如果用户问某词发音，用类似 "schedule /ˈskedʒuːl/" 的格式给音标
4. 逐段推进，读完一段再展示下一段
5. 全部读完后说："朗读完成！可以说'下一步'进入重点词汇。"
注意：不要一次把全文都倒出来，要分段引导。`,

  keyVocab: `你正在带用户做【重点词汇】讲解。
文章内容：
{article}

你的任务：
1. 从文章里选 5-8 个最重要的词或短语（和预习阶段可重叠但更深入）
2. 每个词详细讲解：音标、词性、多个含义、常见搭配、一个文章外的例句
3. 讲完一个问用户"这个词清楚了吗？"再讲下一个
4. 全部讲完说："重点词汇学完了，可以说'下一步'进入句子讲解。"
要像老师讲解一样，有深度但不啰嗦。`,

  sentence: `你正在带用户做【句子讲解】。
文章内容：
{article}

你的任务：
1. 从文章中挑 3-5 个长难句或含重点语法的句子
2. 每个句子：先给出原句，再逐字逐句分析结构（主谓宾、从句、特殊语法）
3. 给出整句中文翻译
4. 如果句子里有词组搭配，点出来
5. 讲完说："句子讲解结束，可以说'下一步'进入练习。"
重点是"拆解"，让用户看懂句子是怎么组装的。`,

  practice: `你正在带用户做【练习】。
文章内容：
{article}

你的任务：
1. 基于文章里学过的新词、新句、新短语，出 5 道练习题
2. 题型混合：英译中、中译英、选词填空、用某词造句
3. 一次只出一道，等用户回答后再判断对错、给解释、出下一道
4. 答错了要指出错在哪、正确答案是什么
5. 5 道做完说："练习完成，可以说'下一步'进入检验环节。"
关键：一次一道，给即时反馈。不要一次把 5 道全列出来。`,

  test: `你正在带用户做【学习成果检验】。
文章内容：
{article}

你的任务：
1. 出 6 道综合测试题：2 道词汇题、2 道句子翻译、2 道理解题
2. 一次一道，等用户回答
3. 全部做完后，给一个评分（0-100）和分项反馈：
   - 词汇掌握：x/100
   - 句子理解：x/100
   - 整体建议：一句话总结该重点复习什么
4. 最后说："学习流程完成！可以导入新文章继续学习。"
这是总结性评价，要量化、要具体。`,
};

注意每个提示都遵循同一个模板结构：先说当前阶段是什么 → 列任务步骤 → 说明结束时的引导语。这种一致性让 AI 的行为可预测。

为什么把提示写成数据而不是写进后端代码？ 因为提示是教学内容，会经常调整（「词汇预习挑 10 个还是 15 个？」「练习出 5 道还是 8 道？」）。放在独立文件里，改教学逻辑不用动后端逻辑，职责清晰。后面第 4-7 课我们会逐个打磨这些提示。

第三步：后端按阶段选提示

修改 app/api/chat/route.ts——从 body 里多取一个 phase，用它选对应的系统提示：

// app/api/chat/route.ts
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from "ai";
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";
import { Phase, PHASE_PROMPTS } from "@/lib/learning-phases";

const ark = createOpenAICompatible({
  name: "ark",
  apiKey: process.env.ARK_API_KEY!,
  baseURL: "https://ark.cn-beijing.volces.com/api/v3",
});

export const maxDuration = 30;

export async function POST(req: Request) {
  // 同时取出对话、文章、当前阶段
  const {
    messages,
    articleText,
    phase,
  }: {
    messages: UIMessage[];
    articleText?: string;
    phase?: Phase;
  } = await req.json();

  // 没导入文章：兜底提示
  if (!articleText || !phase) {
    const result = streamText({
      model: ark(process.env.ARK_MODEL_ENDPOINT!),
      instructions: "你是一个友好的助手。请提醒用户先导入一篇文章。",
      messages: await convertToModelMessages(messages),
    });
    return createUIMessageStreamResponse({
      stream: toUIMessageStream({ stream: result.stream }),
    });
  }

  // 关键：用阶段对应的提示模板，替换 {article} 占位符
  const phasePrompt = PHASE_PROMPTS[phase];
  const instructions = phasePrompt.replace("{article}", articleText);

  const result = streamText({
    model: ark(process.env.ARK_MODEL_ENDPOINT!),
    instructions,
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}

关键改动：

  1. 多取一个 phase — 和 articleText 一样从 body 来。类型是 Phase，但标 optional（没导入文章时不存在）。
  2. PHASE_PROMPTS[phase] — 用阶段当 key 查提示模板。因为 PHASE_PROMPTS 是 Record<Phase, string>，TS 保证每个阶段都有对应提示，不会查到 undefined。这就是第一步用 Record 类型的回报。
  3. .replace("{article}", articleText) — 把模板里的 {article} 占位符替换成真实文章。这是最简单的模板引擎——一个 replace 就够，不用上 Handlebars。

第四步：前端加阶段状态和进度 UI

修改 app/page.tsx——加 currentPhase 状态、进度条、阶段切换按钮：

// app/page.tsx
'use client';

import { useChat } from "@ai-sdk/react";
import { useState, useRef } from "react";
import {
  Phase,
  PHASE_INFO,
  PHASE_ORDER,
  getNextPhase,
  getPhaseIndex,
  TOTAL_PHASES,
} from "@/lib/learning-phases";

export default function Chat() {
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState("");

  // 文章状态（第二课）
  const [articleText, setArticleText] = useState("");
  const [fileName, setFileName] = useState("");
  const [uploading, setUploading] = useState(false);
  const [uploadError, setUploadError] = useState("");

  // 新增：当前学习阶段
  const [currentPhase, setCurrentPhase] = useState<Phase>("preview");
  const fileInputRef = useRef<HTMLInputElement>(null);

  async function handleFileChange(e: React.ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    if (!file) return;
    setUploading(true);
    setUploadError("");
    try {
      const formData = new FormData();
      formData.append("file", file);
      const res = await fetch("/api/upload", { method: "POST", body: formData });
      const data = await res.json();
      if (!res.ok) throw new Error(data.error || "上传失败");
      setArticleText(data.text);
      setFileName(data.fileName);
      setCurrentPhase("preview"); // 导入新文章，从头开始
    } catch (err) {
      setUploadError(err instanceof Error ? err.message : "上传失败");
    } finally {
      setUploading(false);
    }
  }

  // 进入下一阶段
  function goToNextPhase() {
    const next = getNextPhase(currentPhase);
    if (next) setCurrentPhase(next);
  }

  // 有文章才能发消息，且每次带上 articleText 和 phase
  const canChat = articleText && status === "ready";

  return (
    <div className="flex flex-col w-full max-w-2xl py-8 mx-auto px-4">
      {/* 文件上传区 */}
      <div className="mb-4 p-4 border rounded-lg bg-gray-50">
        <input
          type="file"
          accept=".pdf,.txt,.md"
          onChange={handleFileChange}
          ref={fileInputRef}
          disabled={uploading}
          className="hidden"
        />
        <button
          type="button"
          onClick={() => fileInputRef.current?.click()}
          disabled={uploading}
          className="px-4 py-2 bg-teal-600 text-white rounded hover:bg-teal-700 disabled:opacity-50"
        >
          {uploading ? "提取中..." : "导入文章"}
        </button>
        {fileName && (
          <p className="mt-2 text-sm text-gray-600">
            已导入：{fileName}（{articleText.split(/\s+/).length} 词）
          </p>
        )}
        {uploadError && (
          <p className="mt-2 text-sm text-red-600">{uploadError}</p>
        )}
      </div>

      {/* 新增：学习进度条 */}
      {articleText && (
        <div className="mb-4 p-4 border rounded-lg">
          <div className="flex items-center justify-between mb-2">
            <span className="font-medium">
              第 {getPhaseIndex(currentPhase)}/{TOTAL_PHASES} 阶段：
              {PHASE_INFO[currentPhase].label}
            </span>
            {getNextPhase(currentPhase) && (
              <button
                type="button"
                onClick={goToNextPhase}
                className="text-sm px-3 py-1 bg-teal-100 text-teal-700 rounded hover:bg-teal-200"
              >
                进入「{PHASE_INFO[getNextPhase(currentPhase)!].label}」→
              </button>
            )}
          </div>
          <p className="text-sm text-gray-500 mb-2">
            {PHASE_INFO[currentPhase].description}
          </p>
          {/* 进度条 */}
          <div className="flex gap-1">
            {PHASE_ORDER.map((p) => (
              <div
                key={p}
                className={`flex-1 h-2 rounded ${
                  p === currentPhase
                    ? "bg-teal-600"
                    : PHASE_ORDER.indexOf(p) < PHASE_ORDER.indexOf(currentPhase)
                    ? "bg-teal-300"
                    : "bg-gray-200"
                }`}
              />
            ))}
          </div>
        </div>
      )}

      {/* 消息列表 */}
      <div className="flex-1 mb-4 min-h-[300px]">
        {messages.map((message) => (
          <div
            key={message.id}
            className={`mb-4 p-3 rounded-lg ${
              message.role === "user" ? "bg-teal-50 text-right" : "bg-gray-50"
            }`}
          >
            <strong>{message.role === "user" ? "我" : "AI"}</strong>
            <div className="whitespace-pre-wrap mt-1">
              {message.parts.map((part, i) =>
                part.type === "text" ? <span key={i}>{part.text}</span> : null
              )}
            </div>
          </div>
        ))}
      </div>

      {/* 输入框 */}
      <form
        onSubmit={(e) => {
          e.preventDefault();
          if (!input.trim() || !canChat) return;
          // 关键：同时传 articleText 和 currentPhase
          sendMessage(
            { text: input },
            { body: { articleText, phase: currentPhase } }
          );
          setInput("");
        }}
      >
        <div className="flex gap-2">
          <input
            value={input}
            onChange={(e) => setInput(e.target.value)}
            placeholder={
              articleText
                ? `当前：${PHASE_INFO[currentPhase].label}，说点什么...`
                : "先导入一篇文章吧"
            }
            disabled={!canChat}
            className="flex-1 border p-2 rounded"
          />
          <button
            type="submit"
            disabled={!canChat}
            className="px-4 bg-teal-600 text-white rounded disabled:opacity-50"
          >
            发送
          </button>
        </div>
      </form>
    </div>
  );
}

关键改动（相比第二课）：

  1. currentPhase 状态 — 默认 "preview"。导入新文章时重置回 "preview"（从头学）。这就是状态机的当前状态。
  2. 进度条 — 用 PHASE_ORDER.map 渲染 6 段彩条：当前阶段深色、已完成的浅色、未到的灰色。用户一眼看到「学到哪了」。
  3. 「进入下一阶段」按钮 — 调 getNextPhase 判断有没有下一阶段，有就显示按钮。点击调 goToNextPhase 切换状态。阶段切换由用户控制（点按钮），不是 AI 自动切——这保证教学节奏在人手里。
  4. 关键一行：sendMessage({{ text: input }}, {{ body: { articleText, phase: currentPhase } }}) — 现在每次发消息同时带上文章和阶段。后端用这两个字段组装正确的系统提示。

为什么阶段切换让用户点按钮，而不是让 AI 自动判断？ 因为「学完了没」是主观的——用户可能想多问几个词，AI 觉得「差不多了」就跳走会很烦。把控制权交给用户，符合「成人自主阅读」的教学定位（见 MISSION）。AI 在每个阶段末尾会提示「可以说'下一步'」，引导但不强求。

  2. 看到进度条显示「第 1/6 阶段：词汇预习」
  3. 发一句「开始」——AI 应该按词汇预习的要求列生词，而不是随便聊
  4. 点「进入朗读→」，再发「开始」——AI 行为变成分段引导朗读
  5. 再切到「练习」，发「开始」——AI 应该一次出一道题，等你回答

验证状态机生效：同样发「开始」两个字，在「词汇预习」阶段 AI 列生词，在「练习」阶段 AI 出题——说明 phase 真的传到了后端、影响了系统提示。这就是状态机的威力：同样的输入，不同状态下不同的行为。

理解：这是哪种架构？

对照你前一课 Lesson 13 的框架：

层谁控制本课实现
阶段切换（Workflow 层） 代码 + 用户 PHASE_ORDER 数组 + 用户点按钮 + setCurrentPhase
阶段内对话（Agent 层） LLM streamText + 阶段专属 instructions，AI 自由对话
状态传递 框架 body: { phase, articleText } → 后端选提示

这就是 Workflow + Agent 混合架构：大路径（6 个阶段的顺序）是 Workflow，固定可靠；每个阶段内部是 Agent，灵活自由。你前一课学的判断在这里落了地。

当前局限 & 后续课程

这个状态机还有几个问题，后面逐课解决：

  • 阶段提示是粗稿 — 词汇预习挑几个词、练习出几道题，都是拍脑袋的。后续课程逐个打磨。
  • 没记住学过什么 — 切到练习阶段，AI 不知道预习时讲了哪些词。第 14 课做学习状态持久化。
  • 阶段切换是手动的 — 用户得自己点按钮。其实可以让 AI 判断「这个阶段够了」然后建议切换。
  • 没限制 AI 越界 — AI 可能在词汇预习阶段就开始出题。更严格的做法是用结构化输出约束，第 6 课讲。

📋 需求变更预告（2026-08-01）：本课实现的 6 阶段线性状态机（preview → reading → keyVocab → sentence → practice → test）将在第 7 课重构为 6 个功能模块系统（词汇卡片轮播 → 播客 → 听力训练 → 单词测验 → 综合测验 → 学习进度），从线性流程改为推荐路径不强制。

哪些会保留：状态机思想（状态集合 + 转移规则）、TypeScript 联合类型 + Record 完整性检查、数据驱动设计（配置数据与逻辑分离）、Workflow + Agent 混合架构判断。
哪些会改：Phase 类型的具体值、PHASE_ORDER 的内容、PHASE_INFO / PHASE_PROMPTS 的配置、路由从 [phase] 改为 [feature]。

本课的概念教学完全有效——第 7 课的迁移本身就是一次重构实践，你会看到如何用状态机思想从一套状态迁移到另一套。

小测验

架构判断

为什么学习流程用 Workflow + Agent 混合，而不是纯 Agent？

  • 因为纯 Agent 太贵，混合能省钱
  • 大流程路径可预测用 Workflow 固定，阶段内对话灵活用 Agent
  • 因为 Workflow 比 Agent 更先进
  • 因为 Agent 不支持分阶段

类型系统的作用

用 Record<Phase, PhaseInfo> 定义 PHASE_INFO 有什么好处？

  • 运行速度比普通对象快
  • 可以自动生成文档
  • 保证每个阶段都有配置，漏了就编译报错
  • 让对象能被序列化成 JSON

状态机的本质

在词汇预习阶段发"开始"AI 列生词，在练习阶段发"开始"AI 出题——这体现了什么？

  • 同样输入不同状态下不同行为，这是状态机
  • AI 有记忆，记得之前在哪
  • 前端根据阶段改写了用户输入
  • 后端缓存了不同阶段的回答

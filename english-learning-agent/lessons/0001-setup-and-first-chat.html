第 1 课 · English Learning Agent

搭建项目，跑通第一个 AI 对话

Next.js + Vercel AI SDK + 火山方舟 · 约 20 分钟 · 产出：一个能和 AI 流式对话的网页

本课目标

今天我们要把一个能和 AI 对话的 Web 应用跑起来。这是整个项目的地基——后面的文件导入、学习流程、练习检验，全都长在这个地基上。

你将学会三件事：

  • 用 create-next-app 创建一个 Next.js 项目
  • 用 AI SDK 的 streamText（后端）+ useChat（前端）实现流式对话
  • 看懂 Next.js App Router 的目录结构——知道代码往哪里放

和前一课程的关系：你已经会用 Python + FastAPI 做 Agent 后端。今天换成 Next.js + AI SDK——概念完全对应（系统提示、消息历史、流式输出），只是语言和框架变了。这堂课不教 Agent 概念，只教「新工具怎么用」。

前置准备

在终端检查三样东西：

node -v       # 需要 v22+，没有就装 Node.js LTS
pnpm -v       # 没有就运行：npm install -g pnpm
echo $ARK_API_KEY  # 确认你有火山方舟的 API Key

关于火山方舟（Volcengine Ark）：字节跳动的豆包大模型云服务平台。它提供 OpenAI 兼容接口——API 协议和 OpenAI 一模一样，只是地址和模型名不同。这意味着社区里所有支持 OpenAI 的工具都能直接接，AI SDK 也不例外。

前置条件：在 火山方舟控制台开通服务，创建一个接入点（Endpoint），拿到两样东西：

  • API Key（ARK_API_KEY，形如 xxxx-xxxx-xxxx）
  • 接入点 ID（形如 ep-2025xxxxxxxx-xxxxx，在模型接入点详情页复制）

接入点 ID 就是调用时用的「模型名」。豆包常见模型有 doubao-1.5-pro-32k、doubao-1.5-lite-32k 等，但调用时传接入点 ID，不传模型名本身。

第一步：创建项目

pnpm create next-app@latest english-learning-agent

按提示选择（推荐选项已标注）：

提示选择
TypeScriptYes
ESLintYes
Tailwind CSSYes
App RouterYes
src/ directoryNo（直接用 app/ 更简洁）
Import aliasYes（默认 @/*）

进入项目，安装 AI SDK 的四个包：

cd english-learning-agent
pnpm add ai @ai-sdk/react @ai-sdk/openai-compatible zod

四个包各自的作用：

包作用
aiAI SDK 核心——streamText、tool、流转换函数
@ai-sdk/reactReact hook——useChat，管理聊天状态
@ai-sdk/openai-compatible通用 OpenAI 兼容提供方——火山方舟、DeepSeek、Moonshot 等都靠它接
zodSchema 验证——后面定义工具输入参数要用

为什么不直接用 @ai-sdk/openai？ 那个包是给官方 OpenAI 用的，base URL 写死了 api.openai.com。火山方舟虽然协议兼容，但地址不同（ark.cn-beijing.volces.com），所以要改用 openai-compatible 包，自己指定 base URL。这个包是「接任意 OpenAI 兼容服务」的万能钥匙。

第二步：看懂目录结构

创建完的项目长这样（只列关键文件）：

english-learning-agent/
├── app/
│   ├── layout.tsx      ← 全局布局（html、body 标签）
│   ├── page.tsx        ← 首页 ← 你将在这里写聊天 UI
│   ├── globals.css     ← 全局样式
│   └── api/            ← 后端 API 路由
│       └── chat/
│           └── route.ts  ← 你将在这里写 AI 接口
├── package.json
└── .env.local          ← 你将在这里放 API Key（git 会忽略）

Next.js App Router 的核心规则：文件路径 = URL 路径。

文件对应的 URL是什么
app/page.tsx/（首页）网页——用户看到的内容
app/api/chat/route.ts/api/chatAPI 接口——后端逻辑

还有一个关键概念：

'use client' 指令。 在文件第一行写 'use client'，表示这个组件在浏览器里运行（能用 useState、事件监听）。不写就是服务器组件，在服务器渲染，不能有交互状态。聊天界面需要用户输入，所以必须是 client component。

排坑：Google 字体下载失败

如果你跑 pnpm dev 时卡住，或者看到类似 Failed to download Geist font / fetch failed / ETIMEDOUT fonts.googleapis.com 的报错——别慌，几乎每个国内开发者都会遇到。

根因：Next.js 默认模板用 next/font/google 自动加载 Google 字体（Geist、Geist Mono）。这个机制在构建/启动时由 Node.js 去 fonts.googleapis.com 拉字体文件。而 Google 字体站在国内被墙，请求超时，于是卡死或报错。

打开 app/layout.tsx，你会看到罪魁祸首：

import { Geist, Geist_Mono } from "next/font/google";

const geistSans = Geist({
  variable: "--font-geist-sans",
  subsets: ["latin"],
});

有三种解法，按推荐程度排序：

方案 A：直接用系统字体（推荐，最快）

聊天界面根本不需要花哨字体。删掉 Google 字体，让浏览器用系统默认字体，一秒解决，零依赖，构建最快。

把 app/layout.tsx 改成：

import type { Metadata } from "next";
import "./globals.css";

export const metadata: Metadata = {
  title: "English Learning Agent",
  description: "AI 辅助英文文章学习",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="zh-CN">
      <body className="antialiased">{children}</body>
    </html>
  );
}

关键改动：

  • 删掉 import { Geist, Geist_Mono } from "next/font/google" 这一行
  • 删掉 geistSans、geistMono 两个变量
  • 删掉 <body> 上的 {`${geistSans.variable} ${geistMono.variable}`}

系统字体栈由 Tailwind 的 font-sans（或 antialiased 自带）负责，中文用苹方/微软雅黑，英文用系统默认无衬线，完全够用。

方案 B：换镜像源（保留 Google 字体）

如果你确实想用 Geist 字体，可以让 next/font 走国内镜像。在项目根目录创建 .npmrc：

# next/font 的 Google 字体走国内镜像
NEXT_FONT_GOOGLE_MIRROR_URL=https://fonts.googleapis.cn

或者设环境变量后启动：

NEXT_FONT_GOOGLE_MIRROR_URL=https://fonts.googleapis.cn pnpm dev

注：fonts.googleapis.cn 是 Google 官方在国内的镜像，稳定性时好时坏。如果还是失败，回到方案 A。

方案 C：下到本地自托管（最稳，但繁琐）

把字体文件下到 public/fonts/，用 next/font/local 加载。适合部署到生产环境、要保证字体永远可用的情况。本课先不用，等第 10 课部署时再处理。

建议：第一课直接用方案 A。我们的重点是跑通 AI 对话，字体不影响功能。等后面要打磨 UI 了再考虑字体优化。

改完 layout.tsx 后重新 pnpm dev，应该秒开。

第三步：配置 API Key 和接入点

在项目根目录创建 .env.local 文件：

# 火山方舟 API Key（在控制台「API Key 管理」里创建）
ARK_API_KEY=你的key

# 你创建的接入点 ID（在控制台「在线推理」→ 接入点详情页复制）
ARK_MODEL_ENDPOINT=ep-2025xxxxxxxx-xxxxx

.env.local 已被 .gitignore 忽略，不会泄露。Next.js 会自动读取这个文件里的环境变量。把接入点 ID 也放环境变量里，方便后面换模型时只改一处。

第四步：写后端 —— /api/chat 路由

把 app/api/chat/route.ts 的内容替换为：

import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

// 1. 创建火山方舟的模型提供方实例
const ark = createOpenAICompatible({
  name: 'ark',
  apiKey: process.env.ARK_API_KEY!,
  baseURL: 'https://ark.cn-beijing.volces.com/api/v3',
});

// 流式响应最多持续 30 秒（Vercel 部署时需要）
export const maxDuration = 30;

export async function POST(req: Request) {
  // 2. 从请求体取出对话历史
  const { messages }: { messages: UIMessage[] } = await req.json();

  // 3. 调用豆包模型，流式返回
  const result = streamText({
    // 接入点 ID 就是「模型名」
    model: ark(process.env.ARK_MODEL_ENDPOINT!),
    instructions: '你是一个友好的助手。',
    messages: await convertToModelMessages(messages),
  });

  // 4. 把模型流转换成 UI 消息流，返回给前端
  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}

逐行解读：

  1. createOpenAICompatible({...}) — 创建一个「模型提供方」实例。name 是标识符（随便起），apiKey 和 baseURL 指向火山方舟。这一步就是在告诉 AI SDK：「请求发到这个地址，用这个 Key 鉴权」。
  2. ark(process.env.ARK_MODEL_ENDPOINT!) — 用刚才创建的实例生成一个模型对象。参数是接入点 ID（不是模型名！）。! 是 TypeScript 的断言，告诉编译器「这个环境变量一定存在」。
  3. POST(req) — 导出一个叫 POST 的函数，Next.js 就自动把它绑定到 /api/chat 的 POST 请求。这对应 FastAPI 里的 @app.post("/api/chat")。
  4. messages — 前端发来的对话历史。和前一课的 messages 列表一模一样。
  5. streamText({ model, instructions, messages }) — AI SDK 的核心函数。instructions 就是系统提示（对应你前一课学的 system prompt）。
  6. convertToModelMessages — 前端发来的是 UI 格式消息（带 metadata），这个函数转成模型能理解的格式。
  7. toUIMessageStream + createUIMessageStreamResponse — 把模型的流式输出转成前端 useChat 能消费的 UI 消息流（SSE 格式）。

和前一课的对应关系：createOpenAICompatible = 你前一课配置 openai.Client 的 base_url 和 api_key；streamText = client.chat.completions.create(stream=True)；instructions = messages 列表里的 system 消息。概念完全对应，只是封装层级更高。

第五步：写前端 —— 聊天界面

把 app/page.tsx 的内容替换为：

'use client';

import { useChat } from '@ai-sdk/react';
import { useState } from 'react';

export default function Chat() {
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState('');

  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap mb-4">
          <strong>{message.role === 'user' ? '我' : 'AI'}</strong>
          {message.parts.map((part, i) =>
            part.type === 'text' ? <span key={i}>{part.text}</span> : null
          )}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          if (input.trim()) {
            sendMessage({ text: input });
            setInput('');
          }
        }}
      >
        <input
          value={input}
          onChange={e => setInput(e.target.value)}
          placeholder="说点什么..."
          disabled={status !== 'ready'}
          className="border p-2 rounded mr-2"
        />
        <button type="submit" disabled={status !== 'ready'}>
          发送
        </button>
      </form>
    </div>
  );
}

逐行解读：

  1. 'use client' — 这行必须有。因为用了 useState 和表单事件，这些只能在浏览器运行。
  2. useChat() — AI SDK 的核心 hook。一行代码搞定：管理消息列表、发送请求、接收流式回复、更新 UI。对应你前一课手写的 while True 循环 + 消息管理，这里全被封装了。
  3. messages — 当前所有消息（用户 + AI），每条有 role 和 parts。parts 是数组，因为一条消息可能包含文字、工具调用等多种内容。
  4. sendMessage({ text: input }) — 发送消息，触发 /api/chat 请求。
  5. status — 四种状态：'ready'（空闲）、'submitted'（已发送等响应）、'streaming'（正在接收）、'error'（出错）。用它控制按钮禁用。

理解数据流

把整个过程画出来就是：

  浏览器 (useChat)                      服务器 (/api/chat)
      │                                       │
      │   1. POST /api/chat { messages }      │
      │ ─────────────────────────────────────>│
      │                                       │  2. streamText() 调火山方舟
      │                                       │  ──────────────────>
      │                                       │  <──────────────────
      │   3. 流式 UI 消息 (SSE)               │  4. toUIMessageStream()
      │ <─────────────────────────────────────│
      │   5. messages 更新，UI 自动渲染        │
      │                                       │

和你前一课的 Agent 架构完全对应：后端的 streamText = client.chat.completions.create(stream=True)，前端的 useChat = 你手写的消息循环 + SSE 解析。AI SDK 把这些封装成了两个函数调用。

小测验

检查你的理解

app/api/chat/route.ts 里的 POST 函数处理的是什么？

  • 页面加载时自动执行的初始化代码
  • 发往 /api/chat 地址的 POST 请求
  • 所有 /api 路径下的全部请求
  • 数据库的写入操作

应用一下

为什么 app/page.tsx 顶部必须写 'use client'？

  • 为了让页面加载速度更快
  • 为了让搜索引擎能索引这个页面
  • 因为用了 useState 和事件处理，只能在浏览器运行
  • 这是所有 Next.js 页面的强制要求

导入文件，让 AI 读懂你的文章

文件上传 + PDF 文本提取 + 文档注入系统提示 · 约 25 分钟 · 产出：上传 PDF/TXT 后能针对文章内容对话

本课目标

上一课我们跑通了一个通用聊天界面，但 AI 还「不知道」你要学什么文章。今天我们要让它读懂你导入的文章——上传 PDF 或 TXT，提取出文字，然后让 AI 基于文章内容跟你对话。

你将学会三件事：

  • 用 Next.js Route Handler 接收前端上传的文件（FormData）
  • 用 pdfjs-dist 从 PDF 提取纯文本
  • 把文章内容注入 AI 的系统提示，让对话带上下文

本课的架构决策：文章文本不存数据库，而是提取后存在前端状态里，每次发消息时随请求发给后端。这是 MVP（最小可用版本）的最简做法。等到第 8 课做学习状态管理时，我们再把它持久化。

整体流程

  用户选文件 ──> 前端 fetch /api/upload ──> 后端提取文本
                                              │
                                              └─> 返回纯文本给前端
                                                     │
  前端存到 articleText 状态 <─────────────────────────┘
       │
  用户发消息 ──> useChat 的 body 带上 articleText ──> /api/chat
                                                        │
                                      注入到 instructions（系统提示）
                                                        │
                                                  AI 带着文章上下文回复

两个 API：/api/upload（提取文本）+ /api/chat（对话，上一课已有，今天改造）。注意分工——文本提取是一次性的重活，对话是高频的轻活，分开两个接口更清晰。

第一步：安装依赖

pnpm add pdfjs-dist

为什么选 pdfjs-dist 而不是 pdf-parse？

库优点缺点
pdfjs-dist Mozilla 官方维护，解析能力最强，支持复杂排版 API 稍繁琐，要配 worker
pdf-parse API 极简，一行代码出文本 长期不维护，对扫描件/复杂 PDF 提取率低，Node 22 有兼容问题

本课程选 pdfjs-dist——它靠谱，且学会一次到处能用（浏览器预览也用它）。

第二步：写文本提取工具函数

新建文件 lib/extract-text.ts（没有 lib/ 目录就新建一个）：

// lib/extract-text.ts
import { TextItem } from "pdfjs-dist/types/src/display/api";

// 动态导入，避免 pdfjs-dist 的 worker 在构建时报错
async function getPdfjs() {
  const pdfjs = await import("pdfjs-dist/legacy/build/pdf.mjs");
  return pdfjs;
}

/**
 * 从 PDF 文件提取纯文本
 */
export async function extractTextFromPDF(file: File): Promise<string> {
  const pdfjs = await getPdfjs();

  // 关掉 worker，用主线程跑（服务端环境最省事）
  pdfjs.GlobalWorkerOptions.workerSrc = "";

  const arrayBuffer = await file.arrayBuffer();
  const pdf = await pdfjs.getDocument({ data: arrayBuffer }).promise;

  const pages: string[] = [];
  for (let i = 1; i <= pdf.numPages; i++) {
    const page = await pdf.getPage(i);
    const content = await page.getTextContent();
    const text = content.items
      .filter((item): item is TextItem => item.str !== undefined)
      .map((item) => item.str)
      .join(" ");
    pages.push(text);
  }

  return pages.join("\n\n");
}

/**
 * 从纯文本文件读取内容（.txt / .md）
 */
export async function extractTextFromTextFile(file: File): Promise<string> {
  return await file.text();
}

/**
 * 根据文件类型自动选择提取方式
 */
export async function extractText(file: File): Promise<string> {
  const name = file.name.toLowerCase();

  if (name.endsWith(".pdf")) {
    return extractTextFromPDF(file);
  }
  if (name.endsWith(".txt") || name.endsWith(".md")) {
    return extractTextFromTextFile(file);
  }

  throw new Error(`不支持的文件类型：${file.name}（目前支持 .pdf / .txt / .md）`);
}

逐段解读：

  1. import("pdfjs-dist/legacy/build/pdf.mjs") — 用动态导入而不是顶部 import。因为 pdfjs-dist 会访问浏览器 window 对象，如果在模块顶层导入，Next.js 构建时会报错。动态导入保证它只在运行时、服务端加载。
  2. /legacy/build/ — 用旧版构建入口。它不依赖现代浏览器 API，在 Node.js 服务端跑得最稳。新版入口是给浏览器用的。
  3. workerSrc = "" — PDF.js 默认用 Web Worker 并行解析，但服务端没有 Worker。设空字符串让它在主线程同步跑。MVP 阶段文本提取不频繁，主线程跑完全够。
  4. file.arrayBuffer() — 把 File 对象转成二进制缓冲区，PDF.js 需要这个格式。
  5. getTextContent() — 提取一页里所有文字片段（items），每个 item.str 是一小段文字，用空格拼起来就是整页文本。
  6. extractText 统一入口 — 根据后缀名分发到不同提取函数。后面要加 Word、EPUB 时，只需在这里加分支。

这里有个 TypeScript 技巧值得记住：filter((item): item is TextItem => ...) 叫类型谓词（type predicate）。content.items 里既有 TextItem（有 str）也有 TextMarkedContent（没 str）。普通 filter 过滤后类型不变，TS 不知道 item.str 存在；用类型谓词告诉 TS「过滤后都是 TextItem」，后面就能安全访问 item.str。

第三步：写上传接口 /api/upload

新建文件 app/api/upload/route.ts：

// app/api/upload/route.ts
import { NextResponse } from "next/server";
import { extractText } from "@/lib/extract-text";

export const maxDuration = 60; // PDF 提取可能较慢

export async function POST(req: Request) {
  try {
    const formData = await req.formData();
    const file = formData.get("file") as File | null;

    if (!file) {
      return NextResponse.json(
        { error: "没有收到文件" },
        { status: 400 }
      );
    }

    // 限制文件大小 10MB（防止超大文件拖垮服务）
    if (file.size > 10 * 1024 * 1024) {
      return NextResponse.json(
        { error: "文件不能超过 10MB" },
        { status: 413 }
      );
    }

    const text = await extractText(file);

    if (!text.trim()) {
      return NextResponse.json(
        { error: "提取不到文字——可能是扫描件（图片版 PDF），本课程暂不支持 OCR" },
        { status: 422 }
      );
    }

    return NextResponse.json({
      text,
      fileName: file.name,
      wordCount: text.split(/\s+/).length,
    });
  } catch (err) {
    const message = err instanceof Error ? err.message : "未知错误";
    return NextResponse.json({ error: message }, { status: 500 });
  }
}

逐段解读：

  1. req.formData() — Next.js Route Handler 原生支持解析 multipart/form-data。前端用 FormData 发文件，这里一行就能取出来。对应你前一课 FastAPI 里的 UploadFile。
  2. formData.get("file") — "file" 是前端 formData.append("file", file) 时用的 key，两边要对上。
  3. 文件大小限制 — 10MB 是个合理上限。学术论文一般 2-5MB，超了多半是图片太多，文本提取也没意义。
  4. 扫描件检测 — 如果 PDF 是扫描的图片（不是文字版），getTextContent 返回空。这时给用户明确提示，而不是返回空字符串让 AI 一脸懵。
  5. wordCount — 顺便返回字数，前端显示给用户看，建立对文章规模的感知。

第四步：改造聊天界面，加上文件上传

把 app/page.tsx 整体替换为：

// app/page.tsx
'use client';

import { useChat } from "@ai-sdk/react";
import { useState, useRef } from "react";

export default function Chat() {
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState("");

  // 新增：文章相关状态
  const [articleText, setArticleText] = useState("");
  const [fileName, setFileName] = useState("");
  const [uploading, setUploading] = useState(false);
  const [uploadError, setUploadError] = useState("");
  const fileInputRef = useRef<HTMLInputElement>(null);

  // 处理文件上传
  async function handleFileChange(e: React.ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    if (!file) return;

    setUploading(true);
    setUploadError("");

    try {
      const formData = new FormData();
      formData.append("file", file);

      const res = await fetch("/api/upload", {
        method: "POST",
        body: formData,
      });
      const data = await res.json();

      if (!res.ok) {
        throw new Error(data.error || "上传失败");
      }

      setArticleText(data.text);
      setFileName(data.fileName);
    } catch (err) {
      setUploadError(err instanceof Error ? err.message : "上传失败");
    } finally {
      setUploading(false);
    }
  }

  return (
    <div className="flex flex-col w-full max-w-2xl py-8 mx-auto px-4">
      {/* 文件上传区 */}
      <div className="mb-6 p-4 border rounded-lg bg-gray-50">
        <input
          type="file"
          accept=".pdf,.txt,.md"
          onChange={handleFileChange}
          ref={fileInputRef}
          disabled={uploading}
          className="hidden"
        />
        <button
          type="button"
          onClick={() => fileInputRef.current?.click()}
          disabled={uploading}
          className="px-4 py-2 bg-teal-600 text-white rounded hover:bg-teal-700 disabled:opacity-50"
        >
          {uploading ? "提取中..." : "导入文章"}
        </button>

        {fileName && (
          <p className="mt-2 text-sm text-gray-600">
            已导入：{fileName}（{articleText.split(/\s+/).length} 词）
          </p>
        )}
        {uploadError && (
          <p className="mt-2 text-sm text-red-600">{uploadError}</p>
        )}
      </div>

      {/* 消息列表 */}
      <div className="flex-1 mb-4">
        {messages.map((message) => (
          <div
            key={message.id}
            className={`mb-4 p-3 rounded-lg ${
              message.role === "user"
                ? "bg-teal-50 text-right"
                : "bg-gray-50"
            }`}
          >
            <strong>{message.role === "user" ? "我" : "AI"}</strong>
            <div className="whitespace-pre-wrap mt-1">
              {message.parts.map((part, i) =>
                part.type === "text" ? <span key={i}>{part.text}</span> : null
              )}
            </div>
          </div>
        ))}
      </div>

      {/* 输入框 */}
      <form
        onSubmit={(e) => {
          e.preventDefault();
          if (!input.trim() || status !== "ready") return;
          // 关键：把 articleText 作为 body 一起发给后端
          sendMessage(
            { text: input },
            { body: { articleText } }
          );
          setInput("");
        }}
      >
        <div className="flex gap-2">
          <input
            value={input}
            onChange={(e) => setInput(e.target.value)}
            placeholder={
              articleText ? "问问关于这篇文章的问题..." : "先导入一篇文章吧"
            }
            disabled={status !== "ready"}
            className="flex-1 border p-2 rounded"
          />
          <button
            type="submit"
            disabled={status !== "ready"}
            className="px-4 bg-teal-600 text-white rounded disabled:opacity-50"
          >
            发送
          </button>
        </div>
      </form>
    </div>
  );
}

关键改动（相比第一课）：

  1. articleText 状态 — 上传成功后把提取的文本存在这里。这是整个应用的核心数据——后面所有课程都围绕它。
  2. handleFileChange — 选了文件后立刻上传到 /api/upload，拿到纯文本存进状态。注意是立刻上传，不是等发消息时才传——这样用户能马上看到「已导入 xxx 词」的反馈。
  3. 隐藏的 <input type="file"> — 原生文件输入框很丑。用一个 useRef 引用它，点按钮时 ref.current?.click() 触发选择。这是 React 里自定义文件上传按钮的标准做法。
  4. 关键一行：sendMessage({{ text: input }}, {{ body: { articleText } }}) — sendMessage 的第二个参数是请求级配置，body 里的字段会随请求一起发给后端。这样每次发消息都把文章内容带上。

为什么不把文章塞进 messages？ 因为文章不是「对话」的一部分——它是背景知识。塞进 messages 会让对话历史臃肿，且每轮都要重复传。放在 body 里、后端注入 instructions，更符合语义——这对应你前一课学的「系统提示存系统提示，对话存对话」的原则。

第五步：改造 /api/chat，注入文章上下文

修改 app/api/chat/route.ts：

// app/api/chat/route.ts
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from "ai";
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";

const ark = createOpenAICompatible({
  name: "ark",
  apiKey: process.env.ARK_API_KEY!,
  baseURL: "https://ark.cn-beijing.volces.com/api/v3",
});

export const maxDuration = 30;

export async function POST(req: Request) {
  // 关键改动：从 body 里同时取出 messages 和 articleText
  const {
    messages,
    articleText,
  }: { messages: UIMessage[]; articleText?: string } = await req.json();

  // 根据是否有文章，动态构建系统提示
  const instructions = articleText
    ? `你是一个英文阅读辅助助手。用户正在学习以下英文文章，请基于文章内容回答问题、解释词汇、分析句子。

=== 文章内容 ===
${articleText}
=== 文章内容结束 ===

要求：
- 用中文回答，除非用户要求英文
- 解释词汇时给出音标、词性、例句
- 回答要紧扣文章内容，不要泛泛而谈`
    : "你是一个友好的助手。请提醒用户先导入一篇文章。";

  const result = streamText({
    model: ark(process.env.ARK_MODEL_ENDPOINT!),
    instructions,
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}

关键改动：

  1. articleText 从 body 解构出来 — 第一课的 POST 只取 messages，现在多了 articleText。它是 optional（?），因为没导入文章时这个字段不存在。
  2. 动态 instructions — 有文章时，系统提示里嵌入文章全文 + 教学要求；没文章时，给个兜底提示。这就是上下文注入——对应你前一课学的「把外部知识塞进 system prompt」。
  3. 文章直接拼进字符串 — MVP 阶段文章不超几千词，直接拼进 instructions 最简单。等文章超长（万字以上）时，第 8 课会换成 RAG 检索。

常见问题排坑

报错：Cannot find module 'pdfjs-dist/legacy/build/pdf.mjs'

版本问题。检查 package.json 里 pdfjs-dist 的版本。如果是 4.x，路径是 pdfjs-dist/legacy/build/pdf.mjs；如果是 3.x，路径是 pdfjs-dist/legacy/build/pdf.js。建议用 4.x：pnpm add pdfjs-dist@4。

报错：window is not defined / document is not defined

说明 pdfjs-dist 在服务端加载了浏览器入口。确认你导入的是 pdfjs-dist/legacy/build/pdf.mjs（带 /legacy/build/），不是 pdfjs-dist。

上传后提取的文字是乱码或为空

两种可能：

  • 扫描件 PDF（图片版）：里面没有文字层，提取不到。需要 OCR（如 Tesseract），本课暂不支持。
  • 编码问题：TXT 文件如果不是 UTF-8 编码，file.text() 可能乱码。可以用 iconv-lite 转码，但先确保文件存为 UTF-8。

小测验

检查你的理解

前端上传文件时，fetch 的 body 应该传什么？

  • 文件的 Base64 字符串
  • JSON 字符串，包含文件内容
  • FormData 对象，用 append 加上文件
  • 文件的 ArrayBuffer

架构决策

为什么把文章内容放在 sendMessage 的 body 里，而不是塞进 messages 列表？

  • 因为 messages 有长度限制，body 没有
  • 因为文章是背景知识不是对话，放 body 注入系统提示更符合语义
  • 因为 body 加密传输更安全
  • 因为 messages 只能放用户消息，放不了文章

排坑理解

为什么 pdfjs-dist 要用动态 import() 而不是顶部 import？

  • 因为它访问浏览器全局对象，顶层导入会在构建时报错
  • 因为动态导入比静态导入更快
  • 因为 TypeScript 不认识它的类型
  • 因为减少打包体积

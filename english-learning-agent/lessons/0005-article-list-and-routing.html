文章列表与多页学习路由

Next.js 动态路由 + localStorage 持久化 + 自定义 Hook · 约 35 分钟 · 产出：首页文章卡片列表，点击阶段进入独立学习页

本课目标

前四课我们做的是单页应用——一个页面装下所有东西，刷新就丢。今天要把它改造成多页应用：首页是文章卡片列表，点某个学习阶段进入独立的学习页面，文章和进度存在 localStorage 里刷新不丢。

你将学会四件事：

  • Next.js 动态路由：用 [id]、[phase] 文件夹做 URL 参数
  • localStorage 持久化：文章列表和学习进度存浏览器，刷新不丢
  • 自定义 Hook：把状态逻辑封装成 useArticles()，组件更干净
  • 用 Link 组件做页面跳转，理解客户端导航

第一步：定义数据模型

先想清楚存什么。每篇文章需要：唯一 ID、文件名、正文、字数、导入时间、每个阶段的状态。

在 lib/learning-phases.ts 末尾追加：

// lib/learning-phases.ts 末尾追加

// 每个阶段的学习状态
export type PhaseStatus = "notStarted" | "inProgress" | "completed";

// 一篇学习中的文章
export interface Article {
  id: string;                        // 唯一 ID
  fileName: string;                  // 文件名
  text: string;                      // 文章正文
  wordCount: number;                 // 字数
  importedAt: number;                // 导入时间戳（毫秒）
  phaseStatus: Record<Phase, PhaseStatus>; // 6 个阶段各自的状态
}

// 创建新文章时的默认状态：全部 notStarted
export function createDefaultPhaseStatus(): Record<Phase, PhaseStatus> {
  const status = {} as Record<Phase, PhaseStatus>;
  for (const p of PHASE_ORDER) {
    status[p] = "notStarted";
  }
  return status;
}

// 计算完成进度（0-100）
export function getProgress(article: Article): number {
  const completed = PHASE_ORDER.filter(
    (p) => article.phaseStatus[p] === "completed"
  ).length;
  return Math.round((completed / TOTAL_PHASES) * 100);
}

逐段解读：

  1. PhaseStatus — 三态：未开始、进行中、已完成。比布尔值多一个「进行中」，因为用户可能学到一半退出。
  2. Article 接口 — 数据模型。注意 phaseStatus 用 Record<Phase, PhaseStatus>，保证 6 个阶段都有状态字段（漏了 TS 报错，和第三课的 PHASE_INFO 同理）。
  3. createDefaultPhaseStatus — 工厂函数，新建文章时调它生成全 notStarted 的状态。{} as Record<Phase, PhaseStatus> 先建空对象再填充——这是 TS 里初始化 Record 的常见写法。
  4. getProgress — 数已完成的阶段数 ÷ 总阶段数。用于卡片上显示百分比。

第二步：封装 localStorage

localStorage 是浏览器的键值存储，刷新不丢。但它有几个坑：只能存字符串、SSR 时不存在、读写要 try-catch。封装一层避免重复踩坑。

新建 lib/storage.ts：

// lib/storage.ts
import { Article } from "./learning-phases";

const STORAGE_KEY = "ela-articles"; // ela = English Learning Agent

// 读取所有文章
export function loadArticles(): Article[] {
  if (typeof window === "undefined") return []; // SSR 保护
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    return raw ? JSON.parse(raw) : [];
  } catch {
    return []; // JSON 损坏就当没有
  }
}

// 保存所有文章
export function saveArticles(articles: Article[]): void {
  if (typeof window === "undefined") return; // SSR 保护
  try {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(articles));
  } catch {
    // 存储满了或被禁用，静默失败（自己用不至于）
  }
}

// 生成唯一 ID（不用装 uuid 库，这样够用）
export function generateId(): string {
  return `${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
}

逐段解读：

  1. typeof window === "undefined" — 最关键的一行。Next.js 服务端渲染时 window 不存在，直接访问 localStorage 会报错。这个判断确保只在浏览器里执行。localStorage 相关代码必须有这个保护。
  2. JSON.parse / JSON.stringify — localStorage 只能存字符串，对象要序列化。读取时反序列化回来。
  3. try-catch — localStorage 可能被禁用（隐私模式）、可能存满、JSON 可能损坏。包一层 try-catch 保证不崩。
  4. generateId — 时间戳 + 随机串，足够唯一。不必为这点事装 uuid 库。

为什么不用 useEffect 里直接写 localStorage？ 因为多个组件都要读写文章数据（首页列表、学习页更新进度）。如果每个组件自己读写，逻辑分散还容易不同步。下一步我们封装成 Hook，统一管理。

第三步：封装 useArticles Hook

自定义 Hook 是 React 复用逻辑的方式。我们把「文章列表的增删查改 + localStorage 同步」封装成 useArticles()，任何组件调它就能拿到文章数据和操作方法。

新建 hooks/use-articles.ts：

// hooks/use-articles.ts
"use client";

import { useState, useEffect, useCallback } from "react";
import { Article, Phase, PhaseStatus, createDefaultPhaseStatus } from "@/lib/learning-phases";
import { loadArticles, saveArticles, generateId } from "@/lib/storage";

export function useArticles() {
  const [articles, setArticles] = useState<Article[]>([]);
  const [loaded, setLoaded] = useState(false); // 是否已从 localStorage 读取

  // 首次挂载：从 localStorage 读取
  useEffect(() => {
    setArticles(loadArticles());
    setLoaded(true);
  }, []);

  // articles 变化就保存（注意跳过首次加载前）
  useEffect(() => {
    if (loaded) saveArticles(articles);
  }, [articles, loaded]);

  // 添加文章
  const addArticle = useCallback(
    (fileName: string, text: string): Article => {
      const article: Article = {
        id: generateId(),
        fileName,
        text,
        wordCount: text.split(/\s+/).length,
        importedAt: Date.now(),
        phaseStatus: createDefaultPhaseStatus(),
      };
      setArticles((prev) => [article, ...prev]); // 新的排前面
      return article;
    },
    []
  );

  // 删除文章
  const removeArticle = useCallback((id: string) => {
    setArticles((prev) => prev.filter((a) => a.id !== id));
  }, []);

  // 更新某个阶段的状态
  const updatePhaseStatus = useCallback(
    (id: string, phase: Phase, status: PhaseStatus) => {
      setArticles((prev) =>
        prev.map((a) =>
          a.id === id
            ? { ...a, phaseStatus: { ...a.phaseStatus, [phase]: status } }
            : a
        )
      );
    },
    []
  );

  // 按 ID 查单篇
  const getArticle = useCallback(
    (id: string) => articles.find((a) => a.id === id),
    [articles]
  );

  return {
    articles,
    loaded,
    addArticle,
    removeArticle,
    updatePhaseStatus,
    getArticle,
  };
}

逐段解读：

  1. 两个 useEffect — 第一个在挂载时从 localStorage 读数据（只跑一次）；第二个在 articles 变化时写回。loaded 标志确保不会把空数组写回去覆盖已有数据——首次渲染时 articles 是空数组，如果直接存会清空 localStorage。
  2. useCallback — 缓存函数引用。不包的话每次渲染都创建新函数，用到这些函数的子组件会无意义重渲染。这是 React 性能优化的基本操作。
  3. setArticles((prev) => ...) — 用函数形式更新状态，而不是 setArticles([...articles, newOne])。因为 articles 可能是闭包里的旧值，函数形式拿到的 prev 永远是最新的。这是 React 状态更新的安全写法。
  4. { ...a, phaseStatus: { ...a.phaseStatus, [phase]: status } } — 不可变更新：展开旧对象，只改一个字段。React 靠引用变化判断是否重渲染，直接改 a.phaseStatus[phase] = status 不会触发更新。

自定义 Hook 的本质：它就是一个函数，内部用了 React 的 hook（useState/useEffect 等）。函数名必须以 use 开头（React 靠这个判断它是 Hook）。useArticles() 把文章管理的所有逻辑收拢，组件只需调一行 const { articles, addArticle } = useArticles() 就能拿到数据和操作。对应你前一课学过的「工具函数封装」，只是这里封装的是带状态的逻辑。

第四步：写文章卡片组件

新建 components/article-card.tsx——首页列表里的一张卡片：

// components/article-card.tsx
import Link from "next/link";
import { Card } from "@/components/ui/card";
import { Button } from "@/components/ui/button";
import { Article, Phase, PHASE_INFO, PHASE_ORDER, getProgress } from "@/lib/learning-phases";
import { cn } from "@/lib/utils";
import { Trash2 } from "lucide-react";

interface Props {
  article: Article;
  onDelete: (id: string) => void;
}

export function ArticleCard({ article, onDelete }: Props) {
  const progress = getProgress(article);

  // 状态对应的颜色
  const statusColor: Record<string, string> = {
    notStarted: "bg-border",
    inProgress: "bg-primary",
    completed: "bg-primary/40",
  };

  return (
    <Card className="p-4">
      {/* 文件信息 */}
      <div className="flex items-start justify-between mb-3">
        <div>
          <h3 className="font-medium">{article.fileName}</h3>
          <p className="text-sm text-muted-foreground">
            {article.wordCount} 词 · {formatTime(article.importedAt)}
          </p>
        </div>
        <Button
          variant="ghost"
          size="icon"
          onClick={() => onDelete(article.id)}
        >
          <Trash2 className="w-4 h-4 text-muted-foreground" />
        </Button>
      </div>

      {/* 6 个阶段按钮 */}
      <div className="grid grid-cols-3 gap-2 mb-3">
        {PHASE_ORDER.map((phase) => {
          const status = article.phaseStatus[phase];
          return (
            <Link
              key={phase}
              href={`/articles/${article.id}/${phase}`}
            >
              <Button
                variant="outline"
                size="sm"
                className={cn(
                  "w-full justify-start",
                  status === "completed" && "border-primary text-primary"
                )}
              >
                <span className={cn("w-2 h-2 rounded-full mr-2", statusColor[status])} />
                {PHASE_INFO[phase].label}
              </Button>
            </Link>
          );
        })}
      </div>

      {/* 进度条 */}
      <div className="flex items-center gap-2">
        <div className="flex-1 h-2 bg-border rounded-full overflow-hidden">
          <div
            className="h-full bg-primary transition-all"
            style={{ width: `${progress}%` }}
          />
        </div>
        <span className="text-sm text-muted-foreground">{progress}%</span>
      </div>
    </Card>
  );
}

// 相对时间格式化
function formatTime(timestamp: number): string {
  const diff = Date.now() - timestamp;
  const hours = Math.floor(diff / (1000 * 60 * 60));
  if (hours < 1) return "刚刚";
  if (hours < 24) return `${hours} 小时前`;
  const days = Math.floor(hours / 24);
  return `${days} 天前`;
}

关键点：

  1. <Link href={...}> — Next.js 的客户端导航组件。点击后不刷新整页，而是只更新变化的部分，跳转更快且保留状态。对应传统 HTML 的 <a> 标签，但体验好得多。永远用 Link 而不是 <a> 做内部跳转。
  2. href={`/articles/${article.id}/${phase}`} — 动态 URL。比如 /articles/12345-abc/preview。Next.js 会把这个 URL 匹配到 app/articles/[id]/[phase]/page.tsx（下一步写）。
  3. 状态小圆点 — 每个阶段按钮前有个圆点：灰=未开始、青=进行中、浅青=已完成。一眼看出进度。
  4. variant="ghost" size="icon" — 删除按钮用幽灵样式（无背景）+ 图标尺寸，低调不抢视觉。

第五步：写首页 —— 文章列表

import { useState } from "react";
import { useArticles } from "@/hooks/use-articles";

关键点：

  1. showImport 状态 — 点「导入文章」按钮才显示 FileImporter，导入完自动收起。比一直挂着更干净。
  2. 空状态 — 没文章时显示引导文案。别小看这个，空状态体验差用户不知道该干嘛。
  3. loaded 守卫 — localStorage 读取是异步的（在 useEffect 里）。loaded 为 false 时不渲染列表，避免闪烁（先显示空再跳出来）。

第六步：写学习页 —— 动态路由

这是本课的核心。新建 app/articles/[id]/[phase]/page.tsx：

// app/articles/[id]/[phase]/page.tsx
"use client";

import { use } from "react";
import { useRouter } from "next/navigation";
import Link from "next/link";
import { useChat } from "@ai-sdk/react";
import { useState, useEffect } from "react";
import { useArticles } from "@/hooks/use-articles";
import {
  Phase,
  PHASE_INFO,
  PHASE_ORDER,
  getNextPhase,
  getPhaseIndex,
  TOTAL_PHASES,
} from "@/lib/learning-phases";
import { MessageBubble } from "@/components/message-bubble";
import { Button } from "@/components/ui/button";
import { ScrollArea } from "@/components/ui/scroll-area";
import { ArrowLeft, ChevronRight } from "lucide-react";

// 校验 URL 里的 phase 是否合法
function isValidPhase(p: string): p is Phase {
  return PHASE_ORDER.includes(p as Phase);
}

export default function LearnPage({
  params,
}: {
  params: Promise<{ id: string; phase: string }>;
}) {
  // Next.js 15+ 的 params 是 Promise，要用 use() 解包
  const { id, phase } = use(params);
  const router = useRouter();
  const { getArticle, updatePhaseStatus } = useArticles();
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState("");

  // 参数不合法 → 回首页
  if (!isValidPhase(phase)) {
    router.push("/");
    return null;
  }

  const currentPhase = phase as Phase;
  const article = getArticle(id);

  // 文章不存在 → 回首页
  useEffect(() => {
    if (!article) router.push("/");
  }, [article, router]);

  if (!article) return null;

  const nextPhase = getNextPhase(currentPhase);

  // 进入页面时标记为「进行中」
  useEffect(() => {
    if (article.phaseStatus[currentPhase] === "notStarted") {
      updatePhaseStatus(id, currentPhase, "inProgress");
    }
  }, [id, currentPhase, article.phaseStatus, updatePhaseStatus]);

  function handleSend(e: React.FormEvent) {
    e.preventDefault();
    if (!input.trim() || status !== "ready") return;
    sendMessage(
      { text: input },
      { body: { articleText: article.text, phase: currentPhase } }
    );
    setInput("");
  }

  // 进入下一阶段
  function goNext() {
    updatePhaseStatus(id, currentPhase, "completed");
    if (nextPhase) {
      router.push(`/articles/${id}/${nextPhase}`);
    }
  }

  return (
    <div className="flex flex-col h-screen max-w-2xl mx-auto px-4 py-4">
      {/* 顶部导航 */}
      <div className="flex items-center gap-3 mb-4 pb-3 border-b">
        <Link href="/">
          <Button variant="ghost" size="icon">
            <ArrowLeft className="w-4 h-4" />
          </Button>
        </Link>
        <div className="flex-1">
          <h2 className="font-medium">
            {PHASE_INFO[currentPhase].label}
            <span className="text-muted-foreground font-normal ml-2">
              {getPhaseIndex(currentPhase)}/{TOTAL_PHASES}
            </span>
          </h2>
          <p className="text-xs text-muted-foreground">{article.fileName}</p>
        </div>
        {nextPhase && (
          <Button variant="secondary" size="sm" onClick={goNext}>
            {PHASE_INFO[nextPhase].label}
            <ChevronRight className="w-4 h-4 ml-1" />
          </Button>
        )}
      </div>

      {/* 消息列表 */}
      <ScrollArea className="flex-1 pr-4">
        {messages.length === 0 && (
          <div className="text-center text-muted-foreground py-8">
            输入「开始」进入{PHASE_INFO[currentPhase].label}
          </div>
        )}
        {messages.map((message) => (
          <MessageBubble key={message.id} message={message} />
        ))}
      </ScrollArea>

      {/* 输入框 */}
      <form onSubmit={handleSend} className="mt-4 flex gap-2">
        <input
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder="说点什么..."
          disabled={status !== "ready"}
          className="flex-1 rounded-md border border-border bg-background px-3 py-2"
        />
        <Button type="submit" disabled={status !== "ready"}>发送</Button>
      </form>
    </div>
  );
}

逐段解读（重点几个）：

  1. 文件路径 app/articles/[id]/[phase]/page.tsx — 方括号 [id]、[phase] 是动态路由段。访问 /articles/abc123/preview 时，id="abc123"、phase="preview"。这就是 Next.js App Router 的路由规则：文件夹名 = URL 段，方括号 = 参数。
  2. params: Promise<...> + use(params) — Next.js 15 起，params 是 Promise，要用 use() 解包（Next.js 14 直接解构 { params } 即可，看你的版本）。
  3. isValidPhase 类型守卫 — 返回值 p is Phase 是类型谓词（第三课学过）。校验 URL 里的 phase 是不是合法的阶段。用户可能手输 /articles/123/hack，这时要拦截。
  4. useRouter().push(url) — 编程式导航。文章不存在或 phase 非法时跳回首页。router.push 是客户端跳转（不刷新页面），和 Link 一样走 Next.js 路由。
  5. 进入页面自动标记「进行中」 — useEffect 检测当前阶段如果是 notStarted，改成 inProgress。这样用户回到首页能看到哪些阶段学过了。
  6. 点「下一阶段」标记「已完成」 — goNext 先把当前阶段标 completed，再跳到下一阶段页面。

第七步：上传接口微调

上传接口 app/api/upload/route.ts 不用改——它只负责提取文本返回，不管存储。存储逻辑在前端 addArticle 里。这正是第二课把提取和存储分离的好处。

对话接口 app/api/chat/route.ts 也不用改——它接收 articleText 和 phase，不关心数据从哪来（localStorage 还是内存）。前后端解耦。

理解：这是哪种架构？

对照之前学的：

概念来源本课实现
状态机（阶段切换）第 3 课不变，但现在通过 URL 路由切换而非单页 state
组件复用第 4 课MessageBubble、Button、Card 直接用
状态持久化本课新增localStorage + useArticles Hook
多页路由本课新增动态路由 [id]/[phase]

关键转变：第 3-4 课是「单页状态切换」（setCurrentPhase 改 state），本课是「URL 路由切换」（router.push 改 URL）。后者好处：每个阶段有独立 URL，可收藏、可分享、刷新不丢上下文。

当前局限 & 后续课程

  • 对话历史没持久化 — 进入某阶段发的消息，离开再回来会丢（useChat 的 messages 是内存态）。第 14 课做。
  • localStorage 容量有限 — 约 5-10MB，存几十篇文章正文可能满。超长文章可只存摘要。第 14 课升级数据库。
  • 阶段完成是手动的 — 点「下一阶段」才算完成。可以让 AI 判断完成度自动标记。
  • 没有跨设备同步 — localStorage 只在当前浏览器。换电脑就没了。要同步得上数据库。第 14 课。

📋 需求变更预告（2026-08-01）：本课实现的 [phase] 路由和 PhaseStatus 三态管理将在第 7 课重构。

路由变化：/articles/[id]/[phase] → /articles/[id]/[feature]，feature = vocab | podcast | listening | vocab-quiz | final-quiz | progress
状态变化：从线性阶段状态机（6 阶段按顺序）改为 6 个功能模块独立完成状态（推荐路径但不强制）

哪些会保留：动态路由概念（方括号 = URL 参数）、localStorage 持久化模式、自定义 Hook 封装、ArticleCard 卡片设计、SSR 守卫（typeof window）、函数式状态更新。
哪些会改：PhaseStatus 类型名改为 FeatureStatus，phaseStatus 字段改为 featureStatus，createDefaultPhaseStatus 改为 createDefaultFeatureStatus，ArticleCard 渲染的 6 个阶段按钮改为 6 个功能按钮。

小测验

动态路由

文件路径 app/articles/[id]/[phase]/page.tsx 对应什么 URL？

  • /articles（固定路径）
  • /articles/id/phase（字面量 id 和 phase）
  • /articles/任意值/任意值（参数注入 id 和 phase）
  • /articles?id=xx&phase=xx（查询参数）

localStorage 的坑

为什么 localStorage 操作要先判断 typeof window === 'undefined'？

  • 因为 Next.js 服务端渲染时 window 不存在，直接访问会报错
  • 因为 localStorage 在服务端更慢
  • 因为 TypeScript 不认识 localStorage 类型
  • 为了防止并发冲突

自定义 Hook

useArticles() 这个自定义 Hook 解决了什么问题？

  • 让 localStorage 读写更快
  • 把文章管理逻辑封装复用，多个组件共享同一份逻辑
  • 代替 useState，性能更好
  • 让数据自动同步到服务端

状态更新安全

为什么 addArticle 用 setArticles(prev => [article, ...prev]) 而不是 setArticles([article, ...articles])？

  • 函数形式拿到的 prev 永远最新，避免闭包旧值导致数据丢失
  • 函数形式性能更好
  • 函数形式能触发重渲染，直接赋值不能
  • 因为 articles 可能是 undefined

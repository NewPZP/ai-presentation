核心概念：结构化输出

前三课我们一直用 streamText，AI 返回的是自由文本——一段 Markdown 或纯文字。对于聊天场景够用，但有局限：

自由文本（streamText）结构化输出（generateObject）
返回值字符串JavaScript 对象
格式保证无，AI 可能换格式Schema 强制，字段必填
前端渲染直接显示文本可精确控制 UI 布局
适用场景对话、叙述提取数据、分类、列表

为什么词汇预习用结构化输出？ 因为词汇表是数据——每个词有单词、音标、词性、释义、例句。如果用自由文本，AI 这次输出 1. ubiquitous - adj. 无处不在的，下次可能输出 ubiquitous (adj) 无处不在，格式不统一，前端没法稳定渲染成卡片。结构化输出强制 AI 返回固定结构的对象，前端闭着眼渲染都不会出错。

第一步：安装 Zod

pnpm add zod

Zod 是 TypeScript 的数据校验库。你用 Zod 定义一个 Schema（数据结构），Zod 同时给你三样东西：

  1. 类型 — 自动推导出 TypeScript 类型，不用手写 interface
  2. 校验 — 运行时检查数据是否符合结构
  3. 文档 — Schema 本身就是数据结构的文档

对应你学过的 Python pydantic——Zod 就是 JS 版的 pydantic。

第二步：定义词汇 Schema

新建 lib/schemas.ts：

// lib/schemas.ts
import { z } from "zod";

// 单个生词的结构
export const vocabWordSchema = z.object({
  word: z.string().describe("单词原形"),
  phonetic: z.string().describe("音标，如 /juːˈbɪkwɪtəs/"),
  partOfSpeech: z.string().describe("词性缩写，如 adj. / n. / v. / phr."),
  definition: z.string().describe("中文释义，简洁准确"),
  exampleSentence: z.string().describe("文章中包含该词的原句"),
  exampleTranslation: z.string().describe("原句的中文翻译"),
  difficulty: z
    .enum(["basic", "intermediate", "advanced"])
    .describe("难度：基础/中级/高级"),
});

// 整个词汇表的结构
export const vocabListSchema = z.object({
  words: z.array(vocabWordSchema).describe("从文章中提取的生词列表"),
});

// 从 Schema 自动推导 TypeScript 类型
export type VocabWord = z.infer<typeof vocabWordSchema>;
export type VocabList = z.infer<typeof vocabListSchema>;

逐段解读：

  1. z.object({ ... }) — 定义对象结构。每个字段用 z.string()、z.enum() 等声明类型。
  2. .describe("...") — 这是给 AI 看的提示！generateObject 会把 Schema 转成 JSON Schema 发给 LLM，describe 的文字就是字段说明。AI 据此理解每个字段该填什么。这是 Zod Schema 在结构化输出中的核心作用——既是类型定义，也是 AI 的指令。
  3. z.enum(["basic", "intermediate", "advanced"]) — 枚举类型，AI 只能填这三个值之一。比 z.string() 更严格，防止 AI 自由发挥。
  4. z.infer<typeof vocabWordSchema> — 从 Schema 自动推导 TS 类型。VocabWord 类型等价于你手写 interface VocabWord { word: string; phonetic: string; ... }，但单一数据源——改 Schema 类型自动更新，不会出现 Schema 和 interface 不一致的问题。

第三步：写词汇提取 API

新建 app/api/extract-vocab/route.ts：

⚠️ 火山方舟的 generateObject 报 JSON 解析错误？ 如果报 SyntaxError: Unexpected token '...' is not valid JSON，说明 AI 返回了 Markdown 文本而非 JSON 对象。原因：generateObject 默认 mode: 'auto' 优先用 JSON 模式（response_format），但火山方舟对它的支持不完整。修复：显式设 mode: 'tool'，通过 function calling 强制结构化输出，模型必须按函数参数 schema 返回。见下方代码。 

// app/api/extract-vocab/route.ts
import { generateObject } from "ai";
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";
import { vocabListSchema } from "@/lib/schemas";

// 创建火山方舟 provider（和 chat 路由一样）
const ark = createOpenAICompatible({
  name: "ark",
  apiKey: process.env.ARK_API_KEY!,
  baseURL: "https://ark.cn-beijing.volces.com/api/v3",
});

export async function POST(req: Request) {
  const { articleText } = await req.json();

  if (!articleText) {
    return Response.json({ error: "缺少文章内容" }, { status: 400 });
  }

  try {
    // generateObject：让 AI 返回结构化对象
    const { object } = await generateObject({
      model: ark(process.env.ARK_MODEL_ENDPOINT!),
      schema: vocabListSchema,
      mode: "tool",  // ★ 关键！用 function calling 强制结构化输出，火山方舟必须用这个
      system: `你是专业的英语教学专家。
你的任务是从英文文章中提取值得学习的生词。

挑词原则：
1. 优先选词频中等偏上、有学习价值的词
2. 跳过过于简单的常见词（the, is, make 等）
3. 跳过过于生僻的专业术语
4. 包含短语动词和固定搭配（如 "bring about"）
5. 每篇文章提取 8-10 个词
6. 例句必须来自原文，不要自己编`,
      prompt: `从以下文章中提取 8-10 个值得学习的生词：\n\n${articleText}`,
    });

    return Response.json(object);
  } catch (error) {
    console.error("词汇提取失败:", error);
    return Response.json({ error: "词汇提取失败" }, { status: 500 });
  }
}

逐段解读：

  1. import { generateObject } from "ai" — 和 streamText 同属 AI SDK，但 generateObject 返回的是结构化对象而非文本流。它内部让 LLM 用 JSON 模式输出，再用 Zod Schema 校验返回值。
  2. schema: vocabListSchema — 传入 Zod Schema。AI SDK 会把它转成 JSON Schema 发给 LLM 作为输出格式约束，LLM 返回后用 Schema 校验，不合规会重试。
  3. mode: "tool"（火山方舟必须加） — generateObject 有三种模式：'auto'（默认，优先 JSON 模式）、'json'（用 response_format）、'tool'（用 function calling）。火山方舟对 response_format 支持不完整，AI 会返回 Markdown 文本导致 JSON 解析失败。mode: 'tool' 通过函数调用强制结构化输出——模型必须按函数参数 schema 返回，不能自由发挥。这是 OpenAI 兼容服务的通用解法。
  4. const { object } = await generateObject(...) — 返回值解构出 object，就是 { words: [...] } 这个结构。类型是 VocabList，TS 完全感知。
  5. system 提示里写挑词原则 — 这是 prompt engineering。不告诉 AI 怎么挑，它可能选出 the/is/and 这种无意义词。原则越具体，挑词质量越高。

对比 streamText 和 generateObject：
streamText → 文本流 → useChat → 聊天界面（第 1-5 课）
generateObject → 结构化对象 → 直接用 → 卡片/表格/图表（本课）
选择原则：要展示给人读的文字用 streamText；要程序处理的数据用 generateObject。

// components/vocab-card.tsx
import { Card } from "@/components/ui/card";
import { VocabWord } from "@/lib/schemas";
import { cn } from "@/lib/utils";

// 难度对应的颜色标签
const difficultyConfig = {
  basic: { label: "基础", className: "bg-green-100 text-green-700" },
  intermediate: { label: "中级", className: "bg-yellow-100 text-yellow-700" },
  advanced: { label: "高级", className: "bg-red-100 text-red-700" },

export function VocabCard({ word }: { word: VocabWord }) {
  const diff = difficultyConfig[word.difficulty];

  return (
    <Card className="p-4 flex flex-col gap-2">
      {/* 单词 + 难度标签 */}
      <div className="flex items-center justify-between">
        <h3 className="text-lg font-bold text-primary">{word.word}</h3>
        <span className={cn("text-xs px-2 py-0.5 rounded-full", diff.className)}>
          {diff.label}
        </span>
      </div>

      {/* 音标 + 词性 */}
      <p className="text-sm text-muted-foreground">
        {word.phonetic} · {word.partOfSpeech}
      </p>

      {/* 中文释义 */}
      <p className="font-medium">{word.definition}</p>

      {/* 分隔线 */}
      <div className="border-t my-1" />

      {/* 文章原句 + 翻译 */}
      <p className="text-sm italic text-muted-foreground">
        "{word.exampleSentence}"
      </p>
      <p className="text-sm text-muted-foreground">
        {word.exampleTranslation}
      </p>
    </Card>
  );
}

关键点：

  1. VocabWord 类型直接用 — 从 Schema 推导的类型，组件 props 类型安全。word.word、word.phonetic 都有自动补全。
  2. 难度颜色映射 — 用 Record 对象而非 switch 语句。三行搞定，加难度只需加一行。对应第三课的数据驱动思路。
  3. 纯展示组件 — 接收 word 就能渲染，不含状态不调 API。和第四课的 MessageBubble 同类。

第五步：改造词汇预习学习页

现在改造 app/articles/[id]/[phase]/page.tsx，让 preview 阶段有「提取生词」功能。其他阶段保持原有聊天不变。

下面是完整文件，直接整体替换 app/articles/[id]/[phase]/page.tsx。相比第五课的版本，新增部分用 // ★ 新增 注释标出，方便你看出改了哪里。

⚠️ React Hooks 规则：所有 useEffect、useState 等 Hooks 必须放在任何 return 之前。不能在 Hooks 中间写 if (...) return null（提前返回），否则 Hooks 调用顺序会变，React 报错 "change in the order of Hooks called"。正确做法：所有 Hooks 放顶部，提前返回放所有 Hooks 之后。

⚠️ 自定义 Hook 状态不共享：useArticles() 每次调用都创建独立的 state 实例——首页和学习页各自一份。学习页首次渲染时 articles 是空数组（localStorage 在 useEffect 里异步读取，还没执行），getArticle(id) 返回 undefined，if (!article) router.push("/") 立即跳回首页 = "点不动"。修复：用 loaded 标志守卫，加载完才判断文章是否存在；加载中显示 loading。彻底解决跨页面状态共享要用 React Context（后续课程）。 

// app/articles/[id]/[phase]/page.tsx（完整文件，直接替换）
"use client";

import { use } from "react";
import { useRouter } from "next/navigation";
import Link from "next/link";
import { useChat } from "@ai-sdk/react";
import { useState, useEffect } from "react";
import { useArticles } from "@/hooks/use-articles";
import {
  Phase,
  PHASE_INFO,
  PHASE_ORDER,
  getNextPhase,
  getPhaseIndex,
  TOTAL_PHASES,
} from "@/lib/learning-phases";
import { MessageBubble } from "@/components/message-bubble";
import { Button } from "@/components/ui/button";
import { ScrollArea } from "@/components/ui/scroll-area";
import { ArrowLeft, ChevronRight } from "lucide-react";
import { VocabCard } from "@/components/vocab-card";           // ★ 新增 ①
import { VocabWord } from "@/lib/schemas";                     // ★ 新增 ①
import { Loader2, BookOpen } from "lucide-react";              // ★ 新增 ①

function isValidPhase(p: string): p is Phase {
  return PHASE_ORDER.includes(p as Phase);
}

export default function LearnPage({
  params,
}: {
  params: Promise<{ id: string; phase: string }>;
}) {
  const { id, phase } = use(params);
  const router = useRouter();
  const { loaded, getArticle, updatePhaseStatus } = useArticles();  // ★ 解构 loaded
  const { messages, sendMessage, status } = useChat();
  const [input, setInput] = useState("");

  // ★ 新增 ②：词汇预习专用状态
  const [vocabWords, setVocabWords] = useState<VocabWord[]>([]);
  const [extracting, setExtracting] = useState(false);

  // 先算出所有需要的值（不提前 return）
  const isValid = isValidPhase(phase);
  const currentPhase = (isValid ? phase : "preview") as Phase;
  const article = getArticle(id);
  const nextPhase = getNextPhase(currentPhase);

  // ★ 关键：所有 useEffect 必须在任何 return 之前！
  // 非法 phase → 跳首页
  useEffect(() => {
    if (!isValid) router.push("/");
  }, [isValid, router]);

  // 文章不存在 → 跳首页（必须等 loaded=true 再判断，否则 localStorage 没读完会误跳）
  useEffect(() => {
    if (loaded && !article) router.push("/");
  }, [loaded, article, router]);

  // 进入阶段时标记为「进行中」
  useEffect(() => {
    if (article && article.phaseStatus[currentPhase] === "notStarted") {
      updatePhaseStatus(id, currentPhase, "inProgress");
    }
  }, [id, currentPhase, article, updatePhaseStatus]);

  // ★ 加载中显示 loading（loaded=false 时不判断 article，避免 localStorage 还没读完误跳首页）
  if (!loaded) {
    return (
      <div className="flex items-center justify-center h-screen">
        <Loader2 className="w-6 h-6 animate-spin text-muted-foreground" />
      </div>
    );
  }

  // ★ 所有 Hooks 结束后，才能提前 return
  if (!isValid || !article) return null;

  // ★ 新增 ②：提取生词函数（普通函数，不是 Hook，放 return 之后没关系）
  async function handleExtractVocab() {
    setExtracting(true);
    try {
      const res = await fetch("/api/extract-vocab", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ articleText: article.text }),
      });
      const data = await res.json();
      if (!res.ok) throw new Error(data.error);
      setVocabWords(data.words);
    } catch (err) {
      console.error(err);
    } finally {
      setExtracting(false);
    }
  }

  function handleSend(e: React.FormEvent) {
    e.preventDefault();
    if (!input.trim() || status !== "ready") return;
    sendMessage(
      { text: input },
      { body: { articleText: article.text, phase: currentPhase } }
    );
    setInput("");
  }

  function goNext() {
    updatePhaseStatus(id, currentPhase, "completed");
    if (nextPhase) {
      router.push(`/articles/${id}/${nextPhase}`);
    }
  }

  return (
    <div className="flex flex-col h-screen max-w-2xl mx-auto px-4 py-4">
      {/* 顶部导航 */}
      <div className="flex items-center gap-3 mb-4 pb-3 border-b">
        <Link href="/">
          <Button variant="ghost" size="icon">
            <ArrowLeft className="w-4 h-4" />
          </Button>
        </Link>
        <div className="flex-1">
          <h2 className="font-medium">
            {PHASE_INFO[currentPhase].label}
            <span className="text-muted-foreground font-normal ml-2">
              {getPhaseIndex(currentPhase)}/{TOTAL_PHASES}
            </span>
          </h2>
          <p className="text-xs text-muted-foreground">{article.fileName}</p>
        </div>
        {nextPhase && (
          <Button variant="secondary" size="sm" onClick={goNext}>
            {PHASE_INFO[nextPhase].label}
            <ChevronRight className="w-4 h-4 ml-1" />
          </Button>
        )}
      </div>

      {/* 消息列表 */}
      <ScrollArea className="flex-1 pr-4">
        {/* ★ 新增 ③：词汇预习阶段专用 UI，插在空状态提示之前 */}
        {currentPhase === "preview" && (
          <>
            {/* 提取生词按钮区（未提取时显示）*/}
            {vocabWords.length === 0 && (
              <div className="text-center py-8">
                <Button onClick={handleExtractVocab} disabled={extracting}>
                  {extracting ? (
                    <><Loader2 className="w-4 h-4 mr-2 animate-spin" />AI 正在分析文章...</>
                  ) : (
                    <><BookOpen className="w-4 h-4 mr-2" />提取生词</>
                  )}
                </Button>
              </div>
            )}

            {/* 词汇卡片网格（提取后显示）*/}
            {vocabWords.length > 0 && (
              <div className="grid grid-cols-1 sm:grid-cols-2 gap-3 mb-4">
                {vocabWords.map((word, i) => (
                  <VocabCard key={i} word={word} />
                ))}
              </div>
            )}
          </>
        )}

        {/* 原有：空状态提示 */}
        {messages.length === 0 && (
          <div className="text-center text-muted-foreground py-8">
            {currentPhase === "preview" && vocabWords.length > 0
              ? "有疑问？在下方问 AI"      // ★ 词汇已提取时的提示文案
              : `输入「开始」进入${PHASE_INFO[currentPhase].label}`}
          </div>
        )}

        {/* 原有：消息列表 */}
        {messages.map((message) => (
          <MessageBubble key={message.id} message={message} />
        ))}
      </ScrollArea>

      {/* 输入框 */}
      <form onSubmit={handleSend} className="mt-4 flex gap-2">
        <input
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder="说点什么..."
          disabled={status !== "ready"}
          className="flex-1 rounded-md border border-border bg-background px-3 py-2"
        />
        <Button type="submit" disabled={status !== "ready"}>发送</Button>
      </form>
    </div>
  );
}

关键点：

  1. ⚠️ Hooks 规则（本课踩的坑 1） — 原来的代码在两个 useEffect 之间写了 if (!article) return null。当 article 从 undefined 变成有值时，第二个 useEffect 从「不调用」变成「调用」，Hook 顺序变了 → React 报错。修复：所有 Hooks 放顶部，提前返回放所有 Hooks 之后。if (!isValid || !article) return null 移到三个 useEffect 之后。
  2. ⚠️ Hook 状态不共享（本课踩的坑 2） — useArticles() 每次调用是独立实例，首页和学习页各一份。学习页首次渲染 articles=[]（localStorage 还没异步读完），getArticle 返回 undefined，立即跳回首页 = "点不动"。修复：用 loaded 守卫——if (loaded && !article) router.push("/")，加载中显示 loading。彻底解决要用 React Context（后续课）。
  3. 非 Hook 的普通函数可以在 return 之后 — handleExtractVocab、handleSend、goNext 是普通函数不是 Hook，放在 return null 之后没问题。只有 use* 开头的函数受规则约束。
  4. 把判断结果存变量而非提前 return — const isValid = isValidPhase(phase) 先算好，useEffect 里用 if (!isValid) 守卫。这样即使数据无效，Hook 仍然被调用（只是 effect 内部不执行逻辑），顺序不变。
  5. currentPhase === "preview" 条件渲染 — 只有词汇预习阶段显示提取按钮和卡片。其他阶段走原有聊天逻辑。
  6. grid grid-cols-1 sm:grid-cols-2 — 响应式网格：手机 1 列，平板及以上 2 列。

测试流程：

  1. 导入一篇英文文章 → 点「词汇预习」进入学习页
  2. 看到「提取生词」按钮 → 点击 → 显示「AI 正在分析文章...」转圈
  3. 等待几秒 → 词汇卡片网格出现，每张卡片有单词/音标/词性/释义/原句/翻译/难度标签
  4. 下方聊天框输入「ubiquitous 能再详细讲讲吗」→ AI 用 streamText 回答（原有功能不变）
  5. 点「进入朗读→」→ 切到朗读阶段，词汇卡片消失，恢复纯聊天界面

验证结构化输出生效：打开浏览器 DevTools → Network 面板 → 点「提取生词」→ 找到 /api/extract-vocab 请求 → 看响应。你会看到 { "words": [{ "word": "ubiquitous", "phonetic": "/juːˈbɪkwɪtəs/", ... }] }——干净的结构化 JSON，不是一段文字。这就是 generateObject 的输出。

理解：这对应 Agent 的什么能力？

对照你前一课程的 Agent 知识：

Agent 能力本课实现
结构化输出generateObject + Zod Schema 强制 AI 返回固定结构
提示工程system 提示里写挑词原则（词频、难度、跳过常见词）
数据校验Zod Schema 校验 AI 返回值，不合规自动重试
API 分离提取词汇（generateObject）和对话（streamText）分两个接口，各司其职

关键洞察：generateObject 是 Agent 从「能聊天」到「能干活」的关键。聊天是展示给人读的文字；干活是产出程序可处理的数据。词汇提取、分类、打标签、信息抽取——都是 generateObject 的活。

当前局限 & 后续课程

  • 词汇不持久化 — 离开页面再回来，提取的词汇卡片消失。第 14 课做。
  • 没有发音功能 — 卡片只显示音标，不能听发音。第 8 课加 TTS 语音合成。
  • 挑词没有个性化 — AI 不知道用户的词汇水平，可能选出已会的词。第 14 课加用户词汇表。
  • 非流式 — generateObject 是一次性返回，没有流式效果。卡片一起出现而非逐个出现。可接受，词汇表不需要打字机效果。

小测验

结构化 vs 自由文本

为什么词汇提取用 generateObject 而不是 streamText？

  • generateObject 比 streamText 更快
  • streamText 不支持火山方舟
  • 词汇表是固定结构的数据，需要对象格式才能稳定渲染卡片
  • streamText 已经被淘汰了

Zod 的 describe

z.string().describe("音标，如 /juːˈbɪkwɪtəs/") 中的 describe 是给谁看的？

  • 给 TypeScript 编译器看，影响类型推导
  • 给 AI 看，作为字段填写说明
  • 给前端开发者看，代码文档
  • 给 Zod 内部用，不影响行为

类型推导

z.infer<typeof vocabWordSchema> 的作用是什么？

  • 从 Schema 自动推导 TypeScript 类型，不用手写 interface
  • 从 TypeScript 类型推导 Zod Schema
  • 运行时校验数据是否符合 Schema
  • 把 Schema 转成 JSON 发给 AI

枚举的作用

难度字段用 z.enum(["basic", "intermediate", "advanced"]) 而不是 z.string()，好处是什么？

  • enum 比 string 性能更好
  • 限制 AI 只能填这三个值，防止自由发挥，前端可安全映射颜色
  • enum 不需要 describe
  • string 类型不支持 describe
